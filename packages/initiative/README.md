# Initiative

A1-L05 component implementation against `aeon1.c1.v1`. Uses the L03 `OperationalStore` and resource ledger; operational state stays outside the checkout. No identity, preference, adopted drive or inquiry question is seeded.

`InitiativeRegistry` supplies C1 async `get/put/ready` and synchronous `goal/all/propose/accept/revise/history/readyNow`. Revisions begin at 1, compare-and-swap is mandatory, goals retain evidence and reasons, resources may decrease but never increase, dependency cycles and audience widening are refused. Completed/abandoned goals are immutable; propose an attributed successor. Ready goals whose dependencies are unresolved receive no execution. Paused/blocked goals require explicit reconsideration. Waiting goals retain their declared wakeup.

`DriveRegistry(store, memory)` adopts experience-supported growth dimensions (`judgment`, `curiosity`, `code-quality`, `capability`), retains adoption revisions, accepts concrete attributed opportunities, and selects an opportunity into a proposed goal. Dimensions orient choice without supplying a fixed self or questions. Missing coverage is exposed explicitly. Opportunity ranking uses adopted weights; choosing and adopting goals remain decisions of the mind. Forgetting their experience makes drives/opportunities unavailable. Mechanical source checks cannot establish whether the proposed question genuinely follows the content; that judgment needs evaluation.

`PlanRegistry` stores machine-readable Aeon → Lane → Task plans with copyable finite goals, owner, dependencies, writable paths, inputs, model/effort, acceptance, status, evidence and handoff. Tasks inherit the plan owner. Host/model planning must persist and maintain a plan for substantial work; merely storing a plan does not execute it or authorize its writable paths.

`FairScheduler(store, goals, obligations, id, policy, timestampMs)` persists cyclic commitment/conversation/inquiry service, FIFO rotation within each service class, finite windows and a finite lifetime. A flood of incoming work appends behind previously queued work. Window renewal resets window slices only. Restart requires the identical policy; lifetime counters and actual usage remain. `select(timestamp, includeDeliveries?)` returns a selected finite slice or a truthful idle/window/lifetime decision and next deadline. Idle causes no model request; exhausted lifetime has no automatic reset.

`InitiativeRunner({scheduler,runtime,memory,authority,prompt,decide,deliver?})` performs one bounded `tick()` using actual `DurableRuntime.admit/resume`, shared ledger allocations, attributed memory ingestion and scoped memory context. Runtime allocations nest under a persistent agenda allocation and a persistent per-goal allocation, so new steps, retries, cancellation, restart and scheduling windows do not create free allowance. Physical ceilings remain L03 controls; scheduler selection is not permission. The ledger's elapsed limit includes idle wall time. Exhaustion requires an explicit separately authorized host grant; this package never manufactures one.

Call `recover()` after acquiring exclusive host authority. `steer`, `cancel` and `reconsider` preserve durable runtime/goal state; changed host authority adopts resumable runs. Runtime checkpoints resume the same run without new input. Model tools can read the current agenda revision after recovery; a retained shell checkpoint may contain the earlier goal frame. `tick` relies on the selected shell/receiver honoring abort to yield at the declared quantum. Repeated slices without new successful observation back off and then block at the declared stall limit. Failed observations require a changed next observation when continuing. Goal completion requires successful current observations, but an author's completion judgment is not independent qualification.

`initiativeTools(goals,drives,plans,authenticatedAudience,actorId,maximum,clock?)` returns auditable descriptors for agenda access, proposing/accepting/revising/selecting goals, adopting drives, offering inquiry, writing plans and `initiative_goal_progress`. The latter consumes persisted observations from the actual current runtime and permits model completion/replanning without an extra interpretation request. Audience and maximum resources are captured by the host. L02/L06 adapt descriptors to the shell and route them through accounted effects. `runner.decide` must synchronously interpret an already-accounted result; never make an unaccounted model request in that callback. If a model progress tool already revised the goal, the fallback is skipped. No hidden prompt is inserted.

`claimConsolidation` runs memory expiry and claims a leased job only. The host must execute interpretation under an accounted runtime and call memory completion/failure APIs; this component does not synthesize a consolidation result or run an extra model call.

`ObligationRegistry` has independent C1 async `get/put/owed` and synchronous `obligation/all/owe/beginDelivery/confirmDelivery/retry/cancel`. Delivery payload and receipt carry `kind:'report'`, `obligationId` and the **owed revision passed to beginDelivery**. Confirmation requires a persisted succeeded effect, an actual stored receipt, exact audience/channel/optional thread, text/report revision, nonempty host message ID and timestamp. The L07 receiver generates client IDs at dispatch. Progress acknowledgments do not settle an owed outcome, goal completion never cascades into obligation completion, unknown outcomes cannot retry, and model/report content appropriateness still needs judgment. The optional runner delivery callback must use the effect journal and registry; unresolved deliveries remain pending. Repeated callbacks that leave an outcome owed receive a deadline backoff.

Tests use synthetic experience and captured model HTTP fixtures, with actual Pi, durable runtime, resource ledger and developmental memory. They establish component behavior and joined fixture integration, not live competence, independent personality or growth. Host wakeup registration, actual inquiry tools, qualified Mistral selection, meaningful unattended longitudinal cycles, report freshness and independent held-out evaluation remain integration gates.
