# Developmental state

Fresh A1-L04 implementation against `aeon1.c1.v1`, using L03's `OperationalStore`. No historical memory or prompts are imported. No identity, interests or preferences are seeded. Store files must remain outside the checkout (the composition root supplies `checkoutRoot`).

`DevelopmentalMemory(store, clock?)` supplies attributed `ingest`, evidence-grounded `derive`, bounded `context`, C1 `retrieve`/`append`, `adoptSelf`/`selfHistory`, `forget`/`expire`, and leased consolidation jobs. Inputs are trusted typed application calls. Authenticate actors and audiences before calling; these methods never grant authority based on episode content. Text interpretation, source completeness and correctness remain judgments requiring external evaluation.

Episode content means “this actor supplied this speech/tool/action content.” Confidence is null. Derived beliefs, procedures, relationships and self-descriptions preserve source IDs, confidence and derivation. Corrections use new IDs and explicit `supersedes`; contradictory claims coexist. Existing evidence cannot be rewritten through the C1 adapter. Record and storage revisions start at 1. IDs are immutable: forgotten IDs cannot be reused.

Derived scope must be a subset of every source's recipients. A caller must supply the entire destination audience, including delegated recipients. `context` and `selfHistory` apply the same recipient checks. A hidden correction does not remove a public claim for an unauthorized recipient. There is no automatic widening, disclosure or historical import pathway.

Retrieval uses lexical overlap, optional caller-supplied expansion, and recency for ties. It returns whole structured records with provenance. Relevant semantic synonyms without explicit expansion can be missed. The declared policy considers active self facets first, then relevant memories; oversized records are skipped rather than truncated. `maxRecords` bounds the combined payload; `maxBytes` bounds canonical serialized `{memories,self}`, including provenance but excluding selection diagnostics. C1 `retrieve` excludes self facets so its memory limit cannot be consumed by self-state. No embedding/model quality claim is made; indexing and larger-corpus latency qualification remain open.

Self facets hold a chosen interest, value, ability claim, uncertainty, preference or description with reasons and memory evidence. Revision uses compare-and-swap; history remains audience scoped. An ability claim is not a demonstrated capability. The caller receives structured self-state and decides how it affects reasoning. This module inserts no system prompt or hidden instruction layer.

Forgetting computes source descendants atomically and removes their content, affected adopted self values/history, and queued consolidation eligibility. Tombstones retain IDs, scope, attribution and source links to prevent resurrection and support provenance. Derived records inherit the earliest source deadline; expired sources cannot be retrieved or used for derivation before the sweep runs. `expire()` performs logical removal. The opt-in v2 document journal stores immutable version references and separate, individually owned payload rows. Forget/expiry withdraws every earlier journal version for selected memory/self/history/job keys in the same transaction, including historical self facets whose current evidence has changed. Current unrelated self/history remains usable. Selecting a facet key deliberately loses all its prior journal payload history; a future legitimate version receives a new reference and cannot restore an old one. Raw memory payload is never copied into immutable events/artifacts. A capture needing withdrawn history becomes unavailable to a complete-history observer; externally retained authorized copies belong to their own custodian. Withdrawal failure rolls back the whole memory mutation. This is logical database erasure, not forensic secure erasure of SQLite pages, WAL files, backups or other upstream copies; any physical destruction policy belongs to storage/operations. Used evidence must be declared completely: content semantically copied while omitting its source cannot be detected by a mechanical lineage check.

The scheduler can call `expire(now)` and `claimConsolidation(workerId, leaseMs, now)` at wakeup. Interpret `consolidationSources(claim)` outside a transaction and pass explicit `Derivation[]` to `completeConsolidation`. Completion writes all outputs plus the job status atomically, marks derivation as summarized, checks source scope, and fences stale workers. A process crash leaves a running job reclaimable after its lease. Worker errors can call `failConsolidation`; retry is explicit with the failed revision. Cancellation/forgetting invalidates outstanding claims. No physical model requests occur here; the runtime must reserve/account for any interpretation work and refuse completion after cancellation. A timer, provider or scheduled production invocation is not implemented in this module.

`developmentTools(memory, authenticatedAudience)` returns auditable descriptors for `memory_retrieve` and `memory_schedule_consolidation`. The audience is captured by the caller and cannot be supplied in model arguments. Tool job names are prefixed with a destination-scope digest, so a model-selected name cannot probe another audience's job through a collision error; unavailable source errors also conceal whether an unauthorized source exists. L02/L06 adapt these data-only descriptors into the selected shell. L05/L09 own scheduler registration; L08 owns independent behavioral/longitudinal evaluation.

The tests use temporary databases outside the checkout and reopen them. A deterministic later choice consumes the revised adopted preference. This verifies functional state transfer; it does not demonstrate empirical personality, consciousness or growth.
