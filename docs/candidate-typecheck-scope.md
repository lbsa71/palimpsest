## Problem and expected behavior

The installed evaluator passes every frozen `.ts` file to the compiler with `--ignoreConfig`. A separately pinned experimental package is therefore compiled using the production dependency grant, even though the root project includes only `src`, `test` and `scripts` and the experiment's nested dependencies are intentionally absent from the frozen snapshot. The final P06 attempt exposed eighteen unrelated missing-import errors in experimental code alongside four real candidate type errors and a real Unicode failure.

Define the input boundary in the installed trusted evaluator. Check all production source/test/script roots and their compiler-resolved import/declaration closure. Classify the existing standalone experiment packages explicitly; their source/locks remain in full artifact identity and their separately pinned checks remain experimental evidence. An unknown new TypeScript location fails until its evaluation contract is admitted. A static production import of experimental code enters the compiler closure and must pass or fail honestly. A computed import is not statically resolved; excluded standalone package paths are therefore unreadable in version-2 candidate behavior checks and serving workers. This prevents computed import, `require` and direct reads from turning excluded packages into unchecked runtime dependencies. The compiler retains package reads to diagnose static imports; the cognitive runtime does not.

Candidate-controlled `tsconfig` exclusions, labels or manifest fields cannot weaken this transaction's installed policy. Do not install unused experimental SDKs into production just to silence diagnostics. Keep the existing typecheck, trusted-agent and required item checks; an application type error or missing import remains a failure.

## Version and evidence binding

New frozen candidates bind a versioned typecheck policy and its trusted implementation identity in their manifest/evidence. The selected inputs and policy must not silently change after approval. A replaced policy requires new frozen evidence under the previously accepted outer procedure. Manifest schema 2 requires policy version 1, installed evaluator SHA-256, exact production entrypoints and exact runtime-excluded package paths. Evidence schema 1 includes that same policy object; the evidence/manifest digests bind it. Governance binds policy version and implementation identity; the full lists remain manifest/evidence-bound. Recompute classification under installed code before evaluation and execution. Missing or altered policy data fails rather than falling back to legacy semantics. Retain a compatible legacy interpretation for historical manifests lacking the new binding: those retain their original all-manifest `.ts` input semantics, including their original failures. Do not reclassify the recorded P06 candidate as passed. `readManifest` can parse legacy schema 1, but default verification/evaluation rejects it. Only an exact `expectedLegacyManifestDigest` from independently retained custody, installation metadata or a promoted-release journal record permits historical checking. New legacy-shaped bootstrap/proposals cannot obtain that exception from their own fields. Recovery and current-incumbent challenges use trusted custody identity; new admission does not.

Initially classify production TypeScript under `src/`, `test/`, `scripts/` and applicable `trusted/` declarations, plus the exact declared standalone packages `experiments/coding-provider` and `experiments/coding-provider-adapter`. Verify the actual package boundary rather than treating any future `experiments/` path as an automatic exclusion. Recognize supported TypeScript module/declaration extensions explicitly. Source import resolution remains enabled. Full-codebase authoring remains the product requirement; new source locations and policy upgrades use their corresponding evaluation contract, not a permanent human-only restriction.

## Acceptance, non-goals and risks

Establish red behavior with an actual frozen fixture containing an unused standalone experiment with an absent dependency: the existing all-file checker fails; the new explicitly bound production policy passes while retaining experiment hashes. Then demonstrate:

1. Type errors and missing dependencies in every production root fail, including a root test/script and imported declaration/module.
2. Static production imports entering experimental code are checked; broken/missing dependencies fail. Computed imports, direct reads and `createRequire` cannot access excluded packages during protected checks or either normal/scoped serving-worker execution.
3. Unclassified TypeScript paths and malformed/altered policy bindings fail closed. Candidate configuration cannot exclude a known production failure.
4. Copied immutable host/checking paths retain identical policy/toolchain behavior. Policy changes invalidate newly bound evidence.
5. Exact retained legacy manifests recover under original semantics. New or relabeled legacy identities fail admission; a recomputed manifest cannot inherit custody/installation proof. Full snapshot/package/lock identity and independent behavior checks remain bound.

This is not a waiver for the candidate's own compile/Unicode defects, a replacement of its author-written source, a new model call, a root dependency install, a budget refill or broader source admission. Risks are skipped executable source, accidental policy reinterpretation, missing import-closure checks, unbound evaluator changes and treating experimental compatibility as production packaging. Fresh independent source and frozen-artifact review precede any consequential host activation.

That candidate, original checker and observed result remain outside Git in a private audit fixture. The correction adds installed `denyReadPaths` to protected behavior execution and both serving-worker paths, with real regression checks. Denials override the broader read grant and include metadata/enumeration. They do not grant new access.

These are path exclusions on immutable read-only frozen trees, not an inode secrecy boundary against hostile same-user relocation or a writable draft renaming excluded source. Full-codebase draft commands need their own workspace contract and cannot reuse this promise. ## Installed-environment limit and selected retention design

Current verification uses the installed evaluator/check modules and recomputes schema-2 policy under their current identities. It compares the complete current runtime/dependency object, including the compiler's canonical path, and reads Git HEAD plus the original base commit/tree/blob objects. Retained source bytes alone cannot supply those inputs after evaluator/dependency replacement or checkout removal. The exact schema-1 historical identity exception preserves that schema's interpretation under current installed code; it does not select an original historical verifier/runtime.

The [retained-environment contract](retained-environments.md), selected in [ADR 0025](adr/0025-retained-verification-and-execution-environments.md), is **unimplemented** P17/P18 work. It requires independently accepted provenance before historical verifier execution; proposal/preparation or custody artifact membership is insufficient. Preserve old manifests/evidence unchanged, retain the original verifier/check/runtime/dependency and Git closure, and explicitly preserve identity-bearing canonical paths or admit a tested relocation interpretation. Route checks, normal/scoped workers, service, historical publication/import and workspace commands through the same verified resolver and execution projections. Real package resolution, repeated transitions and checkout-independent recovery remain acceptance gates; current typechecking/exclusion evidence does not establish them.
