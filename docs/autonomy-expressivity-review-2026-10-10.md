## Current verdict

Full self-modification expressivity is **not accepted**. The current product has a real narrow cognitive proposal/check/succession/publication route and now has installed bounded conversation continuity. Those are useful capabilities. They do not establish an iterative coding agent or broader autonomous release routes.

The inspected P17/P18 statuses candidly mark these gaps. The principal problem is incomplete integration and capability expansion, not evidence that every small implementation was misreported. A narrow increment can be accepted at its actual scope while the full requirement stays open.

| Capability | Observed boundary | Required positive witness |
|---|---|---|
| Model uses coding tools | Serving Mistral requests disable tools; workspace receivers have test callers but no production caller. | Actual serving path executes inspect/edit/test/repair rounds and retains the session across interruption. |
| Expresses and releases repository changes | Proposals and ordinary admission replace direct `src/agent/*.ts` files; publication updates the same paths. | A useful non-agent change with additions, deletion/rename and relevant tests traverses full-tree freeze, evaluation, activation and exact publication. |
| Changes a dependency or local fork | Current runtime/dependency inputs and shared paths bind historical verification; retained environment selection is unimplemented. | A locally changed dependency alters the running behavior, with reproducible resolution and retained offline recovery. |
| Evolves host and governance | Ordinary governance changes are denied, custodian replacement is disabled, host installation requires the operator. | Autonomous host handoff plus a separately admitted governance change under older controls; new rules apply to a subsequent transaction. |
| Expands its executable development agenda | The catalog accepts exactly two P06 work items with fixed paths/checks and single-call authoring. | It admits a new work contract/check through the governance route, then executes that later work without a human supplying missing stages. |

## Source-grounded acceptance blockers

1. **No serving coding loop.** [Provider requests](../src/providers.ts) at audited lines 177/194 send `tool_choice: none` and reject tool calls. [CLI configuration](../src/cli.ts) still constructs that provider. `CodingWorkspaces` has no production construction/caller in `src` or `scripts`; [runtime](../src/runtime.ts) makes a completion rather than an operation/result/model continuation loop. The selected SDK facade is an experiment, not a root production dependency. A declared schema or a successful receiver test cannot establish model reachability.
2. **Changing an allowlist alone cannot broaden release expressivity.** [Candidate freezing/verification](../src/candidates.ts), audited lines 208–214 and 282–286, restrict changes and preserve non-agent baseline files. [Git publication](../src/git-publication.ts), audited line 208 onward, starts from the baseline tree and updates cognitive files. The missing workspace importer must bind the serving admitted source, and the finished-tree exporter must represent additions, deletions, modes and dependencies through every stage. Editable draft bytes alone do not prove that those bytes can become the running product.
3. **Fork and evaluator continuity are real dependencies, but need bounded sequencing.** [ADR 0025](adr/0025-retained-verification-and-execution-environments.md) identifies current evaluator/runtime/dependency and original-path coupling. Preserve an independently runnable rescue while enabling a changed environment. Do not interpret that prerequisite as requiring all future P18 behavior before isolated implementation of the P17 loop. Capture, trusted selection, affected-consumer routing and offline recovery gate production replacement of shared inputs; repeated autonomous A→B→C evolution remains the later P18 acceptance gate. The staged Node/TypeScript command receiver provides real programmable execution; absence of a general shell alone is not proof of inadequate expressivity. Subprocess-dependent builds and fork resolution still need their own positive evidence.
4. **The protected outer layer still has no autonomous upgrade route.** [Custodian](../src/custodian.ts), audited lines 324–325 and 569, rejects changed governance/schema in ordinary succession and disables custodian replacement. These guards preserve the current contract; deleting them is not the fix. Implement the separate route promised in A17/P18 and show successful activation/recovery. Operator bootstrap remains assisted deployment evidence, even when every preceding test passes.
5. **The development agenda cannot escape its seed catalog.** [Plan validation](../src/development-plan.ts), audited lines 64–75, requires two specified items, `src/agent/brain.ts`, fixed check names and one proposal call. The [executor](../src/development-executor.ts) preserves finite historical attempts. General coding must have an admitted iterative session/accounting contract; resetting old attempts or hiding several calls inside one callback does not expand the product correctly. Completing the two catalog examples is not general autonomous plan execution.

## How implementation will be challenged

Every claimed expansion must identify its entrypoint, reachable operations, actual changed component class, receiver authority, emitted artifact, activation route and remaining ceiling. A prerequisite-only change must name the capability it unblocks and the next consuming integration. Test totals alone do not answer those questions.

Distinguish four kinds of evidence: implemented primitive; integrated deterministic workflow using real files/processes; evaluated activation/recovery of the exact artifact; configured-model behavior through the installed route. Scripted provider fixtures are appropriate for mechanics. Separately bounded actual-model work must show investigation and repair without a supplied solution before claiming cognitive competence. Record `not run`, failure and assistance explicitly.

Pair denial checks with legitimate positive cases. Refusing writes to the active evaluator is necessary; successfully authoring and separately admitting its future replacement is also necessary. No permanent directory, package, catalog or governance ceiling is justified merely by a passing denial test. Conversely, no unrestricted execution or arbitrary live mutation is required to prove source expressivity.

For consequential changes, Sol supplies the frozen commit/artifact, positive witness, actual checks, limitations and intended milestone claim for independent review. Review findings distinguish a defect in the increment, a blocker to a broader claimed capability, and remaining work outside the increment. Passing a bounded increment does not close its parent requirement. The same scrutiny applies to Astra's proposed designs and prerequisites.

## Next capability milestone

The smallest useful expansion is P17's **model-reachable durable coding session**, not another standalone tool demonstration. Through the serving runtime, a scripted provider must select real search/read/edit/command operations, receive a genuine failed check, repair the draft, resume after Store reopen and an allocation-window pause, and submit that exact workspace for the appropriate evaluator. Demonstrate eligible direct/Slack entry and independent standing-growth entry to the same loop, retaining each lane's authority and accounting. Include a draft outside `src/agent/` to establish authoring breadth while labeling any still-unavailable activation class honestly. Do not supply the mutation through an operator bypass. This proves mechanics only; a finite configured Mistral task remains separate.

In parallel, implement the admitted-source importer/full-tree artifact route and the retained-environment foundation needed for broader production dependencies. Then demonstrate non-agent application activation, a used local fork, and autonomous host/governance/catalog transitions with old-control evaluation and retained recovery. Keep the existing A→B→C continuity gate for repeated environment evolution. Collector responsiveness can be a genuine reliability prerequisite for a particular release, but is not itself evidence that coding expressivity increased.
