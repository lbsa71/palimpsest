# Rewrite acceptance and handoff

Status: active acceptance specification, 2026-10-11. No rewrite runtime gate has passed. The old [acceptance catalogue](history/pre-aeon-2026-10-11/docs/acceptance.md) is historical; its test results are not rewrite acceptance.

The product target is useful sustained reasoning/action at least comparable to the named mature agents, together with an independently developing, continuing Autark. Evaluate actual artifacts, observations and later behavior. Do not score hidden reasoning length, assertive language, self-praise, fixed persona compliance or activity as competence.

| Shell selection | Effective request audit and replacement across tools, compaction, delegates and resume; physical-call/effect interception; pinned alternatives; finite comparable screen; justified adopt/fork/build decision | A1-L02; C1 and A1-L08 screening cases; does not await full integrated benchmark |
| Component readiness | Observable task behavior, negative tests, cancellation/restart and uncertainty under the named contract; correct scope/resource control; meaningful real adapter tests where needed | A1-L03–L07 and L09 components; fixtures permit parallel development |
| Product qualification | Frozen integrated candidate versus versioned Claude Code/Codex, case-level outcomes, resource/intervention/latency measures, confounders and limitations; same-model harness and best-system comparisons kept distinct | A1-L08; joined L02–L07 candidate and L09 runtime |
| Whole-system evolution | Autark-authored meaningful change beyond cognition, real tests and independent review, exact release, continued state; separate real staged evaluator/governance replacement in disposable runtime; failure with unavailable provider and stopped predecessor recovers | A1-L09; A1-L06 authoring and A1-L08 independent evidence |
| H1 — transfer responsibility | Accepted preceding gates, versioned capability/authority manifest, qualified model/tool/prompt/workload profiles, usable Aeon 2 task plan, demonstrated self-chosen bounded cycle and tested recovery | A1-L09; Aeon 2 E1–E5 refines this same gate |
| Aeon 2 cycle acceptance | Each finite lane completes its stated experiment with actual evidence and an explicit positive/negative/inconclusive result; capability claims need their own thresholds; later transfer/revision observed | A2 lane owners; independent checks under A1-established controls |

A1-L08 fixes task families, objective rubrics, score margins, sample/horizon rules and non-regression thresholds **before candidate scoring**, using baseline variance and product needs. Record protocol changes as new versions; do not lower a criterion after observing a failure and call the original gate passed. A finite evaluation report may be complete with negative results. **H1 and full Aeon 1 remain unaccepted until the required product thresholds actually pass.** Missing authorized access to either comparator leaves corresponding parity unverified; useful engineering work may continue.

## Mandatory behavioral coverage

- **Reason and finish:** unfamiliar coding/debugging and a non-coding investigation require several observations, a failed attempt, repair and independently verifiable completion. An unsupported statement that work was done fails.
- **Continue:** exceed one context window, restart with an open tool/effect outcome, preserve a correction/cancellation, resume or wait truthfully, and finish without duplicate accepted effects. Unknown delivery remains unknown until reconciled.
- **Initiate:** with no fresh user prompt, select a worthwhile standing goal, gather new evidence, make progress and preserve a reasoned next choice. A fixed timer producing generic self-reflection fails.
- **Remember and develop:** retrieve relevant older experience, revise a belief with provenance, consolidate and later apply learning in ordinary interaction; preserve privacy while allowing justified shared learning. A twelve-record recent window or global transcript dump is not sufficient evidence.
- **Express an owned self:** decisions show persistent but revisable preferences, grounded disagreement and ordinary independent action. Both automatic agreement and reflexive opposition fail. No requirement to claim feelings or consciousness.
- **Own instructions:** replace an imposed persona and audit every application-side request fragment through plain turns, tools, summaries, recovery, resource discovery and child agents. Uncontrollable mandatory behavioral layers fail the primary-mind shell gate. Provider training/service opacity is recorded separately.
- **Delegate:** bounded children gather or implement independent work; parent checks actual artifacts, reconciles conflicts and retains ownership. Verify accounting, cancelled-child cleanup and scope enforcement.
- **Communicate:** direct and Slack paths share the same behavior; long work does not block ingress/updates; recover declared missed-message coverage with pagination/rate-limit/retention gaps visible. Explicitly decide and test offline first-mention discovery rather than silently assuming joined-thread recovery covers it. Later reports refer to the correct revision and thread.
- **Evolve:** modify application, tool/dependency and control machinery through appropriate independently checked paths; rollback code while preserving current memory, tasks and uncertain effects. The candidate cannot approve itself by changing its own evaluator.
- **Measure fairly:** retain individual failures and actual resources; report manual interventions. Separate model, harness and context effects with bounded ablations. Synthetic time tests prove mechanics, not weeks of development.

The capability manifest records exactly what was qualified. New models, consequential prompt changes, new tools or a replaced shell receive relevant requalification. Ordinary thought is not subject to repeated permission rituals; actual effect and resource grants remain enforceable outside personality instructions.

## Planning-package acceptance only

This documentation change requires internally consistent requirements, two Aeons, fourteen lane goals, concrete task/model/effort/ownership fields, resolvable references, explicit dependency and handoff gates, persisted diagnosis and reuse choices, and verified decommission evidence. Documentation checks do not require re-running the retired runtime's entire suite. See [planning validation](rewrite/validation.md) for the executed checks and their limits.
