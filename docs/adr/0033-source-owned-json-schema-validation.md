# ADR 0033: Replace the interim TypeBox dependency with a narrow owned validator

- Status: implemented and fixture-verified, 2026-10-11; root dependency integration and fresh review are the lead's gates. This does not accept all A1-L02, qualify model competence, or deploy a successor.
- Scope: ADR 0032's RW21 source-dependency boundary for Pi tool schemas. Pi's selected loop and Mistral remain the architecture.
- Evidence: [TypeBox reassessment](../rewrite/evidence/A1-L02/2026-10-11-typebox-reassessment.md) and [adoption evidence](../rewrite/evidence/A1-L02/2026-10-11-narrow-schema-adoption.md).

Use the source-owned runtime/type closure of `@cfworker/json-schema` 4.1.1 at `5409fdc2bd144f68e8b28c61c71fcb16600000a6`. Retain eight modules, MIT license, exact upstream/retained hashes, the full local patch, original API cases and a relevant pinned JSON-Schema-Test-Suite selection. The complete closure is 1,721 physical lines / 53,808 bytes with zero external runtime imports. TypeBox's measured Compile/Convert closure was 691 modules / 47,785 lines; its broad internal barrels defeat useful selective adoption. Remove the interim npm dependency once the remaining callers use plain schemas.

This adopts an existing validator instead of constructing a bespoke schema checker. The upstream [README](https://github.com/cfworker/cfworker/blob/5409fdc2bd144f68e8b28c61c71fcb16600000a6/packages/json-schema/README.md) describes draft support and its evaluation-free design; the pinned [source](https://github.com/cfworker/cfworker/tree/5409fdc2bd144f68e8b28c61c71fcb16600000a6/packages/json-schema/src) establishes the actual closure. Our compliance statement is limited to retained cases and actual tool schemas. Upstream's [explicit exceptions](https://github.com/cfworker/cfworker/blob/5409fdc2bd144f68e8b28c61c71fcb16600000a6/packages/json-schema/test/unsupported.ts) include dynamic references and some formats; current tools use none of those features. There is no hidden network reference loader.

Tool schemas are owned data-only Draft 2020-12 definitions. Validate strictly without converting string numbers, booleans or required nulls, without removing optional nulls, and without inserting defaults. Preserve null only when the schema declares it. Prior Pi glue accepted `null` as integer zero, `true` as integer one, and `"10"` as integer ten; this is an intentional behavior change. A schema failure becomes an observation for model repair before dispatch. It must never be silently interpreted as an accepted external effect.

The host's canonical JSON contract rejects class instances, undefined, non-finite numbers and cycles before validation. Schema dereference annotations stay on a private clone, and validated arguments are cloned without mutating the original call. A small local correction uses own JSON properties for required/dependency presence and property iteration, rather than allowing JavaScript prototype fields to satisfy JSON constraints. The fork records this semantic patch separately from TypeScript syntax/import adaptation.

The selected model catalogue consumes only type declarations. Retain explicit protocol types and remove unused runtime catalogue schema builders. Tool parameters remain generic schema objects; TypeBox's static inference layer is removed rather than reimplemented. Runtime validation remains mandatory.

The normal root TypeScript check/build and Node test runner cover the closure. Source edits require no upstream publication or manual installed-package changes. The checked-in probe proves an edited validator is compiled and loaded in a fresh process, then restores and verifies the original. L09's supervisor owns actual successor activation and canonical-state continuity; a fresh load does not claim those product capabilities. Compiler/Node source ownership remains reproducible pinned provisioning/build/patch procedures, rather than bundling all toolchain source into this small library.
