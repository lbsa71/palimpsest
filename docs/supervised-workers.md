# Supervised cognitive worker lifetime

Status: P05/P10 worker reliability refinement source-reviewed, frozen-reviewed, installed and verified over six minutes of local live operation, 2026-10-09. The separate [serving responsiveness defect](serving-responsiveness.md) remains unresolved; broader readiness is not established.

## Problem and expected behavior

The earlier installed host recovered its otherwise idle worker every five minutes after the 09:18 UTC start: `worker_failed` at 09:23:26, 09:28:30, 09:33:34, 09:38:37 and 09:43:41. Epoch advanced from 110 to 115 while the outer API and Slack stayed connected. Its `AgentWorker` used the finite-job isolation runner's default 300,000 ms lifetime; that runner unconditionally kills the owned process at expiry. A real disposable worker with a 750 ms lifetime was initially healthy and failed after idle 900 ms, with actual PID disappearance after stop. No model request caused that reproduction.

A healthy supervised cognitive worker must retain its process identity and continuity across idle periods and many valid responses. Keep finite startup and per-RPC deadlines, current authority checks, strict protocol framing/correlation and explicit abort/drain. A real crash or unresponsive source must still cause bounded mechanical recovery. Do not represent routine elapsed lifetime as a source failure or interrupt live work to extend a finite job allowance.

## Selected scope and interface

Introduce a separate trusted `runIsolatedSession` entry point for supervised descriptor workers. Keep `runIsolated` jobs and their default/max wall-time and combined output bounds unchanged. Session invocation requires an owner AbortSignal and synchronous PID/stdout observers, permits only current trusted Node and host-selected read-only source/harness paths, and denies network, fork, candidate write grants and disposable HOME/TMPDIR writes. This is not an arbitrary unbounded command interface or a candidate-selected timeout exception.

Deliver stdout only to the bounded worker protocol parser, without retaining a cumulative transcript or applying a lifetime valid-response ceiling. Preserve bounded captured stderr diagnostics and kill/drain on overflow, malformed/unsolicited/oversized frames, observer failure, startup/RPC deadline, closed transport or owner cancellation. The worker parser retains its 131,072-byte incomplete-frame ceiling and matching pending-ID validation. Explicit finite `lifetimeMs`, where supplied by trusted tests/owners, retains its existing finite behavior.

The trusted authority callback is synchronous and throws on denial. Returning a Promise or other thenable fails closed, consumes any eventual rejection and drains the actual owned process before returning; the wrapper waits only for process drain. Copy accepted task/memory inputs before this wrapper yields. The trusted host is responsible for periodic behavioral health checks and custody. This does not supply hard CPU/RSS quotas or an independent watchdog after the entire host dies. Preserve the existing retained-process reconciliation and startup/cutover recovery contracts; do not infer independent parent-death guarantees from a JavaScript timer.

## Acceptance, dependencies, non-goals and material risks

Reproduce failing behavior before implementation. With an actual isolated worker and accelerated parent timer, advance beyond 300,000 and 600,000 ms of idle time and verify the same PID, healthy request/probe and retained checkpoint sequence. Separately send more than 1 MiB of aggregate valid bounded responses without closing the worker. Record accelerated-clock evidence distinctly from actual elapsed live observation.

Verify actual finite-job deadline/PID disappearance, hung startup and RPC termination, malformed/oversized/unsolicited frames, stderr overflow, observer failure and cancellation with actual drain. Deny persistent private/source/scratch writes, fork and network through the real sandbox. An actual GenerationHost idle test must preserve epoch, current memories/tasks and reservations; a genuine crash must still recover. Relevant existing worker/isolation/generation/authority suites and typechecking must pass. Fresh source and exact-artifact review precede installation; then observe the live host beyond its former five-minute expiry without replaying calls or changing allocations.

Dependencies are Node 24, macOS Seatbelt, the existing trusted worker harness, protocol receiver and custodian. Non-goals are broader command/subprocess grants, model/provider changes, funding/cadence changes, dependency upgrades and universal availability. Risks are accidentally exposing unlimited candidate writes/output buffering, weakening finite jobs, losing scope/epoch authority, abandoning owned processes on observer failure and confusing API availability with cognitive-worker reliability.
