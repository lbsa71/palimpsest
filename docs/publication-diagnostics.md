## Publication failure evidence

**Problem:** The first live plan publication retained an exact prepared commit and correctly held its unconfirmed push, but discarded all command failure evidence. The reservation-to-result interval was about 30.55 seconds against a 30-second command deadline. That is consistent with a timeout, but includes confirmation work and cannot establish which operation failed. Reconciliation also records its next observation deadline from a time sampled before the operation, so a slow operation can immediately permit another observation.

**Expected behavior:** Record one bounded push-command result after its existing push reservation, with exact candidate/target/commit identities, a fixed operation enum, exit code or null, signal or null, and a deadline flag tied to an actually observed timer expiration. Retain the fixed 30-second deadline under one host-owned timer; expiry settles the operation independently of pipe closure and requests SIGKILL for its positively owned detached process group, including ordinary subprocesses that ignore SIGTERM. A requested signal is not recorded as an observed termination signal. Record success as well as failure. Exclude raw arguments, URLs, streams, environment and error messages. Command execution evidence and independently observed publication remain separate: command failure can still mean remote success, and command success with unavailable remote confirmation remains uncertain. Start the observation backoff from completion of the observation operation.

**Acceptance:** Meaningful fixtures exercise a rejected initial push with retained sanitized diagnostics, actual deadline expiration, independently observed remote success despite failed command reporting, unavailable confirmation after a successful command, and durable restart with no second push. Every diagnostic has the target hash and follows `push_reserved`; no diagnostic-only preflight record creates an interrupted-preparation hold. Changing identities cannot authorize observation or replay. Existing frozen-source, remote identity, ancestry and no-checkout-mutation recovery checks remain enforced. A fake execution fixture alone does not prove operating-system timeout behavior; record any gap.

**Non-goals, dependencies and risks:** No automatic push retry, force push, longer timeout, destination change, credential exposure, candidate-controlled command/timeout, or modification of an uncertain old operation. The failed historical attempt cannot be retrospectively diagnosed. Additional metadata must not accidentally enter the publisher's preparation-state interpretation; timer cleanup and process shutdown must remain bounded. Promise settlement must not depend on inherited pipe closure after the parent exits. Terminate only the owned process group and prove that an ordinary descendant holding inherited pipes cannot keep publication pending or continue untracked; never signal unrelated processes. A descendant deliberately creating a separate process group is outside this proof. Abrupt host death before command completion can leave a reserved intent without a diagnostic, requiring observation rather than replay. Existing configured publication authority and immutable candidate evidence are prerequisites.
