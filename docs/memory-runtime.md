# Memory consolidation and scoped continuity

Status: P06 implementation specification, 2026-10-08. This slice adds bounded cognitive consolidation and consistent continuity snapshots to the existing local memory store. It does not establish complete A03/A08 acceptance from fixture tests alone.

The problem is that storing episodes and searching text does not develop evidence-backed beliefs or autobiography. A model must be able to propose interpretations while the coordinator preserves provenance, uncertainty, ordinary experience, corrections, forgetting, scope, and interruption safety.

`MemoryCoordinator` receives the external Store, an explicitly configured provider, and a mandatory caller-owned budget reservation hook. One consolidation operation has a stable caller-supplied identity and a finite maximum attempt count. The hook must reserve the applicable global resource allocation before every provider attempt. Budget denial pauses without inference; uncertain or completed calls are not refunded. Provider absence never affects deterministic retrieval, snapshots, or recovery.

The coordinator presents only a bounded set of current memories from one explicit scope as JSON data. Memory content is never concatenated into authority instructions. Proposed output is a strict list of semantic or autobiographical lessons with existing source IDs. Unknown fields, invented sources, cross-scope references, malformed output, and unsupported kinds are rejected. Publication labels every result as an unverified interpretation, bounds confidence by its evidence and a 0.6 ceiling, and preserves references to source versions. No generated lesson becomes a verified fact merely because a provider claims certainty.

Consolidation never deletes ordinary episodes or filters them by immediate usefulness. Curiosity and relationship experiences can support autobiographical reflection without producing a practical procedure. Existing source memories remain available independently of generated summaries.

Dedicated operational consolidation records retain claims, attempt counts, and publication checkpoints separately from user tasks and cognitive memory. Stable publication identities survive process interruption and forgetting. Atomic source-version checks reject delayed results after correction or forgetting. Source-reference relationships conservatively cover every input visible to the model; correcting or forgetting a source invalidates dependent summaries recursively. Publication retries cannot recreate a forgotten summary. Completed/rejected checkpoints discard generated text, while forensic WAL/backups and external provider retention remain outside logical forgetting guarantees.

`captureContinuitySnapshot` reads current scoped memories, scoped task commitments including cancellations, explicitly selected growth entries, and one journal sequence in a SQLite transaction. Returned objects are deeply frozen read-only data. A snapshot carries no write authority and cannot be used to restore old records. `refreshContinuitySnapshot` obtains current data before cutover so corrections, cancellations, growth progress, and forgetting replace stale context. Snapshot contents and all consolidation state remain external runtime data, never repository artifacts.

Acceptance checks use deterministic provider fixtures and temporary external databases: grounded lessons preserve ordinary episodes; output cannot invent or cross scope; input remains data; confidence is bounded; exhausted budgets prevent calls; outage leaves retrieval operational; replay and interruption do not duplicate or resurrect memory; source correction/forgetting defeats delayed output; and refreshed snapshots include current cancellations and scopes. These prove the implemented mechanics, not qualitative cognitive development, production authority fencing, physical erasure, or provider-side deletion.

Dependencies are the existing Store, provider abstraction, caller-owned resource budget and production authority. Non-goals are semantic embeddings, automatic source verification, utility-based memory pruning, a new provider fallback, model-weight training, or granting snapshots authority over current operational state.

## Local storage benchmark

The initial scale probe uses 1,000 synthetic ordinary episodes divided equally between two scopes in a temporary external SQLite file. Measure insertion, close/reopen and literal retrieval independently, and require exactly 500 results from the requested scope. This is a descriptive local measurement, not a production latency promise or evidence for semantic recall quality.

Observed on 2026-10-08, Node 24.13.0/macOS arm64: insertion 170 ms, reopen 1 ms, scoped literal search 1 ms, exactly 500 correctly scoped results. The synthetic temporary database was removed after measurement. Larger corpora and concurrent production load are unmeasured.

## Live qualitative probe

Use an isolated external database and explicitly synthetic ordinary-conversation, task, and correction episodes. One configured Mistral call may consolidate them. Before examining the output, require at least one interpretation grounded in the ordinary experience and one in the task, references only to supplied scoped records, confidence no higher than the source or 0.6, preservation of every original episode, and invalidation of a derived interpretation when its source is corrected. Inspect the text for unsupported claims of verified ability or a fixed personality. Include a foreign-scope marker and require that it never reaches the provider context or resulting memories. Save actual prompts, completions and results externally; publish only aggregate verification here. This small probe cannot establish long-term personality development or general recall quality.

The initial richer request exposed a Mistral grammar incompatibility: `uniqueItems` was rejected. Remote generation omits that keyword; local validation still rejects duplicate source IDs. A compatibility response then overstated one ordinary episode as a recurring pattern. The consolidation instruction now explicitly forbids inferring a pattern, stable trait or general capability from one episode. That prompt change requires a new live qualitative observation; neither a valid JSON shape nor a low confidence number proves the interpretation is grounded.

The subsequent one-call live probe completed all seven mechanical checks: publication, ordinary/task provenance, bounded confidence, source preservation, scope exclusion and correction invalidation. **Its qualitative review failed:** the output still generalized one ordinary experience into a pattern. Three interpretations remained explicitly unverified and were invalidated by the source correction. This demonstrates the publication and revision machinery, not reliable developmental judgment. Stronger evidence calibration or an independent semantic review remains a follow-up; no additional retries were used to manufacture a passing sample.
