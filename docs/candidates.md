# Frozen candidate evaluation

Status: P09 implementation contract, 2026-10-08. The candidate pipeline freezes proposed cognitive source changes and collects independent mechanical evidence. It does not grant approval, transfer authority, or replace the active release.

The problem is that passing checks on a mutable checkout cannot establish the identity or behavior of the code later admitted. A candidate must not modify its own checks or inherit the operator's credentials while being evaluated.

`freezeCandidate` requires a clean Git HEAD and builds the complete tracked snapshot under the external data directory's `releases` subtree. Proposed writes are limited to direct TypeScript files under `src/agent/`; traversal, duplicate paths, symlinks, no-op changes, and changes to the runtime, custody, providers, storage, tests, or engineering rules are rejected. The live checkout remains unchanged. Source files and manifests are read-only after freezing; filesystem permissions complement the independent sandbox boundary rather than replace it.

The manifest binds the base commit, complete file hashes and modes, cognitive-source digest, nonsecret configuration, explicit provider/model profile, runtime identity, acceptance contract, and installed trusted-check digest. `verifyFrozenCandidate` rechecks all frozen contents and the current base before use. Any mutation, stale base, altered installed check, or changed frozen manifest invalidates the candidate.

The runtime binding includes the Node binary and the complete installed development dependency tree, including the native TypeScript compiler. `typecheck` uses that exact hash-bound compiler in isolation with trusted strict flags, no emission, and no candidate-controlled compiler configuration. `trusted-agent-contract` is the other mandatory mechanical gate. Both check records include actual exit information, bounded stdout/stderr, and their digests. The evidence envelope has its own canonical digest. Verification repeats after checks finish to reject changes made during evaluation.

The manifest's `requiredChecks` is selected by trusted orchestration and always includes those two baseline gates. The evolution coordinator additionally requires the protected `cross-scope-memory` challenge, and the custodian independently requires the same gate. The installed check digest covers both baseline and promotion fixtures. `evaluateChallenge` can diagnose a known incumbent's additional limitations without representing that diagnostic result as its baseline admission grade. Tests prove the original entrypoint fails mixed-scope inputs and a scoped candidate passes, including filtering before memory-count bounds.

`evaluateCandidate` exercises the exact frozen snapshot under the [local isolation boundary](isolation.md). Protected fixtures and assertions live in the coordinator's installed `trusted/agent-contract.test.mjs`. The candidate receives fixture data and emits observable completion-request results in an isolated process. Assertions run outside that process, so a candidate cannot pass by replacing `node:assert`, manipulating a test reporter, or simply calling `process.exit(0)`. A valid process exit is necessary but insufficient. The normal contract checks structured task input, separation of system policy from recalled data, bounded memory, provenance and uncertainty, ordinary episodes, and bounded output requests. It does not establish every future cognitive-quality claim; a proposed improvement also needs appropriate before/after evidence and independent review.

Evidence is generated by the coordinator, includes the candidate/manifest identities and actual check outcomes, and is stored outside the repository. Failed checks preserve the current baseline. A candidate's own tests or explanation are supplementary evidence. No candidate-supplied pass/fail grade becomes an admission result.

`readManifest(releaseDir)` validates the serialized manifest identity. `verifyFrozenCandidate({ repositoryRoot, releaseDir })` additionally rehashes contents, compares protected files to Git objects at the declared base, and verifies installed inputs. Even recomputing an altered manifest cannot authorize protected-file changes. Historical rollback artifact checks may explicitly use `requireCurrentBase: false`; new-candidate admission must retain the default stale-base rejection. Configuration must already be nonsecret; obvious credential keys are rejected, but automatic detection cannot identify every secret string in arbitrary data.

The governance digest covers protected non-agent runtime source, trusted code, tests, package/lock/compiler configuration, AGENTS.md, and the seed/acceptance contracts. Progress, README, and research prose remains fully bound by the snapshot digest but can change in a later base commit without changing admission machinery. A candidate still cannot modify any non-agent file within its own transaction. This lets the operator record required progress alongside an admitted source change while preserving the separate governance-upgrade boundary.

Acceptance criteria: exact frozen identity survives reopening; prohibited edits fail; protected state remains outside the checkout; source or manifest tampering and stale bases fail; a behaviorally wrong candidate fails despite syntactically valid source; a candidate's early successful exit cannot manufacture a pass; valid changed behavior passes the normal contract. Tests use small temporary Git repositories and synthetic configuration, never production history or credentials.

Dependencies are a clean repository, Git, the selected Node/toolchain, the installed protected contract, and working process isolation. Non-goals are direct live edits, automatic merge/push, reviewer or interview approval, process cutover, resource isolation beyond the documented local boundary, and custodial self-upgrade.
