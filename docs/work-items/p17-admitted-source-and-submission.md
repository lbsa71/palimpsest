# P17 admitted full-source import and immutable submission

Status: bounded receiver implemented and fixture verified, 2026-10-10; connected serving acceptance and production gates remain separate. Part of [P17.3/P17.4](../../PLAN.md#p17--implement-the-seeds-iterative-coding-capability) and the approved [durable coding-session contract](p17-durable-coding-session.md), under [ADR 0019](../adr/0019-coding-autonomy-and-reusable-agent-plumbing.md), [ADR 0020](../adr/0020-isolated-workspace-files-and-reconciliation.md) and the still-unimplemented [ADR 0025](../adr/0025-retained-verification-and-execution-environments.md).

## Problem and expected behavior

The host can import caller-supplied workspace files, but it has no connected receiver that selects and verifies the complete admitted source from custody or retains an exact authored submission with a durable admission disposition. A cognitive-only source binding or a matching caller digest cannot establish the full source or authorize grafting today's checkout onto an older release.

The new source importer selects the active release from trusted GenerationHost custody, invokes its original asynchronous candidate verification, rechecks current actor/epoch/source authority after waits, and independently reads regular link-free bytes and modes twice before returning the WorkspaceBase, complete WorkspaceFileInput list, directories/root mode and trusted runtime/profile descriptors. Empty, executable, binary and non-agent files retain their exact identity; unadmitted checkout content is excluded.

CodingArtifacts stores an immutable full-source baseline artifact with task/session/attempt provenance and idempotent import receipt, then captures an immutable versioned `coding-submission/1` artifact from the actual CodingWorkspaces receiver. The artifact retains the complete file bytes/modes, directories/root mode, full-tree identity, original drafting base, independently observed current serving base, session contract and actual command receipt references. A durable Store receipt records exact changes and either a lossless cognitive-compatible bridge descriptor or `awaiting_supported_admission`. Classification is not review, admission, publication or activation.

## Acceptance criteria

- Actual custody/worker/collector fixtures import the admitted complete snapshot, including non-agent, empty, executable and binary files, into the real workspace receiver. Checkout drift never changes imported bytes.
- Missing verification inputs, tampered content/modes/manifest, links, stale origin/epoch, cancellation or expired authority return no source-bearing result. Recheck authority and time after every asynchronous boundary.
- Import retries retain the original immutable source artifact and session/attempt provenance rather than selecting a new base. Admission import may precede final contract digest; later reads and submission require that digest and current host authority.
- Real full-tree submission validates the expected workspace digest, actual manifest, writer quiescence, complete bytes/modes/directories and stable origin/current state. Mutation/base races and unresolved effects cannot silently receive compatible admission.
- Persist actual external artifacts plus durable Store receipts. Subsequent edits or restarts cannot alter a submitted artifact or make its prior evidence apply to a newer revision. Duplicate operation identity cannot create a second submission or confer new admission permission.
- Exact change classification preserves additions, deletions, modes, binary and non-agent changes. Only representable cognitive additions/modifications with unchanged supported modes and exact current base receive a bridge descriptor. All broader or base-changed drafts remain preserved awaiting a supported admission/reconciliation route.

## Scope, dependencies and risks

Owned files are only `src/coding-artifacts.ts`, `test/coding-artifacts.test.ts` and this work item. Existing Store events/effects, GenerationHost collector/custody and CodingWorkspaces manifest/writer contracts are dependencies. Integration separately adds trusted directory/root-mode inputs to WorkspaceImport, because files-only import would omit metadata. This receiver changes no evaluator, Custodian, protected check or grant. The native session coordinator owns ingress, finalized session contracts, tool exposure, scheduling and connecting a bridge descriptor to the actual cognitive route.

Source-bearing reads and submission require trusted current task/session authority, a live custody grant and finite expiry. Artifacts stay in a private directory outside the checkout. The source importer never fetches dependencies or selects a historical evaluator. Historical evaluator/runtime unavailability remains unavailable under the existing verification contract; this increment does not implement retained environments.

The [public receiver](../../src/coding-artifacts.ts) uses numeric millisecond `expiresAt`, task/session/attempt identity and the current epoch. Initial `importSource` permits an absent contract digest because admission must first bind its imported artifact and workspace. It persists `coding.source.import.intent` before collection, binding the originally selected release; a stopped retry may repeat verification for that same source, but cannot silently choose a changed base. The immutable `coding-source/1` artifact and `coding.source.imported` receipt retain that original selection across authorized epoch renewal. `readBaseFiles`, `readBaseTree` and `submit` require a finalized contract digest and current trusted authorization.

`WorkspaceBase.treeDigest` uses the workspace file-manifest schema (path, SHA-256, byte length and numeric mode), distinct from CandidateManifest.snapshotDigest. The sourceArtifactId seals the full retained source, including observed directory modes and the original manifest/runtime/profile. Finalized session admission must bind that ID; the legacy candidate snapshot identity itself covers regular files. Submission retains the full files and directory/root metadata plus its separate fullTreeDigest, and records actual command outcomes from the Store rather than accepting model-selected evidence references.

The compatible descriptor carries the admitted sourceBinding and complete freezer inputs. Its inputs can include cognitive bytes unchanged by the current authoring session but inherited from an earlier serving release: the legacy freezer starts from Git HEAD, so a diff against the drafting source alone could discard those bytes. Asynchronous bounded Git reads obtain only historical object identities and current clean-revision evidence; authored bytes come from the sealed workspace. Each owned metadata process closes before its outcome is accepted, with current authority, expiry, cancellation and quiescence checked after every wait. A changed checkout revision yields a preserved draft awaiting reconciliation.

The descriptor obeys the intersection of the unchanged freezer and actual legacy proposal parser: at most ten files, supported direct cognitive paths of at most 240 characters, nonempty UTF-8 content of at most 100,000 JavaScript characters and the freezer's existing byte/mode constraints. It also requires representable directory metadata and an exact current source. Broader changes, empty-directory changes, invalid UTF-8, format overflow or changed bases receive no lossy subset. `legacy_cognitive_format_limits_require_supported_admission` explains format overflow. The downstream receiver must still verify the exact frozen complete tree and perform every existing release check/review before admission.

The receiver's text read cannot capture binary bytes and there is no public general checkpoint operation. Submission therefore invokes the actual confined manifest receiver, then holds its existing writer claim during a synchronous independently verified no-follow complete-tree copy. A crash with an unproven claim remains held. No claim of protection against an unrestricted hostile process running as the same user or hard power-loss durability is made.

Import and submission apply the existing workspace limits (4,096 entries, 32 MiB total, 1 MiB per regular file). Unavailable or unsupported input remains unavailable; no truncation or dependency acquisition repairs it. Persistent unresolved effects or unproven writer ownership prevent capture, and cancellation drains positively owned helpers before returning.

Non-goals are live provider use, dependency installation, evaluator/Custodian changes, broader release admission, publication, deployment or full P17/P18 completion. Material risks are full-tree truncation, binary/mode loss, stale-source relabeling, incorrect quiescence, and confusing a preserved draft or compatible descriptor with an accepted release. Tests must reproduce missing behavior before implementation and retain actual filesystem/worker/collector evidence separately from later production gates.

## Evidence

The missing-feature RED established an actual serving worker, admitted baseline and two real collector jobs before the absent receiver failed with ERR_MODULE_NOT_FOUND. This proves the feature was missing; it is not a claim of a failing evaluator. Private evidence is retained under `/tmp/palimpsest-coding-artifacts-evidence/red` and `/tmp/palimpsest-coding-artifacts-evidence/green` with source/evidence pins in metadata.json.

The final actual receiver suite passed thirteen cases in 193,909 ms, with no failures, skips or cancellations (`node --test test/coding-artifacts.test.ts`, `green/artifacts-final-acceptance.tap`). It exercises full source and directory-mode import, external immutable artifacts, real confined manifest/mutations/commands, reopened Store receipts, concurrent/duplicate identities, changed checkout exclusion, exact freezer output, unsupported changes, source/artifact tampering, missing historical Git inputs, late expiry/revocation/abort, real recovery epoch fencing, manifest/byte races and actual stopped-helper cancellation. The stopped helper PID is gone before return; its unknown effect is preserved and reconciled as not-staged rather than replayed. Focused bridge/consumer-limit checks also passed three cases in 60,163 ms: exact eleven-file, 100,001-character and over-240-character-path artifacts remain preserved, while the unchanged actual parser rejects each representation. Final `npm run check` and `git diff --check` passed. Relative documentation links were verified locally.

The changed-base and inherited-source cases use actual frozen sources, workers, verification and custody transfer with explicitly synthetic cognitive envelopes only to drive the mechanical phase. Those envelopes are not evaluator passes, model review or release evidence. The inherited-source witness separately shows an actual diff-only freezer losing inherited serving bytes, followed by the complete bridge matching the exact submission; that is a mechanism witness, not a historical receiver-run RED.

These fixtures make no provider calls and use only private disposable repositories/state/artifacts. They establish this receiver's contracts, not eligible ingress, native provider conversion, shared accounting/fairness, automatic reporting, live activation or all P17 behavior. Those integration/production gates belong to the connected serving/coordinator work item and independent acceptance. No live state, keys, network, dependency installation, publication or installation was used.
