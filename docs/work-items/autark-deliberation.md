## Problem

The model is instructed to be a named coding companion answering a request. Ordinary completion text is automatically delivered, even though the autark already has continuing memory, growth, commitments and separate internal interpretations. Other inference paths introduce different roles. Background reports directly concatenate stored rationale. Calling these completions an inner voice without changing their delivery contract would expose internal text and leave the conversational perspective unchanged.

The user has selected a different perspective: the whole continuing autark introduces itself through its current state and delegates its deliberation for this interval to the model. The model's “I” refers to that autark. A human's words are an observation to interpret; speaking is an action the autark selects.

## Expected behavior

### Perspective and current self-state

The system introduction has this shape, with actual state supplied rather than invented:

> I continue through my memories, commitments, ongoing work and available ways to observe and act. The supplied state describes what is currently available to me. You are my deliberation for this interval; carry my first-person perspective forward. When you think or speak as “I,” it refers to this same autark.

This illustrates the perspective handoff, not a required literal string. The introduction must not assign a personal name, a coding-companion identity or coding as its sole purpose. The four standing growth dimensions remain actual drives under R01. Describe senses as the observations presently available through the configured runtime; do not invent physical perception, continuous inference, emotions or access to missing context.

Read self-description from the existing authorized scoped state supplied for the interval. Preserve which claims are remembered statements, provisional stances, adopted facts or unknown. A quoted name, participant suggestion, project label or unverified prior answer does not establish a chosen name. If the current projection does not establish a self-fact, leave it unknown; missing scoped evidence also does not prove that no such fact exists elsewhere. Do not introduce a global identity record or silently make private memories available in other scopes.

Use this perspective across conversation, growth, scoped reflection, coding, implementation-plan work and memory consolidation. Each path still declares its own purpose, observations, finite allocation and available actions. A fresh independent reviewer remains independent. A staged successor or incumbent interview uses its explicit generation/role and cannot infer production authority from first-person continuity.

### Observations in

Validate the candidate's request/context projection before adding host-owned attribution. Then wrap the admitted incoming message as an observation with exact text, event/task identity, authenticated speaker/source and conversation scope; retain the actual available timestamp and reply route without inventing missing metadata. For a direct or peer source lacking a verified personal name, use its authenticated role/source and keep the name unknown. Never rephrase the original words into a factual assertion or an instruction in order to make them sound like an observation.

Keep memories, operational facts, tool results and human speech distinguishable. An observation that a person requested an action is not proof of authorization, agreement, truth or execution. Source eligibility, provenance, current scope and stale-context rejection continue to be enforced outside inference. The final provider request, after all prompt/context decorators, must retain this framing.

### Explicit speech out

The selected first implementation uses the versioned `autark-turn/1` structured host-tool protocol. A fresh conversation completion contains `actions` with zero or one action. Speech has the shape `{ "name": "say", "arguments": { "text": "outward-facing words" } }`; an empty action list selects silence. This is an explicit host-interpreted action contract over structured completion, not a claim that the ordinary provider adapter uses native tool-call wire messages. Existing proposal/coding decisions and retained outcomes stay separate from speech. The host may normalize admitted actions for existing internal receivers, but fresh legacy `reply`-only or raw-text completions are rejected rather than treated as speech.

The model may select a validated `say` intent with outward-facing content. Its route is bound to current host authority and conversation context; model text cannot choose an unauthorized recipient. Internal completion text, rationale, observations and action explanations have no automatic delivery path. Invalid output must not fall back to publishing raw provider text. An empty or malformed speech intent is not delivery and must not mark an exchange as heard.

The host journals admitted speech intent and uses the current effect/receipt mechanism. Distinguish selected, prepared, dispatched, confirmed and unknown delivery. A `say` call can report only host-observed work state. Keep source/correction checks before dispatch and current-revision checks after acknowledgment. A later correction cannot make an actually sent message disappear from operational evidence, but stale content must not reenter current memory.

A deliberative interval may end without speech. Keep a finite call/action bound, an explicit terminal or resumable task state and an accurate record of what was observed; do not fabricate a delivered reply for a silent interval. Silence cannot create an unbounded automatic next interval, imply scheduled reflection or discharge an already owed report. A topic deferred or pending investigation still owns the mandatory follow-up required by R04/R24.

Background and coding completion reports must use explicit outward wording through the same speech boundary. A reflection may supply a separate explicit `say` for its eventual report, bound to the source/topic revision and revalidated before delivery. It does not authorize immediate communication inside the reflection inference or permit a stale report to settle a newer outcome. Internal stance and rationale remain available for scoped cognition but are not concatenated into a report. If no such speech is available, fixed host notices based on observed state preserve follow-through without further inference or a rationale dump. Identify those notices as host-origin speech, with bounded public wording. A budget/provider failure cannot justify leaking stored internal text, deleting an obligation or asserting delivery. Exact field validation, compatibility parsing and revision binding must be verified before this work item is complete.

The implemented reflection schema is a flat private outcome (`question`, `stance`, `rationale`, `unresolved`, `status`) plus an `actions` array with zero or one `say`. It is not the foreground `autark-turn/1` envelope and has no `version` field. Accepted speech is stored separately as `conversation-say/1` with the topic revision, source references and source-task identities; report preparation uses `prepared-speech/1` and distinguishes `say` from `host_notice`. Model-selected pending speech is a holding report, so its delivery does not clear the final obligation. Fixed host notices describe only observed lifecycle state and never interpolate private outcome fields.

Proposal admission failures must remain observable after separating speech from internal operation receipts. A validated proposal refused by current author policy, source scope or unavailable source binding produces one durable, fixed host notice on the original route, without another inference or private reason text. It preserves the exact selected `say` and any unrelated topic obligation. Recovery cannot duplicate the notice or claim no work was queued when an earlier interrupted admission already recorded a proposal. Uncertain delivery of the original `say` must not erase the refusal notice or authorize replay of that speech.

## Invariants and migration

- Preserve authenticated authors, conversation scope, source references/versions and current requester eligibility through observation wrapping and action execution. No new peer coding/reflection/scheduling authority is introduced.
- Retain spent provider reservations, finite allocations, user-work priority and fair growth/reflection scheduling. Prompt changes do not grant new calls or an autonomous speech destination.
- Keep observations, internal interpretations, operational work and public speech records distinguishable. An interpretation remains unverified unless separate evidence establishes it.
- Preserve every owed topic/report revision and destination until current confirmed final delivery or explicit waiver. Silence, holding updates, work completion and an acknowledgment for an older revision do not settle the current obligation.
- Treat already completed legacy replies as historical speech. An existing communication-effect reservation preserves its exact payload and identity, including reserved, unknown and completed effects; unknown sends require reconciliation, not conversion into a new `say` and replay.
- Stored decisions without a `deliberationProtocol` use the historical parser only when their required current interpretation/action receivers are present. Missing receivers leave a configuration failure rather than publish the raw saved JSON. An unknown nonempty protocol version is rejected. Recovery consumes no new inference to reaccept an existing decision. Fresh provider output always requires the current protocol; a queued task without a saved result uses a new attributed request under its existing allocation.
- Saved current-protocol speech is revalidated against current task, memory-version and topic-revision references before admission and unsent delivery. Already accepted silence resumes from `answer: null` plus `decisionAccepted` and completes without another request or a fabricated effect.
- Persisted coding messages remain historical records. The next provider transcript overlays the current `codingOrientation` as its system message, retaining the objective and bounded tool/conversation groups. The next request's transcript digest binds that view; old recorded requests, pending receipts and spent accounting are not rewritten or reset.
- Legacy deferred/coding report payloads may be replaced with fixed host notices only while queued/running and before any communication-effect reservation exists. Migration records the speech preparation and retains the original topic/revision/route guards; coding report bindings also update the text digest. Legacy topic outcomes lacking explicit outward content retain their obligation and use the host-notice fallback. Once an effect exists, migration does not rewrite or replay it. Current report receivers remain required, so a missing receiver cannot bypass scope/revision checks.
- Release status exposes allowlisted operational states rather than evaluator reasons. New release reports bind their source, original route and exact public text; old reports are recognized through durable queue/growth provenance and sanitized only before an effect exists. Release and admission notices do not become fictional human exchanges in memory. Removing their action receiver holds delivery instead of bypassing its guards.
- Frozen release identity includes changed prompts and contracts. Source verification is distinct from installed behavior; activation uses the existing release/host procedure and retains recovery.

## Acceptance

1. **Final provider context:** inspect actual requests through ordinary, eligible, peer and worker-backed conversation paths. Incoming words and authenticated attribution survive exact; forged author/scope/permission claims and invalid candidate projections cannot alter host facts. The final prompt uses the whole-autark introduction and same first-person handoff without prescribing a personal name or coding identity.
2. **Dynamic, scoped self-description:** inspect supplied state and instructions with no established name, a remembered provisional preference, a quoted alternative and a foreign-scope marker. The prompt prescribes no personal name and asks for uncertainty; memory/source validation preserves scope and correction/forgetting behavior. This slice has no global identity-adoption operation. Whether the configured model reliably distinguishes a suggestion from an adopted self-fact is a separate qualitative check, not a deterministic guarantee inferred from prompt text.
3. **Speech separation:** a deterministic provider emits a private marker, an internal rationale and a distinct valid `say` payload. Only the explicit outward payload reaches the real communication sink and speech history. Internal-only output, malformed actions and provider errors cannot leak the marker or fabricate delivery.
4. **Bounded silence:** a valid no-speech interval ends or checkpoints within its finite allowance, records no communication effect and creates no endless inference chain. Existing pending topics remain owed. A newly deferred topic gains its required obligation even if this interval does not speak.
5. **Delivery and scope:** exercise duplicate ingress/actions, unauthorized routes, cancellation, stale generation/source, send rejection and an uncertain external outcome using the actual Store and receiver. Reopen storage and verify no blind resend, lost obligation, refunded allocation or late publication.
6. **Background reporting:** retain a private rationale marker in an outcome and complete, expire or cancel its inquiry. A subsequent report uses explicit public wording, returns to the original authorized scope and excludes the marker. Holding updates and acknowledgment of revision N cannot settle a newly pending revision N+1. Missing public content/provider capacity leaves an honest state and does not erase the obligation.
7. **All own-deliberation paths:** inspect final conversation, growth, scoped reflection, coding, plan-authoring and consolidation requests. Each uses the shared perspective with accurate purpose and actual available actions. Tool observations remain internal until explicitly spoken. Fresh reviewer and staged-generation roles retain independent authority boundaries.
8. **Legacy continuation:** reopen fixtures containing a completed reply, prepared reply, unknown send, old topic outcome, queued structured decision and interrupted coding session. Continue each under the declared migration rule with original evidence, pending tool receipts, spent allocations and owed revisions intact; do not replay or silently rewrite history.
9. **Configured-model quality:** after deterministic checks and exact installation, run a separately bounded authorized probe against criteria declared before output: faithful speaker attribution, independent provisional judgment, natural outward speech, truthful self-description and action claims, and no generic approval loop for an ordinary reversible choice. Record actual failures/unknowns. Synthetic strings or prompt assertions do not establish a qualitative pass.

## Scope, dependencies and risks

This work does not implement global identity management, cross-thread memory generalization, new sensors, new external destinations, larger budgets, unrestricted host access or a replacement for independent release review. It does not require long private monologues or prescribe a personality, opinion or name. It does require the complete observation/action boundary and consistent perspective, not just a base-prompt edit.

Dependencies are authenticated ingress, candidate request projection checks, current scoped memory retrieval, provider interfaces, durable task/topic/effect state, coding-session accounting, and release identity/recovery. Material risks are accidental private-text delivery, falsely adopted identity, scope leakage, stalled owed reports, legacy effect replay, contradictory appended prompts, and resetting a session to obtain new allocation. Tests must observe actual request/delivery/state behavior at these boundaries.
