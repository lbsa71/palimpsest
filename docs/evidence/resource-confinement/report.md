## Implemented behavior and integration contract

Existing Linux cgroup v2, systemd delegation, `prlimit`, bubblewrap and ext4 are reused; no agent library or new package dependency is introduced. The prior read-only observation had unlimited CPU/file/memory limits and inherited global UID process/fd limits. These were not aggregate containment.

`ConfinedCommand.resourceLimits?: ResourceLimits` and `WorkspaceOptions.resourceLimits?: ResourceLimits` are optional solely to keep the deterministic fixtures source compatible. Every configured execution enforces its complete profile or throws; it never falls back to an unbounded launch. **Production readiness must require an explicit profile** through `diagnoseResourceConfinement(workspace, limits?)`; omission returns `ready:false`. The root application owner must propagate the profile to both model-loop workers and source-workspace commands in addition to the integrated tool paths.

The trusted supervisor must start within its own systemd service with `Delegate=cpu memory pids`, `User`/`Group` matching its host UID, and an independently configured service envelope (`MemoryMax`, `TasksMax`, `CPUQuota` as appropriate). Merely chowning a detached cgroup does not grant migration across the session/system-slice common ancestor. After acquiring the exclusive process lease, call `await initializeResourceDelegation(cgroupRoot)` **once before starting work**. It moves only this supervisor into `host/`, enables the three controllers and kills/drains/removes stale `command-*` leaves. Failure is execution unavailable; do not continue or invoke initialization to reap active workers.

`ResourceLimits` fields are `cgroupRoot`, `memoryBytes`, `pids`, `cpuQuotaMicros`, `cpuPeriodMicros`, `maxFileBytes`, `maxOpenFiles`, `workspaceBytes`, `workspaceInodes`. Configuration is host selected, never a worker/tool argument. The fresh leaf installs and reads back `memory.max`, zero swap, whole-group OOM killing, `pids.max` and aggregate `cpu.max`. A trusted shell blocks on fd 3 while the host assigns its PID; only then does it exec `prlimit` and bubblewrap. All subsequent threads/forks remain in the constrained domain. Worker mounts expose neither cgroup controls nor the backing block device.

Memory means cgroup-charged memory, including anonymous allocations, page cache and kernel accounting; it is not a virtual-address-space bound. CPU enforcement is an aggregate **rate quota** per period, plus the existing host wall timer and supplementary per-process `RLIMIT_CPU`. It is not a kernel-maintained lifetime cumulative CPU budget. The host timer requires the trusted supervisor to remain responsive; scheduling/draining can extend elapsed wall time. Do not describe the supplementary per-process CPU limit as the aggregate mechanism. The enclosing service envelope and application concurrency policy must also bound the trusted host and the sum of simultaneous workers.

`prlimit` imposes hard and soft file-size/fd ceilings and disables core dumps/locked memory. `runConfined` returns optional measured `resources` (`memoryPeakBytes`, `oomKills`, `pidsLimitHits`, `cpuUsageMicros`, `cpuThrottledMicros`), and `stoppedFor:'resource-limit'` on OOM. Kernel pids refusal need not kill a program; the receipt reports the event. File-size and disk/inode refusal use the ordinary nonzero/error observation. Output and the existing 64 MiB temporary filesystem remain bounded; tmpfs allocations are also charged to the cgroup.

Workspace byte and inode capacity is enforced by a fixed-size ext4 filesystem, covering trusted tool writes and command writes alike. Readiness checks actual filesystem type, block capacity and inode capacity against the declared limits. Execution refuses nested filesystem mounts crossing devices. A post-hoc usage scan or cgroup does not enforce disk capacity. `packages/supervisor/provision-workspace.mjs` is a one-time administrator helper: `create NEW_DIRECTORY UID GID BYTES INODES` preallocates a root-owned fixed backing image and mounts its workspace with `nodev,nosuid`; `remove DIRECTORY` verifies its owned layout and loop backing and removes this disposable resource. Creation refuses existing directories and therefore cannot truncate retained data. The supervisor uses no sudo; do not grant this helper as a worker capability. Production startup/remount/uninstall and retained-image preservation are the deployment owner's responsibility; the destructive `remove` command was used only for the disposable test image.

Termination writes `cgroup.kill` to include detached descendants, also kills the bubblewrap process group, waits for child close and kernel `populated 0`, reads observations, and removes the leaf. A 3-second failed drain throws execution unavailable. Parent death is independently handled by bubblewrap and the gate EOF; empty stale leaves are reaped on supervisor restart. Systemd should retain default `KillMode=control-group` for the enclosing service. No ambient privileged runtime process or service installation was added.

## Observed bounded validation

[Real TAP](real-tests.tap): **8 passed, 0 failed/skipped**, run inside a disposable delegated system service with outer `MemoryMax=256M`, `TasksMax=64`, `RuntimeMaxSec=45`. Test workspace was 16 MiB with 128 inodes, baseline worker memory 128 MiB, 24 processes, 20 ms CPU/100 ms period, file size 2 MiB, 64 descriptors. The memory test lowered aggregate memory to 64 MiB; four children requested only 20 MiB each. The process test attempted only 32 sleeping children. Storage tests wrote at most 24 MiB or created at most 256 empty files into the already bounded filesystem. No global host exhaustion was attempted.

The final measured OOM peak was **67,108,864 bytes**, with seven reported killed processes. The bounded process test reported two limit hits. Two busy child interpreters plus their parent under the 10 ms/100 ms CPU profile consumed **176,788 CPU microseconds** over **1,813.23 elapsed milliseconds**, with **3,498,262 throttled microseconds** (aggregate scheduling accounting may exceed wall time). File size stopped at exactly 2,097,152 bytes; descriptor opens failed with `EMFILE`; disk and inode allocation failed with `ENOSPC`. Every normal/OOM/timeout/cancel case removed its cgroup. A real disposable host `SIGKILL` left `populated 0`, prevented the detached child's delayed filesystem write, and restart removed its stale leaf.

[Component TAP](component-tests.tap): **20 passed, 0 failed/skipped**, covering existing authority, exclusive process lease, namespace protection, worker protocol and tool execution. Strict TypeScript check and `git diff --check` passed. Normal component runs include only the always-enabled readiness refusal; the real cases are explicitly opted in using `AEON_RESOURCE_WORKSPACE` rather than being presented as default-suite coverage.

The first real harness invocation used `node --test`, which left the test-runner parent in the delegation root and correctly failed controller enabling with `EBUSY`. The corrected harness runs the test module directly as the service's sole main process, matching the supervisor initialization contract. This was a harness failure, not evidence of fallback execution. Subsequent controlled runs passed. The final command and output are retained in the TAP receipt.

The fixed workspace preserved a marker file through a real administrator unmount/remount. After validation the test filesystem was unmounted and removed. The backing image, loop association, temporary directory and all four transient service cgroups were verified absent. No delegation grant, mount, service or sudo policy remains. The retired service was never restarted; no external messages, provider calls, publication or network work occurred.
