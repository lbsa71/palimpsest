# Quality of self-authored changes

Status: inspection contract and instruction refinement, 2026-10-09; R03 and the user's explicit quality-inspection direction. Passing an acceptance check establishes that check's observed behavior. It does not establish maintainability, useful improvement or broad correctness.

Before admission, a fresh engineering reviewer inspects the exact frozen before/after source, selected host work contract and independently collected evidence. The review evaluates whether the change addresses the actual defect; preserves earlier capabilities, scope and recovery contracts; remains small and readable; handles relevant boundary cases; and respects configured resources. Descriptive names, simple control flow and accurate comments matter. Hard-coded fixtures, weakened gates, speculative dependencies, unnecessary rewrites and cosmetic claims of capability are defects. Missing evidence is inconclusive, not success.

The authoring instructions ask for the smallest sound change, grounded reasoning and testable behavior. They prohibit inventing test results. Failure diagnostics and relevant review findings reach a separately allocated next attempt. Problem-specific hints explain observed constraints rather than dictate source: memory lineage is immutable data, JSON escaping counts toward bytes, newest order must be chronological, and truncation must preserve valid character boundaries. Review also considers useful context retention: reducing each experience to a token merely to satisfy a limit should be rejected even if a narrow mechanical bound passes.

After each live shed, the implementation lead inspects the admitted bytes and actual independent results. Record the requested behavior, substantive change, check/review findings, source identity, continuity/publication observations, and limitations. Tune instructions or checks only from concrete evidence, with host changes reviewed and installed separately. A candidate cannot revise the contract admitting itself. Qualitative judgments remain fallible; a model's confidence or coherent explanation does not override a failed mechanical check.

The prior live conversational shed (`f3def48`) corrected obsolete capability-denial policy while retaining the existing scope filter. Inspection also shows the current memory descriptor still omits version, evidence and update time, and its bounded list alone does not establish a total UTF-8 budget. These observed limitations motivate the two P06 contracts. They are not claims that the new contracts have already completed live.
