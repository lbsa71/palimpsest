## Behavioral specification and design

1. The incumbent may publish a boot target only after the release journal records prior-policy probation acceptance of that exact candidate/policy. Host-executed bootstrap source is already classified as control source; its changes require the existing separate control-upgrade path.
2. Before publication, verify candidate and runtime bytes, copy the exact Node into a private bounded boot snapshot, and bind its candidate/policy/runtime identity. For initial candidates without a runtime bundle this is a retained executable copy, not a fabricated candidate-bundle claim. Freeze and fsync the whole snapshot before atomic active-reference replacement.
3. Normal boot executes `/usr/bin/env --chdir=<selected-slot> ./node payload/deployment/bootstrap-evolution.ts ...`. Resolving the directory once avoids mixed Node/source generations if the active reference changes. Selected bootstrap checks its own canonical runtime, source and descriptor, and runs its selected installation preflight. Derived runtime configuration preserves the externally configured host grant while using the retained exact Node path.
4. Publishing active never changes rescue. Rescue rotation is a separate accepted-host API which requires an accepted active target, an exact current-authority/runtime boot-ready witness written only after that snapshot reports normal-boot readiness, and no failure latch. It retains older snapshots. No candidate-authored verdict is accepted as a substitute for release acceptance.
5. Failed normal execution, including a malformed Node that cannot run any application fallback, latches rescue through a fixed systemd `ExecStopPost` shell command. `KillMode=control-group` drains the failed generation before `Restart=on-failure` starts the same unit/UID/resource grant. The shell does not implement admission or evaluate candidate text. Clean systemd stops do not latch rescue. Existing start-rate limits bound repeated rescue failures.
6. The independent rescue verifies that its target was previously accepted, requires free launcher/coordinator leases, and restores only host code selection. It retains the actual operational database and monotonic authority journal. No model, signing key or fresh evaluator is needed for the selection operation. Usable credentials/configuration still depend on existing preflight/application contracts.
7. Interrupted snapshot creation is non-executable staging; interrupted pointer publication selects either complete target. A crash before clearing a prior failure latch conservatively retains rescue. Initial partial provisioning can finish its missing active reference; reinstallation preserves established active/rescue selections. State, old snapshots and uncertain-effect records are never deleted to make space.

Reuse decision: use systemd's existing cgroup stop/restart behavior, GNU env's single chdir and the existing release/lease/verification machinery. A new root broker, second service/user manager and an application-owned descendant killer add authority or incompatible cgroup bindings without solving a necessary problem. The fixed shell is OS process-manager configuration. Its only decisions are failure-latch selection and recording `SERVICE_RESULT`; all evolving application logic runs unprivileged in the selected source.

## Limits and next review

The real systemd check runs small explicit process fixtures through the generated selection/failure commands; it does not run the entire frozen product with privileged mounts, model tools and the new boot preflight in that one service. Existing host-succession tests separately exercise frozen successor source/Node, authority epochs, provider-independent recovery and operational history. Passing these separate checks is not a claim that their complete installed composition has been demonstrated. Fresh consequential review and an installed-composition rehearsal remain required before product acceptance.

Rescue rotation is currently a host API, not an ordinary evolution-mailbox operation, and does not itself conduct a new independent evaluation. It relies on the completed prior-control candidate acceptance and on accepted host code invoking the separate operation. The added boot-ready witness prevents rotating to an accepted snapshot that has not completed normal bootstrap, and rejects prior authority epochs. That callback/rotation composition still requires fresh review; do not call automatic rescue rotation qualified.

Installer/renderer/provisioning source remains editable and admissible as control source. Actual privileged reapplication of units or provisioning, even under an unchanged declared grant, remains administrator-only in this implementation. Existing mounts and the unchanging OS grant need no privileged application-source execution for normal boot/runtime/preflight upgrades. This is explicitly narrower than arbitrary privileged whole-host evolution; no permanent human-only *normal runtime* component is claimed as a solution. New external resource/UID/mount authority cannot self-escalate.

Retention consumes the fixed host-data volume. ENOSPC or missing/corrupt rescue leaves a visible bounded failure, never silent deletion. Recovery assumes accepted host generations preserve readable state and rescue artifacts; arbitrary destruction by an already accepted host is not repaired by a boot pointer. ELF-loader/shared-library and other OS dependencies remain externally granted platform prerequisites.
