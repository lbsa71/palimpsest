## Implemented boundary

`ServiceProcess.start(candidateId, authority, evolution?)` accepts public `{ policyDigest, allowedModelIds? }`. Product startup requires this metadata; engineering starts without it expose explicit unavailable evolution tools. Validation rejects extra metadata fields, non-digest policies and unbounded model lists. No evaluator credentials enter the child. Supervisor bootstrap supplies its authenticated policy digest; successor and recovery startup use `status.probationJudge?.policyDigest ?? status.active.policyDigest`, preserving the old judge during control probation.

The actual frozen service child installs `ordinaryServiceTools` through `AutarkApplication.additionalTools`: source checkout/check, proposal, freeze, external evaluation, release submission and status. It also installs root-owned handoff tools. Human author eligibility comes from accepted direct modification eligibility and Slack eligible IDs; the model allowlist comes from public parent metadata, defaulting to the accepted model. Provenance uses the existing host `proposalProvenance` callback and independent origin checks. Source/evidence/policy paths and grants are host-selected.

`EvolutionMailbox` uses the same host-private `operational.sqlite` as ordinary runs. Its `host.evolution-jobs` documents bind each stable request ID to an immutable request artifact, exact candidate, proposal, policy and authority. Payloads are bounded to 8 MiB; at most 32 unresolved jobs are queued by default. Model callbacks persist jobs and wait at most 30 seconds with cancellation. A timeout leaves the durable job unresolved and reports the stable ID.

Host APIs `jobs/status/request`, `processEvaluation`, `completeEvaluation`, `processSubmission`, `completeSubmission` and `recover` form an explicit external evaluator/controller rendezvous. `processEvaluation` takes a trusted externally configured evaluator callback. Completion requires an externally signed complete `ReleaseProof`, binds its candidate manifest, prior authority, evidence and artifact identities, and stores the proof independently of the author response. A host-configured `readArtifact` resolver can ingest the production `sha256:` evidence scheme; verified bounded evidence bytes are retained in operational artifacts without rewriting the signed references. `mailbox.readArtifact` lets the controller read those retained original content addresses after external receipt loss. Authentication and accepted evaluator/policy qualification remain enforced by the real release controller. The mailbox has no signing implementation or default passing evaluator.

`processSubmission` supplies the stored external proof to a trusted host coordinator callback. That callback invokes `ServiceSupervisor.release` for an ordinary change or `stageControl` with a host-registered next policy for a control change. It must return the corresponding exact submission receipt. Stage versus activation remains a controller decision. A completed trusted transfer receipt may be retained after the author is fenced. Interrupted dispatches become `uncertain`; processing refuses to dispatch them again. The operator/evaluator reconciles the exact job ID using the completion APIs, rather than blindly retrying.
