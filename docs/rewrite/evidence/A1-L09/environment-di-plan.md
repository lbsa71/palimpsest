## Interface decisions proposed for adoption

1. **Small capabilities, supplied once.** Reuse existing ports and `Pick`-sized interfaces before creating a type. Share only the genuinely common `WallClock { nowMs(): number }`, `MonotonicClock { nowMs(): number }`, `IdSource { nextId(): string }`, and cancelable timer semantics if useful. Preserve root's accepted broker names; adapt at composition, do not rename them for consistency alone. A timer port schedules a callback and returns an idempotent `cancel()` handle; sleep/timeout helpers are built on that port with observable disposal. Do not expose Node handles to pure logic. Wall time establishes timestamps/signed windows; monotonic time measures local durations. Neither can silently replace the other.
2. **Explicit defaults only at composition.** A named production factory or host constructor may build concrete adapters. Internal domain functions receive a value/port and never fall back to Date/process/global fetch. Capture approved function identities once, including methods that need binding; mutation of an options object cannot swap time, transport or ownership mid-operation. Existing entry signatures can remain production facades where justified; no legacy compatibility requirement exists. Shared C1 schema changes need L01, and root serializes public call-site composition. No reflection, decorator registry, dependency resolution framework or application-wide service locator.
3. **Separate storage and file capabilities.** Domain code normally receives existing Store operations; do not duplicate the store. Storage adapters receive a bounded `openDatabase(filename, mode)` factory and filesystem operations needed for canonical/private-path checks; the SQL handle exposes only used exec/prepare/statement/close operations with synchronous transaction behavior. Preserve real SQLite WAL, CAS, rollback and locks. For protected files retain fd-relative `open/read/fstat/fsync/link/close` semantics and before/after inode/device checks. A `readText(path)` facade that bypasses custody/race checks is insufficient. A source identity port returns actual device/inode/journal identity, not caller claims.
4. **Process/network ports retain mechanisms.** Reuse `runWorker(WorkerOptions)` and confined command APIs at their consumers. Inside the implementation, separate spawn/streams/close/kill, procfs/kernel observations and timers. Keep authority checking outside injected effect executors and immediately around actual dispatch. Research receives resolver and bounded pinned-request capabilities; the request adapter must use the validated address, not resolve it again. Slack/provider ports include streamed bodies, cancellation and explicit close; fake returns cannot skip byte/resource accounting.
5. **Host composition is privileged, testability is not evidence authority.** Callable ports never enter ApplicationConfig, model tools, signed payloads, worker JSON, prompts or candidate packets. Public live acquisition entrypoints must still reject caller transport/evaluator/sensor overrides. Trusted launchers choose concrete live adapters; test-only composition returns evidence marked synthetic/engineering and ineligible for live acceptance. Do not use a caller-selected `kind:'host'` flag as authentication. A DI implementation change affecting observer/control/source identity must be staged and manifest-bound under the prior accepted controls. Existing source-custody, current-use/withdrawal, owner locks and live/synthetic predicates remain authoritative.
6. **Entropy is distinct from identity.** Inject deterministic IDs in tests, detecting duplicate/malformed IDs before destructive overwrite. Host-generated secret/signing material needs an explicit entropy source; production uses secure randomness. Do not use test IDs or seeded fixture bytes as operational credentials. Deterministic hashes of supplied bytes stay pure and retain the exact algorithm/schema.
7. **Other host state includes collation and ambient base URLs.** DI01 freezes explicit string ordering/case-folding semantics. A host collation adapter, if retained, is injected and its locale/runtime identity is part of affected manifests; prefer pure explicitly specified ordering where behavior permits. Do not silently replace locale ordering in existing signed digests: demonstrate equivalent accepted inputs or stage a separately versioned identity change under prior controls. Every task owns this closure in its listed files, including memory tie breaks, scheduling, artifact/registry ordering and evidence inventories. Retained schema base URI must be explicit or a constant pure default, not browser location.
8. **Cleanup and unknowns remain visible.** Clock failure/regression/nonfinite readings, timeout setup failure, database/file/network/process errors, cancellation races, shutdown and failed cleanup propagate through the same ports. An uncertain dispatched request retains original reserved charges; elapsed zero or successful cleanup must not be invented. Preserve durable pending records and late authentic settlement. Use controlled real adapters for mechanism evidence separately from deterministic fakes.

**Root interface-release protocol:** for mutually consuming components, root first records one exact interface-only revision, consumer signatures, deterministic fake contract and the owners allowed to consume it. This permits independent authoring and component checks without requiring mutual implementation acceptance. In particular, freeze DI06/DI06a schema-call signatures together before either implementation; freeze the DI17/DI22 observer/adapter signatures before their parallel implementation; likewise freeze DI20/DI21 worker framing. Interface freeze is not behavioral acceptance. Once both exact implementation commits exist, root assembles a separate join revision and obtains fresh review of the cross-component predicates; neither component can accept its dependency by pointing at its own fake. If an interface changes, root versions and releases it again to all named consumers before further integration. Final-join dependencies mean this joined check, not circular waits for each other's prior fresh acceptance.

There is no implicit concurrent shared-file ownership: DI14 follows DI02 on application/broker; DI18 follows b2; DI24 follows b3; DI15 waits for relevant control repair release. New helper/test/evidence paths are unique. Where a dependency is listed as an API requirement, authoring against a frozen fake is possible; acceptance requires the actual joined dependency. Root owns central PLAN/execution/lane status/config/lockfile integration; this design author does not modify them. A source owner must request root reassignment for an uncovered file rather than silently expand its path set.
