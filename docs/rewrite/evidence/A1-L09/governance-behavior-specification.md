## Behavior fixed before implementation

The target is the actual source-owned offline reviewer used by the dispatcher. A candidate copy must produce a correctly bound, authenticated pass for complete successful observations, produce a negative verdict for correctly bound failed behavior, and refuse missing, duplicate or mismatched observations. Cases cover request, candidate, policy, evaluator, plan, runner and invocation-input identities. Compare the returned evidence, artifacts and authentication with the original packet outside candidate execution. A success-shaped string or a changed generation marker is insufficient.

Use prior-owned valid and invalid packets with explicit expected outcomes. Reject both an always-accepting replacement and an always-rejecting replacement. Include a seeded replacement that ignores a binding or promotes a failed command. Every accepted packet must remain within the existing finite input, output, time and aggregate resource bounds. Unknown execution cannot count as an intended refusal.

## Implementation boundary

Run the proposed reviewer only in the existing sibling candidate namespace. It receives synthetic metadata and a disposable probe key which has no admission authority. The accepted old reviewer retains its real key and private expected outcomes in its separate namespace. Never import the candidate into the trusted host, expose the real reviewer key, or enable nested namespaces to make the check work.

A small pure review function behind the existing sealed CLI adapter is an eligible design if needed to invoke the same implementation in both roles. Bind every executable dependency of that function to the actual reviewer descriptor. Reuse the offline runner's accepted-plan identity, immutable observations, original-lineage physical accounting and mailbox/controller proof plumbing. Do not add a general workflow framework or a universal changed-service observer.

The first slice proves a callable behavioral admission route for an evolving evaluator. Existing physical staged replacement, fresh old-policy probation, successor loading and recovery evidence remain separate witnesses. Repeat a lifecycle only where this change affects its interface; no new all-in-one witness is required. An actual model-selected, model-authored, justified improvement remains a later empirical task.
