## Frozen API and fault ordering

Use `DevelopmentAccounting` as a host-only composition adapter. `ApplicationOptions.developmentAccounting` is an optional trusted construction factory receiving the actual operational store and validated configuration. It is absent from application configuration and model tools. The factory returns the adapter, which supplies a `ResourceLedger` subclass, wraps the actual `ShellPort` and `EffectReceiver`, and records broker transport and raw response facts. Application construction verifies its exact configuration/profile binding. Ordinary composition uses its unchanged ledger and shell when the factory is absent. The broker gains only an optional synchronous raw response hook, called before trusted provider settlement.

The constructor requires the externally accepted registration/role digests, unchanged original grant and ledger, actual closure/configuration/profile, host transport signing identity/key, descriptor-pinned raw store and a synchronous recorder capacity reservation callback. Signed facts authenticate the trusted host, not candidate assertions. The external qualification of registration, roles, clock, observer and transport remains outside this bridge. No framework or dependency is added.

Preflight requires an existing original root with exact original envelope, issued-at and deadline, already accepted role allocations, and an exact original-request inventory at a quiescent registration boundary. No original request may be reserved, dispatched or uncertain. Original anchor rows must stay identical thereafter; changed anchors or unobserved requests refuse work. The immutable anchor limitation is conservative and explicit. The bridge cannot import or qualify historical rows, fabricate atomicity, or accept an unsupported route.

Isolated local root maps to its accepted original role allocation; every other allocation, request, reservation and parent identity maps deterministically using registration/role identity. The binding and mappings are durable in the original store, so replacing local state cannot reset original lifetime, sublimits or charges. Candidate composition can share the original store: candidate requests keep physical IDs and descendants are allocated under the accepted candidate role; no duplicate local physical charge is created. Existing allocations inconsistent with this role route refuse dispatch. All local allocation sublimits must fit their original parent. Mapping and original allocation commit before any local allocation write. Repeated contradictory bindings fail.

Before receiver entry, original dispatch and transition commit first, followed by local dispatch/effect intent. A missing local row never proves non-dispatch. The receiver and provider entry paths recheck actual original dispatched state and original cancellation/deadline. IDs are never silently replayed; an orphan blocks its role's continuation.
