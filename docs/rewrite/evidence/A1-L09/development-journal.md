## Pre-code API and causal freeze

`StoreOptions.documentJournal?: DocumentJournalOptions | null`, and identically typed trusted `ApplicationOptions.documentJournal`, are host construction inputs only. Options are `{ stream: string; hostId: string; maxAnchorDocuments: number; maxAnchorBytes: number }`, with nonempty identities and nonnegative safe integer ceilings. No model/configuration/tool input, callbacks, new dependency, schema migration, or second database. Application passes the option when opening its OperationalStore, before its first document mutation. Omission adopts an existing binding; explicit null refuses a bound store. Any contradictory options refuse. Unbound ordinary stores retain ordinary document behavior.

Published reserved namespace/key are `system.document-journal` / `binding`. The revision-one binding contains schema `aeon.document-journal.v1`, all four options, `anchorId` and `anchorSequence`. Generic put/delete refuse the whole reserved namespace, and generic append refuses reserved journal event types. Binding creation and anchor append happen together under the existing BEGIN IMMEDIATE transaction. Anchor event type is `document-journal-anchor`, stream is the host stream, ID is host-generated UUID, and data is `{ schema, hostId, documents }`; documents are actual `{namespace,key,revision,value}` rows sorted namespace/key, excluding reserved metadata. Pre-materialization SQL counts rows and computes a conservative byte upper bound (six times stored UTF-8 row bytes plus per-row/host/schema overhead); excess refuses before selecting values. Exact canonical anchor bytes are also checked. This can conservatively reject an otherwise fitting snapshot. Both limits are durable binding identity.

`document-mutation` events contain `{ schema, hostId, namespace, key, before: Document|null, after: Document|null }`, actual stored values/revisions, in the same transaction/savepoint as the successful CAS put/delete. The document SQL mutation precedes the journal INSERT; either failure rolls back both. Failed CAS/serialization creates no journal event. Outer rollback also removes all nested writes/events. Delete followed by recreate may restart revision at one; immutable global event sequence and before/after null make the history unambiguous. No complete-history claim precedes anchorSequence. Public `documentJournalBinding()` returns the validated binding or null. Every put/delete rereads and validates the persisted binding, including writers opened before activation or reopened without options. Once a handle observes a binding, deletion/change refuses. Reopen validates the anchor; missing binding with retained reserved events refuses. Raw SQL outside OperationalStore is outside this writer closure; recorder independently checks immutable event prefix and replays the anchor/mutations against current snapshots.

The recorder already captures all document rows plus global event prefix in one bounded read-only transaction. It must inspect the reserved binding, retain the anchor, and replay ordered mutations to the current snapshot. Journal presence does not independently qualify observer completeness, host identity, recorder bounds, or history before activation.
