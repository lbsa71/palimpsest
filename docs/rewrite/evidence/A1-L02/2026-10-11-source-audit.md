- AI SDK's agent wrapper is 323 lines but delegates to generation/stream engines. ## Discriminating implementation findings

**Pi.** Core constructs no unsolicited base persona and requires a supplied stream function unless the host explicitly installed a fallback. It supports tool preflight and host context/request hooks. Core has no built-in persistence/compactor/delegation. `continue()` rejects a transcript ending with an assistant message; restart after tool requests therefore requires host reconciliation and materialized tool results. Existing transcript system text can outlive a replacement constructor prompt. [Agent construction](https://github.com/earendil-works/pi/blob/89e5c2c075535e2f427c30fc74720d65b2944ff9/packages/agent/src/agent.ts), [transcript behavior](https://github.com/earendil-works/pi/blob/89e5c2c075535e2f427c30fc74720d65b2944ff9/packages/ai/src/utils/transcript.ts).

Pi's provider surface is not neutral merely because its core is. Anthropic OAuth injects a Claude Code identity; Codex Responses adds a fallback assistant instruction. The retry helper defaults to zero retries and SDK retries are disabled in inspected paths, but Codex WebSocket continuation retries/SSE fallback are separate. A fetch-only observer cannot count WebSocket dispatch. The initial selected API transport must expose every physical attempt and final request; add other paths only after audit. [Retry helper](https://github.com/earendil-works/pi/blob/89e5c2c075535e2f427c30fc74720d65b2944ff9/packages/ai/src/utils/provider-retry.ts), [Codex adapter](https://github.com/earendil-works/pi/blob/89e5c2c075535e2f427c30fc74720d65b2944ff9/packages/ai/src/api/openai-codex-responses.ts).

Pi's ordinary AI build regenerates model catalogs; offline build needs validated hydrated data absent from the fresh clone. Upstream local-package tooling is useful but its pack operation builds all public packages. A narrow reproducible workspace build is implementation work, not a capability established by this audit. The optional durable package supplies more machinery with its own state ownership; it is an alternative to evaluate, not an automatic core dependency. [Packer](https://github.com/earendil-works/pi/blob/89e5c2c075535e2f427c30fc74720d65b2944ff9/scripts/pack-packages.mjs).

**Rig.** AgentRun performs no I/O and serializes explicit pending model/tool steps. Reissued pending work requires the host to account, cancel/drain and reconcile; a reissued model attempt is not inherently another consumed turn. The run envelope is version checked, but cross-version state compatibility is not guaranteed. High-level hooks do not execute when a host directly drives the low-level stepper. RunSpec defaults to no preamble and one model call; output-preamble augmentation is enabled for applicable structured-output modes. Explicit configuration is essential. [Run defaults](https://github.com/0xPlaygrounds/rig/blob/9e7cb6000355b7ae1a89c913bf98b8a6f17661ee/crates/rig-agent/src/run/spec.rs), [stepper fixture](https://github.com/0xPlaygrounds/rig/blob/9e7cb6000355b7ae1a89c913bf98b8a6f17661ee/tests/fixtures/agent_run_stepper/src/main.rs), [Mistral dialect](https://github.com/0xPlaygrounds/rig/blob/9e7cb6000355b7ae1a89c913bf98b8a6f17661ee/crates/rig-core/src/providers/openai/wire/dialects.rs#L270).

**AI SDK.** Ordinary instructions are caller supplied; Mistral JSON-object mode adds formatting text and `safePrompt` exposes a provider-specific setting. Requests default to two retries; zero disables that layer. The separate stream-retry surface has different semantics: omission disables it, while explicit zero can still permit a callback-requested retry. Logical callbacks need not fire for every request attempt. Use direct provider transport capture, preserve raw usage and unknown outcomes, and do not infer physical accounting from a tool-loop step counter. Packages execute built `dist`, so source edits need a rebuild and successor restart. [Retry policy](https://github.com/vercel/ai/blob/ba05943b69ad070558bb5bc912da99ec66d7d263/packages/ai/src/util/prepare-retries.ts), [stream engine](https://github.com/vercel/ai/blob/ba05943b69ad070558bb5bc912da99ec66d7d263/packages/ai/src/generate-text/stream-text.ts), [shared build config](https://github.com/vercel/ai/blob/ba05943b69ad070558bb5bc912da99ec66d7d263/tools/tsdown-config.mts).

**Codex.** Official OpenAI documentation describes [App Server](https://learn.chatgpt.com/docs/app-server); current source also supplies a native [core API sample](https://github.com/openai/codex/blob/72f999edc7848961b99c4b98bf1e62d12fa35798/codex-rs/thread-manager-sample/src/main.rs). Custom base text does not remove every context contributor. The selected source wire API accepts Responses, not Chat Completions; [gateway compatibility](https://learn.chatgpt.com/docs/enterprise/gateway-compatibility) requires a genuine compatible tool round trip. [Hooks](https://learn.chatgpt.com/docs/hooks) document coverage limits, so they are not a universal effect monitor. Its exclusion from the final three rests on fit and source burden, not a claim that it cannot be embedded or forked.

## Decision versus unresolved evidence

The source review supports the chosen integration strategy and identifies concrete risks. It does not establish Pi's reduced build, transport/effect invariants, recovery or comparative task quality. Q1–Q5 in ADR 0032 supply the exact follow-up. Build/activation simplicity and autonomous modification success must be measured; no conclusion here uses the human's language aesthetics as a criterion.
