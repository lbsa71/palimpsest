# TypeBox dependency reassessment

This is inspection and an unadopted temporary candidate, not a source dependency adoption. Pi remains selected. TypeBox 1.3.27 remains pinned as an **interim external dependency**, so Q1's complete editable runtime-dependency boundary is not satisfied.

The source checkout is TypeBox tag `1.3.27`, commit `ffe23ba614322bf0dcb846ceaf7c1bbc7ef0bba6` from `https://github.com/sinclairzx81/typebox`. Source is MIT. Its standard `index`, `compile`, `value` and `error` paths transitively reach **691 of 694 source files, 47,785 physical lines, 2,357,452 source bytes**. Even direct Compile/Convert entry points reach 687 files because internal barrels tie validation to broader type/value/schema engines. Shipping only its public API files would hide that maintained closure. Its npm installation is 6.2 MiB/1,385 files including generated declarations/builds.

A temporary ordinary-source candidate was checked to distinguish source buildability from scope: it needed syntax-only changes in eight files (parameter properties → declared fields and constructor assignments; numeric ByteMarker enum → constant object). It passed strict erasable TypeScript checks and the existing 22 shell cases. Clean, warm and edited builds measured 5.902 s, 5.875 s and 5.796 s; regression runs and a fresh edited-dependency process passed. The provenance/hash inventory is `experiments/agent-shell/audit/typebox-source-manifest.json`; the unadopted measurements are `experiments/agent-shell/results/typebox-unadopted-probe.json`. The candidate was removed at the lead's scope reassessment. **None of those TypeBox source/syntax patches is present or loaded in the handed-off shell.**

The next finite dependency task should compare a small existing JSON Schema validator against the retained validation/coercion behavior, including invalid and optional-null arguments. A possible candidate is `@cfworker/json-schema`; it has not been inspected or selected here. Use explicit JSON schema types if justified and avoid replacing proven validation with a bespoke unsafe checker. Bound its source/import closure, licensing, behavioral differences and local edit/build/restart proof before adoption. No Rig fallback is justified merely by this schema dependency's breadth.

For ADR0032's lead-owned addendum: the selected Pi loop stays unchanged; the interim validator's editable-source gate is open, and the observed 47,785-line closure makes wholesale TypeBox retention inconsistent with the user's cherry-picking preference. A bounded existing-validator comparison is the concrete next step. This changes a dependency qualification disposition, not the agent-loop architecture or model default. Compiler/Node sources need reproducible explicit checkout/build/patch procedures and pinned toolchain artifacts; they need not be bundled wholesale in the primary source tree.
