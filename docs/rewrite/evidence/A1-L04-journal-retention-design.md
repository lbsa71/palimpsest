## Decision and evidence

Keep the journal's immutable event identities and ordered structural history. Move its raw document values into individually owned, withdrawable payload records in the **same OperationalStore**. `forget`/`expire` withdraw the journal copies of affected memory-owned documents in the same SQLite transaction as current-state erasure. A successful withdrawal preserves a structural marker, never a raw before-value. Complete raw-history replay becomes explicitly unavailable wherever a necessary payload was withdrawn. This is an intentional capability limit, not a successful replay of redacted evidence.

Root's [unchanged reproduction](A1-L04-journal-forgetting.md) at `b2efacd` passed ordinary forgetting and failed all three journal compositions after reopen: activation before ingestion, activation after ingestion, and expiry with descendants/self history. Pre-code checkpoint `25ad92a` and evidence `0582971` retain that result. No new execution is claimed here. The [43 accepted journal checks](A1-L09/development-journal-review.md) establish transaction/replay mechanics, not memory erasure. [DevelopmentalMemory](../../../packages/development/index.ts) already erases current memory content, affected self values/history and consolidation eligibility. The defect is the extra raw copies created by [OperationalStore](../../../packages/storage/index.ts), including its activation anchor.

Source inspection also covers the [memory contract](../../../packages/development/README.md), [acquisition design](A1-L08/development-acquisition-design.md), [complete inventory correction](A1-L08/development-retention-specification.md), and sibling recorder `49f2679` (`evaluations/development/acquire.ts`, read with `git show`). That recorder requires byte-identical prior event prefixes, complete before/after replay, and the full attempted raw-byte inventory. Merely changing memory documentation, filtering `events()`, or adding an audience map cannot reconcile these contracts.

| Option | Actual consequence | Disposition |
|---|---|---|
| Immutable references plus withdrawable journal values | Normal complete replay while values exist; transactional owned-content erasure; explicit loss of raw history afterward | **Choose.** Reuse the existing database, document storage, CAS, transactions and bounded capture. |
| Rewrite/redact old raw journal events | Can remove bytes, but changes prior event identities/prefixes and anchor binding; needs a second original/redacted-history protocol | Reject. More invasive than moving values out of immutable events. |
| Never journal developmental values; observer only captures current snapshots | Avoids this duplicate, but loses overwritten intermediate revisions even before forgetting | Insufficient for the accepted recorder requirement. Useful only for an explicitly incomplete observer. |
| Exempt journal/evaluator data from forgetting or forbid forgetting during observation | Preserves complete evidence by defeating existing memory behavior | Reject. Neither audience access nor observer attachment grants retention authority. |

No new dependency, encryption/key service, second database, generic privacy graph or semantic text-redaction engine is justified. The operational artifact table and QualificationStore are immutable content-addressed stores without ownership-aware withdrawal. Putting these payloads there and deleting by hash would couple unrelated owners with equal bytes; do not reuse them for mutable journal retention. Reuse ordinary document rows internally instead. This is a source-owned rewrite: replace the experimental journal wire format and its consumers together, without a dual-format compatibility reader.

## Ownership and authority boundary

The erased set is determined by declared provenance and exact owned document keys, not by searching all stores for matching text. It includes the forgotten memory closure, its journal versions, and affected adopted self/history/job versions. It does **not** silently acquire authority over separately attributed CommunicationsCore inputs, runtime observations, already emitted prompts/checkpoints, backups, another database, or independently retained qualification originals. Equal content is not equal ownership. The root regression deliberately isolates memory and derived self so these other owners cannot explain away its failures.

`DevelopmentalMemory` remains a trusted application service; its existing audience/result filtering is not an authorization API. The authenticated host must decide who may request forgetting before calling it. Journal withdrawal is a trusted store operation available to that same service, never a new model-selected namespace/delete tool. The journal's host/audience binding cannot override a valid memory forget request or extend expiry. Undeclared semantic copying remains outside mechanical provenance guarantees, as in the existing contract.

Success means the memory-owned current and journal payloads are logically absent on all supported operational reads after the transaction commits and after reopen. It does not mean forensic destruction of SQLite/WAL, zeroing already returned caller buffers, or erasure of separately owned copies. Keep that existing limitation; do not broaden it to exempt the new operational journal copies.

## Concrete store wire and APIs

Names below are the implementation contract to freeze before code; minor naming changes require coordinated consumer review. Existing public `put`, `delete`, `events`, constructor options and memory `forget`/`expire` call shapes can remain. Journal schema changes to `aeon.document-journal.v2`.

```ts
type JournalRef = {
  versionId: string; // host-generated unique ID, never a content-address
  namespace: string; key: string; revision: number; sha256: string;
};
type JournalPayload =
  | { ref: JournalRef; state: 'available'; document: Document }
  | { ref: JournalRef; state: 'withdrawn'; withdrawalId: string };

// Trusted API. Expected revisions are current document revisions, or null if absent.
withdrawDocumentJournalContent(input: {
  id: string; reason: 'forget' | 'expiry';
  targets: { namespace: string; key: string; expectedRevision: number | null }[];
}): { withdrawalId: string | null; withdrawnVersionIds: string[] };

// Existing bounded snapshot gains complete payload disposition, not hydrated events.
type DevelopmentSnapshotV2 = {
  documents: /* current application documents plus binding */ unknown[];
  events: StoredEvent[];
  journalBinding: /* immutable v2 binding or null */ unknown;
  journalPayloads: JournalPayload[];
};
```

1. Reserve internal payload/head namespaces beneath `system.document-journal`. Reject generic put/delete for the complete reserved set and generic append for anchor/mutation/withdrawal event types. Internal writes use private SQL helpers under the existing transaction, so they cannot journal themselves. Do not place raw values in head records or binding metadata. Generic application enumeration excludes these internal implementation rows; `captureDevelopmentSnapshot` explicitly inventories every payload/disposition and the structural events. Its contract must account for all internal rows read, not hide their resource cost.
2. Each successful anchored/new document version receives a fresh `versionId`. Store one payload record keyed by that ID and a head pointing from the exact namespace/key to its current ref. The commitment is SHA-256 of canonical `Document` bytes; it verifies integrity, not secrecy. No cross-document or cross-version byte deduplication. Delete/recreate may reuse revision 1 but must never reuse a version ID. Protected head metadata can retain the prior ref until the delete event commits; an absent document has no active head afterward.
3. The anchor stores the actual ordered application-document refs, not values. Activation bounds the existing ordinary rows and the prospective refs/payload/index overhead **before** materialization, then writes all payloads/heads, anchor and binding in one transaction. Exclude only the explicitly reserved journal internals from its application document set. An ordinary store activated after memory ingestion gets the same erasable payload inventory as activation before ingestion. No claim precedes the anchor sequence.
4. A mutation contains `{namespace,key,before: JournalRef|null,after: JournalRef|null}`. Use the existing head for `before`; check its namespace/key/revision and digest against the actual current Document. Create only the new `after` payload. A withdrawn `before` remains a withdrawn ref: never recreate it from the current row, an equal digest, a later version or an observer copy. Document CAS, head/payload changes and structural event append commit together. A failed CAS or append creates nothing; savepoint/outer rollback restores everything.
5. Withdrawal first validates all target current revisions, then changes **every already-created payload version for those exact keys** from available to a payload-free withdrawn record and appends one withdrawal event listing its exact refs/version IDs, request ID and fixed reason. This includes anchor values and both sides of all prior mutations. It does not alter old events, sequence numbers, digests or binding. Retain only metadata in withdrawn records. SHA digests/IDs/provenance are not a claim of inference-proof secrecy. No user-supplied reason string may carry forgotten content into the marker.
6. The withdrawal ID identifies an idempotent request: an identical retry returns the committed outcome; conflicting reuse rejects. No journal binding means a no-op result and no journal metadata, after ordinary target validation. The same-key withdrawal is a cutoff at this transaction, not a ban on all future use of a self facet ID. A later legitimate version gets a new ID; old references stay withdrawn forever. Memory tombstones still prevent reusing a forgotten memory ID.
7. A complete snapshot contains current application documents, the unchanged global event prefix, binding and every referenced payload's available/withdrawn disposition in one transaction. Events never hydrate raw values. Missing payloads without a matching durable withdrawal are corruption/unavailable, not inferred deletion. Validate withdrawal identity and ordering against the structural stream; do not accept a caller-forged `state: withdrawn`. Bounds include refs, all internal rows/bytes, withdrawal lists and materialized output before read; retain the existing 512-row/1,048,576-byte capture ceilings. An over-bound snapshot refuses without truncation. Payloads/tombstones can eventually exhaust that finite capture budget; this repair does not add compaction or hide history to postpone it.
8. Reopened and previously opened handles reread the durable v2 binding and respect withdrawals on every relevant transaction. No process-local retention cache. Changed/disabled binding and generic reserved writes still refuse. Old raw v1 bound stores fail with a specific unsupported-journal error; do not relabel them safe, automatically purge historical evidence or migrate them silently. Tiny synthetic databases are recreated in tests. Any real preexisting raw v1 state requires a separately authorized remediation/import task; this proposal does not destroy it.

The existing SQLite tables suffice; private helpers can use CAS updates to reserved document rows. Freeze exact reserved row schemas and canonical ordering in the implementation checkpoint. Do not add a new SQL table solely to make this proposal look like a separate store. Source edits must preserve ordinary unbound-store behavior and the actual descriptor-backed application/store association.

## Memory transaction and failure ordering

Within the existing `forget` transaction, compute the full memory descendant closure and collect affected keys **before** clearing fields/deleting rows. Collect `development.memories` keys; each current affected `development.self` key; each affected `development.self-history` key; and affected `development.jobs` keys. Critically, for every affected history entry also collect its corresponding **self facet key**, even when the currently adopted facet now cites unrelated sources. Otherwise its old journal version escapes deletion. Withdraw all historical payload versions of those selected keys. This deliberately sacrifices more journal history for that facet than the minimum revision subset; it does not erase an unrelated current self value. It avoids adding a second provenance index to storage.

Perform the current tombstone/self clearing/history deletion/job cancellation writes, then call withdrawal for the collected keys with their **post-write** revisions (null for deleted history). This ordering removes the raw `before` references and any transient versions created during the same forget transaction. It may also withdraw the newly written payload-free tombstone version; that is harmless and honest. Leave current tombstones and unaffected values intact. The transaction then commits and returns the existing audience-filtered forgotten IDs. `expire` uses the same internal path with reason `expiry`, preserving inherited deadlines and pre-sweep retrieval exclusion.

Withdrawal failure, marker INSERT failure, serialization failure, stale expected revision or SQLite failure rolls back the **whole** forgetting transaction; the caller must not receive success. A crash before commit leaves the original state; a crash after commit leaves current erasure and marker/dispositions together. On expiry failure, existing retrieval still excludes expired sources, but the sweep must surface failure and cannot claim completed erasure. No cross-database callback, observer acknowledgment or external store availability is on the operational forget commit path.

Historical job error strings and prior self reasons can contain memory-derived text; selecting complete affected owned document histories handles these without text parsing. Separately owned runtime/model records remain separately owned. Direct raw SQL tampering or arbitrarily malicious accepted host code is outside the trusted OperationalStore writer closure; verifier rejection is still required for malformed or missing refs/markers.

## Recorder and separately retained evidence

Update the recorder's replay contract, rather than catch all failures as “corrupt journal.” On capture, validate the complete immutable structural prefix/binding and owned ref graph. With all necessary values available, resolve refs, verify hashes/revisions and replay exactly to current documents, preserving every intermediate mutation/deletion. Captures retain exact bytes and the full attempted-byte inventory under the existing 512-record, 1,000,000-byte artifact and 8-MiB attempt limits; the store's larger capacity is not additional allowance.

With an authenticated withdrawal, retain the bounded structural snapshot and withdrawal metadata and record `document-history-withdrawn` with source binding, role, cursor and withdrawal IDs. Stop that active full-history acquisition with an **unavailable** disposition. Preserve earlier snapshots, physical requests, charges, rejected drafts and the consumed attempt/grant identity; no retry/reset or passing partial B. Do not fill gaps from current rows or old snapshots and call the new operational history complete. A missing ref without withdrawal is a separate `document-history-corrupt-or-missing` finding. Overflow remains the existing explicit capacity failure. These outcomes must be independently testable after recorder reopen.

An already returned capture is a copy. QualificationStore's write-once originals are owned by the evidence custodian; they are not a hidden operational memory cache. Keep that store immutable and its digest inventory complete. Before real private acquisition, the accepted host plan must separately bind authority for those copies: evidence custodian, exact source/attempt, purpose, audiences including providers/reviewers, permitted data scope, retention horizon and disposition on a withdrawal request. Authentication to read current memory alone is insufficient. A plan signature cannot invent that authority; the host must validate against an independently configured accepted grant.

For this bounded repair, the supported external path is **independent retention of original evidence under an explicit grant**, or synthetic fixtures. No implicit raw archival grant is inferred. A finite retention horizon needs enforced access/retirement controls; the current QualificationStore alone has none. Therefore plans requiring deletion-on-memory-forget, revocable raw retention, or timed destruction remain unavailable until a separate concrete custodian lifecycle is implemented and reviewed. Do not accept such a plan with a prose promise. This repair neither adds a generic evidence deletion service nor authorizes indefinite private retention by default.

Distinguish the two operations:

| Operation | Operational result | Qualification/evidence result |
|---|---|---|
| Forget/expire memory-owned records | Atomic current and journal-payload erasure; durable withdrawal marker | Active capture needing those raw values becomes unavailable. Existing independently authorized external originals are unchanged. |
| Withdraw an attempt's use as evidence | No automatic mutation of the operational memory store | Append a host-authenticated unavailable/withdrawn disposition to the attempt claim record; preserve original B/T/envelope and inventory. All future attempt-use/reader entrypoints must consult that terminal disposition. No re-signing a reduced inventory as complete. |
| Request destruction of independently retained originals | Outside the memory API's authority/result | Current write-once store cannot claim success. Route to its separately authorized custodian; until an implemented lifecycle completes, report retained/pending and exclude the affected attempt from qualification. |

The recorder task implements the second row as a narrow durable terminal transition (for example `withdrawAttemptUse(reasonCode)` callable only by the trusted host), with idempotent reopening and fail-closed readers/verification through the recorder. Bind its authenticated marker to the exact attempt/plan, prior B/envelope digest when present and accepted custodian identity. Reserve a fixed bounded terminal-disposition slot in the existing plan metadata allowance before acquisition; exhaustion cannot silently prevent revocation or mint a fresh allowance. CAS-update recorder claim state and retain the authenticated marker there without rewriting B/T or unlinking raw hash files. No model request is needed. A historical independently authorized report is not automatically rewritten when later operational forgetting occurs; any assertion of current erasure needs current evidence. An externally exported envelope cannot be recalled by this API. Downstream admission/H1 use must receive the current custodian disposition, not trust a stale exported pass. Existing automatic release/H1 eligibility remains false.

### A future observation window on continuing state

Withdrawal ends this full-history attempt, not the possibility of later developmental qualification. JR1/JR2 alone deliberately cannot qualify a fresh attempt from the original now-incomplete anchor. A separately assigned **JR5 checkpoint boundary** is the narrow follow-up; it is not permission to retry the failed attempt or reset lived state.

JR5 would add a host-only `checkpointDocumentJournal({ id, expectedLastSequence, maxDocuments, maxBytes })` transaction. Under accepted observer authority, quiesce writes, verify the existing binding/full structural prefix, CAS the expected last sequence, and append a bounded `document-journal-checkpoint` containing refs for the actual current application documents. Create fresh payload IDs and update heads for those current versions in that transaction; retain old refs as withdrawn, every old event, and the immutable original binding. This new copy of a surviving current value must never reconstruct an erased historical value. Tombstoned memories stay tombstoned; current unrelated self/history rows and all operational tasks/resources remain current. No model tool exposes this operation.

A **new independently accepted plan and one-use attempt/grant** pins that checkpoint's ID, sequence and digest as its explicit history start, with an independently authorized resource grant rather than replenishing the consumed old one. Its recorder still retains/checks the full old structural prefix and failed-attempt provenance; it claims complete values only from the named checkpoint forward. Preregister every new opportunity, begin the three real W intervals after that boundary, and acquire all required transfer/feedback evidence anew. An unchanged old plan or candidate-selected start cursor cannot use this path. A later required withdrawal ends the new attempt too. Checkpoint creation, plan acceptance and current-byte retention each need their own existing host authority; none implies product acceptance.

Before implementation, JR5 must freeze its exact wire and prove that the old attempt remains unavailable, a fresh bounded synthetic window can replay continuing current state, an unaccepted/candidate-selected checkpoint is rejected, old evidence remains retained, and resource/lived-state rollback never occurs. Existing snapshot/attempt bounds still apply; if accumulated metadata no longer fits, report that separate capacity limitation instead of pruning old history. This follow-up is intentionally outside the minimal repair claim, explicitly preventing a temporary missing API from becoming a permanent ban on qualification after legitimate forgetting.

## Causal acceptance, not a documentation exception

- Import root's four `b2efacd` regression cases **byte-for-byte** into the repair validation tree: ordinary control remains passing; journal-before, late-anchor and expiry become passing without changing their event/snapshot/reopen assertions. Preserve original red checkpoint/evidence. The original tests need no v2-specific waiver.
- Prove available history still reconstructs intermediate revisions, deletion and recreation. Reuse the existing 43 journal/storage test predicates; adapt only their new wire construction/ref resolution, recording the diff. Binding mutation, incomplete global prefixes, reordered versions, failed CAS and tampering must still fail.
- Erase both source and derived payloads plus self value/reason/history, including an old self revision now superseded by a facet with unrelated evidence. Its current unrelated value remains usable, but selected old journal refs remain withdrawn. Exercise job error history and repeated forget/expiry.
- Equal canonical bytes in another owned key, another namespace and another document incarnation do not share payload identity. Withdrawal of one key leaves the other key's available payload untouched; a future legitimate same-key version never rehydrates an old ref. Forgotten memory IDs still cannot be reused.
- Force withdrawal-event INSERT failure and payload-update failure with actual SQLite triggers; force outer rollback and caught savepoint rollback. Neither partial erasure nor a successful return survives. Reopen at committed/uncommitted boundaries, and use handles opened before activation and before withdrawal. Validate stale expected revisions and conflicting idempotency IDs.
- Activate after existing memory/self writes: the anchor contains refs and all corresponding payloads are erasable without recursion. Generic reserved writes/appends reject. Preallocation bounds include new indexes/refs/markers; a deliberately tiny cap refuses before materializing excessive payloads. Ordinary unbound behavior stays unchanged.
- Capture before and after real withdrawal using the recorder: structural prefix bytes stay identical; withdrawn content disappears from the new operational snapshot; the recorder reports history-withdrawn unavailable, retains prior authorized raw copies/inventory/charges and cannot resume under a new grant. Missing payload without marker must instead report corruption/missing evidence. Neither outcome is a partial-history pass.
- External attempt-use withdrawal prevents later reader/freeze/close/verification use after reopen while preserving immutable original bytes and denial/disposition evidence. Synthetic fixtures pass the supported retention preflight; absent authority, incompatible revocable retention and an expired/unenforced finite-horizon grant refuse **before** private capture or dispatch. Equal digest artifacts owned by unrelated evidence remain unchanged.
