## What the joined case adds

The earlier `shell-joined.test.ts` crash case used a simulated inspection. `packages/tools/test/tools.test.ts` did actual coding tools but reopened after completion. `provider-portability.test.ts` reopened storage gracefully and used simulated effects. `service-process.test.ts` killed the real service but did not run the coding task. These remain useful separate evidence; none alone establishes the last T05 clause.

The new fixture runs an actual confined selected Pi worker through `createBrokerShell`, `ToolEffectReceiver`, `EffectJournal`, `ResourceLedger` and `DurableRuntime`. Deterministic Mistral-format responses choose actions from inspected results; no network provider is invoked. It reads `sum.mjs`, writes a seeded subtraction defect using the observed digest, runs a real Node assertion that fails, and repairs by CAS patch. Immediately after that real mutation succeeds but before the receiver returns its receipt, the parent sends SIGKILL to the host and waits for the signal exit.

SQLite reopen marks the original repair and its physical request uncertain. The task cannot resume. The local receiver's ordinary reconciliation reports unresolved. A new authority explicitly inspects the actual file through `WorkspaceTools.read` and records an attributed repair receipt; the original effect grant and physical request remain unchanged. A fresh host/worker reconstructs the pending assistant tool result from that receipt, begins its next model request, and is killed before its response. A third authority resumes the original checkpoint, issues a new accounted reasoning request, runs the actual verification command, and finishes the same run. It never redispatches the uncertain repair or reuses/settles the unknown provider request. Continuing cognition is a distinct charged attempt, not a free retry or an invented result of the interrupted attempt.

Observed result: **five unique tool effects**, **seven model attempts**, **12 total durable requests**, **one retained unknown provider request**, one real failed command observation, final `verified 5`, and epochs **1 → 3 → 5**. Duplicate input still resolves to one run. All fixture workspaces/state are removed. Test cleanup kills any remaining host process group before granting the successor; this fixture does not independently certify automatic descendant cleanup, which has its own physical cases above.
