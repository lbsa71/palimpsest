The smallest proposed capability is **explicit continuation of a quiescent native session after host interruption**, under the same original observer grant, ledger, deadline and workspace. It does not recover a dispatched unknown request, rewind effects, resume active children, or establish context reduction. No binary, account, credential, native/physical check or code change was performed for this design.

## Source facts and acquisition gates

At the base revision, `evaluations/baselines/codex-worker.mjs` uses `--ephemeral` and `/tmp/aeon-baseline-home`; Claude's invocation uses `--no-session-persistence` and the same temporary home. Confinement creates a fresh 64 MiB `/tmp`. `run-native.ts` refuses every attempted `baseline-run`, including successful runs, and unconditionally cancels the allocation in `finally`. Durable ledger evidence already exists, but durable native continuation does not.

`BaselineObserver` reopens the identical frozen grant without allocating again. Any reserved/dispatched/uncertain request prevents continuation; dispatched requests become uncertain, reservations remain held, and cancellation is permanent. `ResourceLedger` retains original `startedAt`, counts elapsed wall time across restart, and refuses duplicate allocation. These controls remain unchanged. `ProcessLease` holds a real exclusive SQLite transaction; losing its lock alone does not prove native descendants have exited. Existing namespace/cgroup cleanup must provide that separate observation.

Reuse the products' own session stores and resume commands. The [Codex 0.162.1 tagged CLI source](https://raw.githubusercontent.com/openai/codex/rust-v0.162.1/codex-rs/exec/src/cli.rs) describes explicit UUID resume and optional stdin continuation. Its [tagged execution source](https://raw.githubusercontent.com/openai/codex/rust-v0.162.1/codex-rs/exec/src/lib.rs) uses the existing app-server `ThreadResume` API; an unresolved latest/name selection instead starts a thread. Consequently this design accepts a canonical UUID only, never a name, picker or `--last`. Tagged source is first-party source evidence, not proof of installed-binary behavior or event ordering.

Retained Claude 2.1.296 help supports `--session-id <uuid>`, `--resume [value]`, and explicitly describes `--no-session-persistence` as disabling persistence. Current [Claude session documentation](https://code.claude.com/docs/en/sessions) describes JSONL transcripts under the configuration directory's projects tree and explicit-ID continuation. It warns that the storage format is internal. The actual pinned files, auxiliary state, flush behavior, resume startup events and effective instructions remain acquisition prerequisites. Do not infer those bytes from current documentation, edit transcripts, or supply a fabricated transcript.

## Checkpoint and authority contract

Persistence is an opt-in synthetic engineering mode declared before the first original request. Existing ordinary runs keep their replay refusal and cancellation. Previously attempted delegation runs are never made recoverable retroactively. No new grant, allocation, price model, context estimator or protocol ceiling is introduced.

1. Start with an empty native-state subtree in an isolated workload workspace. The existing `/work` mount survives launch generations; private observer/lease/control state stays outside the namespace. No personal home, native account, provider credential, session from another run or ambient configuration is imported. Authentication identity is exclusively the retained dummy bridge token plus explicit fixture transport; session bytes confer no provider authority.
2. Execute a complete native parent turn. Before checkpoint eligibility, require successful native exit, all tool completions observed, zero pending worker RPCs, zero active children, zero reserved/dispatched/uncertain requests, an uncancelled allocation, and successful namespace/resource cleanup. Preserve actual workspace effects. A model's assertion of completion is insufficient.
3. Under the exclusive lease, seal the actual native state and checkpoint in host-private storage. Record exact session ID, original grant and run ID, ledger/request revisions and charges, original start/deadline, launch generation, predecessor exit/cleanup receipts, workspace manifest, configuration/argv/environment identities, source/native/runtime/kernel manifests, and full native instruction/request/tool-result artifacts. Store directory names and each regular file's bytes/hash/mode; reject links, special files, hardlinks, foreign ownership and paths escaping the subtree. Proposed local checkpoint bound: 256 files and 16 MiB total, within the original workspace storage allowance; exceeding it is unavailable, not truncation or an increased grant.
4. Publish a revisioned `ready` checkpoint only after those observations and durable artifacts commit. The checkpoint path in `run-native.ts` must bypass ordinary cancellation only for this proved quiescent state; failure or interruption before eligibility still cancels normally. Close state and release the lease after cleanup. The positive fixture interrupts the host after readiness, not an active provider request.
5. A new host acquires the same lease and explicitly supplies the expected checkpoint ID/generation. Verify the immutable manifest and ledger, elapsed time, remaining request/token/cost limits, predecessor absence, and workspace/native bytes before launch. Restore only the sealed native subtree if needed; do not restore workspace effects or overwrite observed later edits. A changed workspace causes refusal. Atomically consume `ready -> running` before launch and retain the new generation; duplicate/concurrent consumers lose. Never reset a consumed checkpoint after crash. A further continuation requires a newly observed quiescent checkpoint.
6. Gate the first resumed provider request on the actual matching native startup session event, checked locally by the worker's bounded existing stdout parser. Preserve raw events. After completion, close normally or create another explicitly planned checkpoint within the same original allowance. A mismatch, missing history, unknown outcome, child activity, cancellation or expired deadline stops dispatch and drains descendants. Charges retain actual known/unknown settlement; no synthetic cancellation zeroing or grant replacement.

Same-run immutable identity includes binary/helper hashes, Node, full baseline/package source manifest, host tool hashes, native model/effort/thinking/tool definitions/beta profile, namespace/kernel/resource profile, `/work` cwd, dummy authentication mode and original grant. A new bridge's loopback port and launch/lease generation are the only declared per-launch differences, with both actual invocations retained. Checkpoint storage is mutable native data, never executable configuration authority. Reestablish the original explicit configuration on resume and retain all actual startup sources. If native recovery reloads or changes instructions, record the complete difference and stop claims until it is understood.

Claude's current isolated delegation profile retains built-in agents/plugins and adaptive thinking/high effort. Keep it, empty setting sources, strict empty MCP, disabled slash commands, fixed native model roles and the synthetic-only protocol guard. The blank-workspace preflight may gain only a typed checkpoint-resume exception after exact verification; it must not admit arbitrary nonempty workspaces. Keep full native hand-back wrappers as instruction/provenance sources. Delegation review found a fixture-only Codex command-success assertion repair; implementation starts only after root joins that review, with a newly frozen source manifest.

Active child recovery is outside this first path. A checkpoint must not be published while any actual child/request is unresolved. Cancellation aborts active siblings and retains all charges. Native child session files may be preserved as opaque checkpoint provenance; their existence does not qualify resumable child execution. Tool side effects are not reissued or rewound. Native transcript persistence is neither an effect journal nor proof that an unobserved command did not run.

## Context reduction remains separate

The required recovery/context workload also needs real context reduction. This specification closes only the durable-continuation design. Current [Claude context documentation](https://code.claude.com/docs/en/context-window) describes compaction and reloaded startup instruction sources; pinned help advertises `--autocompact auto|100k–1M`. Neither establishes a bounded small headless compaction path under the selected isolated flags. Codex headless compaction route/schema is unacquired. Dropping old messages, replaying a fresh prompt, manufacturing a summary or lowering the reservation does not meet the requirement.

Keep this qualification gate unavailable until a separate fixed synthetic acquisition can trigger the pinned native reduction surface under an original full-context allowance, retain its request/response and before/after history, account for every compaction request, and observe retained facts plus all newly loaded instructions. Do not enable a new endpoint, beta, wildcard protocol, cognition reduction or larger fixture in this implementation. An acquired unsupported compaction surface must retain its exact refusal and receive separate disposition.

## Fixed synthetic physical plan, not launch authorization

After pure checks and fresh source review, default maximum is **one acquisition, one positive and one negative per product**, serialized by root. Freeze each exact source, argv/config, public replies, sentinels, assertion helper and original envelope before launch. Acquisition failure blocks the positive; no fallback, retry, fourth experiment or enlarged grant is implied. Every experiment has a fresh declared original grant before its first dispatch, never a grant reset. Its predecessor and resumed launch share that one grant and clock.

| Original per-experiment limits | Codex | Claude |
|---|---|---|
| Requests / concurrency / total wall time | 8 / 4 / 60,000 ms | 8 / 4 / 60,000 ms |
| Full input context / output ceiling | 200,000 / 4,096 tokens | 1,000,000 / 4,096 tokens |
| Original total token / synthetic cost cap | 1,632,768 / $100 | 8,032,768 / $100 |
| Request timeout; request/response/CLI bytes | 10,000 ms; 1,000,000 each | 10,000 ms; 1,000,000 each |

Retain the existing native profiles/prices and declare concrete namespace or kernel/storage limits in each frozen source plan. Synthetic cost is accounting only; no account/key inspection, paid inference or external network is admitted.

- **Acquisition:** capture pinned help and one bounded two-phase native session under the original allowance: first phase performs one actual local write and completes; second explicitly resumes that ID and performs an actual read. Predeclare at most two provider requests per phase. Capture all native files, startup identity timing, before/after instructions, actual tool-call attribution and response bytes. Unsupported routes/headers/new format stop the attempt. This identifies mechanics; it is not the interruption proof.
- **Positive:** use the acquired exact surface. First phase records an unpredictable public fixture marker via an actual successful tool result and native session history. Publish readiness, prove native descendants drained, terminate the host at that boundary, and use a distinct host process to resume. The follow-up prompt must omit the marker, prior tool output and earlier task text. Require identical native session identity, the prior actual tool-result/history in the resumed native request or an acquired opaque continuity witness, a new native read of the existing artifact, and a known final completion. Source hashes and original ledger/clock must remain continuous; fresh-thread execution fails regardless of final answer. Maximum two requests per phase; no extra request to repair an assertion.
- **Negative:** create an actual interrupted dispatched provider request with a retained reservation, then explicitly request continuation from the same state. Require no new native launch/provider dispatch, original uncertain charge held and allocation cancelled, no ready checkpoint, and all descendants drained. Maximum two original requests before interruption. A fresh grant cannot satisfy this negative. Pure cases additionally cover corruption, stale ownership, altered configuration and replay without multiplying physical experiments.

Use public synthetic replies and isolated temporary workload roots only. Preserve first failures and raw requests before and after accounting, headers, responses, CLI events, complete native stores/instructions, tool result IDs/exits, checkpoint/lease revisions, cleanup receipts and original ledger snapshots. Actual native files/history and host interruption distinguish this proof from a bridge-only fixture. A refusal or fixture defect is retained as an engineering failure, not a product competence score. Document each case's bounded result and unavailable gates; fresh review is required before integration.
