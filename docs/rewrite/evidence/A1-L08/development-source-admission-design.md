## Decision and existing boundaries

Keep the existing paged projector unsigned. Add small deterministic derivation/verification helpers and explicit recorder methods that consume selectors and retained references, reconstruct evidence through the actual recorder, retain proofs, and call its private signer. Do not export `observe`, accept caller-built `DevelopmentObservation`, pass an observation-signing callback, or make proof retention a certification operation. External workload/checker qualification remains a separately accepted host input. The recorder can verify attribution and exact bindings; it cannot infer that a newly supplied checker is competent.

| Observed contract | Consequence |

| `DevelopmentSourceProjection.kind = 'proposed-source-facts'`; current paged projection verifies actual reader manifests, intermediate versions, consumed input/result ancestry and physical requests | Recompute this projection inside admission. Accept no cached projection as authority, even if previously retained. |
| Cycle origin is only `request` or `unknown`; selections have sequences but no event timestamps | Preserve origin. A goal's self label or lack of a found request cannot establish spontaneity. Bracket actual new selections; never date them with the admission call's clock. |

No standalone library supplies these exact source/journal/original-grant semantics. Reuse the source-owned Pi application, recorder, complete-page readers, canonical hashing/signatures, document journal, current-use fences and DC1 script algorithm. Build only the application-specific derivation and admission functions below. A second scheduler, checker framework, signing service, event bus or dependency is unjustified. Private checker execution is not implemented by this task or supplied by adopting another agent shell.

## Preclaim input and checker authority

The concrete protocol schedule names phases and ordinals but does not fully identify which learning/interference/feedback delivery belongs to each opportunity, nor define task output extraction or scoring. That information must be frozen before claim. Do not infer it from convenient ID strings, output prose or the order in which results arrived.

Add a **host-only**, detached `sourceAdmission` option at recorder claim/reopen, distinct from the candidate options and driver selectors. Its exact descriptor is retained once in a preallocated `adaptation` slot. Store its digest in recorder owner state and require the same accepted digest on reopen. A absent descriptor permits the existing recorder operations but makes all new semantic admissions unavailable. It never permits filling missing metadata from defaults. Newly enabled admission requires a new unclaimed plan/closure and external acceptance; an already claimed attempt cannot acquire this authority later.

```ts
interface SourceAdmissionPolicy {
  version: 1;
  planDigest: string;
  workload: ArtifactRef | null;       // exact public matching/mapping contract
  checkerId: string | null;
  checkerSourceDigest: string | null;
  extractorSourceDigest: string | null;
  rubricDigest: string | null;
  qualification: ArtifactRef | null;  // approved nonsecret qualification certificate
  clockQualification: ArtifactRef | null;
  bounds: {
    maxMetadataRecords: number; maxMetadataBytes: number;
    maxProofBytes: number; maxCheckerBytes: number;
  };
  adaptationOrdinals: { policy: number; workload: number | null; qualification: number | null;
    clockQualification: number | null;
    learningChecks: { opportunityId: string; ordinal: number }[];
    scriptChecks: { controlId: string; assignmentId: string; ordinal: number }[] };
}
interface SourceAdmissionTrust {
  acceptedPolicyDigest: string;
  acceptedQualificationDigest: string | null;
  checker: { id: string; key: Uint8Array; principalId: string;
    independenceGroup: string } | null;
  acceptedClockQualificationDigest: string | null;
}
// Proposed additions to AcquisitionRecorderOptions, not a public signer:
// sourceAdmission?: { policy: SourceAdmissionPolicy; trust: SourceAdmissionTrust }
```

The trusted host selects these accepted digests and principal/key identity under the existing prior policy, outside candidate control. Qualification must cover the exact checker/extractor/rubric, workload family, disclosure/matching predicates and authorized execution mode; identity in a JSON field is not qualification. The checker principal/group must be excluded from candidate/author control under that policy. Reusing the two final reviewers does not automatically satisfy fresh-context or independence requirements. Private answer keys and unrestricted qualification material remain in a separate host-qualified private custodian, **outside the recorder's generic reviewer-readable inventory**. The qualification artifact admitted here is only an explicitly approved nonsecret certificate binding exact checker/extractor/rubric/workload digests and the external acceptance disposition. It contains no traversable private artifact references, secret bytes or private paths. The host's independently accepted certificate digest is required; a newly signed author certificate is insufficient. The public workload is the only part admitted as task input. Absent independently established qualification yields unavailable semantic admission, rather than importing private originals through a generic evidence-read tool.

Mechanical-only policy is explicit: workload/checker/extractor/rubric/qualification fields and their corresponding trust/slot entries may all be null. `inspectAssignment` and `recordCycle` then work from accepted source/manifest/clock evidence without requiring a semantic checker. Synthetic mechanical fixtures need no live clock qualification; live temporal eligibility still requires the separately accepted clock certificate, immutable actual bracket sources and inequalities below. Lack of semantic qualification cannot manufacture autonomy, but it also does not prevent recording correctly labeled mechanical cycle facts. Workload-dependent experience/learning/opportunity/control methods remain unavailable until their specific mapping/qualification prerequisites exist. A policy cannot be upgraded after claim; use a new unclaimed attempt if subsequent semantic acquisition requires more authority or capacity.

Hash order is acyclic: first freeze public packet and workload mapping (which contains schedule/assignment digests, but no planDigest/policyDigest or configuration hash); construct role configuration with that workload hash; seal the plan and its executable acquisition closure; then construct policy with the already fixed planDigest and obtain external acceptedPolicyDigest before claim. The executable closure hashes verifier code, not this attempt's eventual policy bytes. Qualification/clock certificates commit underlying executable/workload/sensor identities and external dispositions, not the enclosing policy hash. The policy is retained as reserved evidence and pinned in owner state, **not retroactively inserted into the signed plan**. Plan capacity already reserves its bounded storage and metadata before signing. A changed accepted policy cannot reuse an old claim, even if all byte counts happen to fit.

The public workload contract is a bounded, canonical v1 object containing `scheduleDigest = identity(plan.protocol.schedule)`, `assignmentDigest`, and ordered `opportunities` and `scripts` arrays. An opportunity entry contains `{id, family, roles}`; each role entry contains `{roleId, assignmentId, learningAssignmentId: string|null, interferenceAssignmentIds: string[], feedbackAssignmentId}`. A script entry contains `{controlId, roleId, cases: {assignmentId, feedbackAssignmentId}[]}`. It also contains the public extraction/rubric identifiers and the allowed mediator/workspace matching specification. The policy pins actual executable/rubric digests independently. Validate exact keys, bounded unique IDs, manifest family/control membership, complete schedule coverage and exact role-local packet entries. Require the workload artifact digest to equal every behavioral role's accepted `developmentControl.workloadDigest`. This uses the existing matching commitment; it does not put private answers in application configuration.

Every field, maximum and artifact slot must be validated in the same preclaim calculation as P2's reservations. Retaining four policy artifacts does not create extra slots: use distinct declared entries from the existing 54 optional slots. Missing optional headroom means infeasible. Reference equality can reduce actual stored bytes, never the preclaim reserve. Admission descriptors, policy digest state and extra raw proof references must be included in actual escaped canonical owner/B/final copy sizes. No plan, witness cap or original grant is changed by this design.

Concrete pool placement is mandatory: policy, public workload and approved nonsecret certificates consume their declared `adaptation` proof slots/bytes, **not** `sourcePool` slots. The existing source pool remains dedicated to its already planned candidate/configuration/closure/packet material; no duplicate policy material is added there. The full semantic profile reserves up to four policy objects plus twelve receipt-import objects; mechanical-only policy reserves its policy object and, for live time, its public clock certificate. Preclaim charges each at its validated artifact ceiling and includes duplicate embedded receipt copies in mandatory q bounds. No semantic checker is needed to calculate or reserve mechanical-only capacity.

Bounds are positive safe integers; `maxProofBytes` and `maxCheckerBytes` cannot exceed the plan's mandatory proof byte ceiling, and all source/artifact reads remain under their existing recorder bounds. Metadata bounds are explicit preaccepted limits passed unchanged to the paged projector, with their serialized index/owner costs included before claim. Array/count bounds come from the validated concrete schedule, fixed proof counts and 54-slot maximum; reject duplicate or out-of-range ordinals and unaccounted judgment support. These checks do not establish a measured JavaScript heap or full-profile performance qualification.

The checker returns a domain-specific signed record, supplied to admission by retained reference. It does not receive the observer key or a signing callback:

```ts
// Domain: aeon.development.source-check.v1
interface DevelopmentSourceCheck {
  version: 1; planDigest: string; policyDigest: string;
  roleId: string; opportunityId: string; assignmentIds: string[];
  sourceDigest: string;                // identity of recorder-derived unsigned evidence
  checkerSourceDigest: string; extractorSourceDigest: string; rubricDigest: string;
  output: ArtifactRef; feedback: ArtifactRef;
  acquisition: 'completed' | 'failed' | 'unavailable';
  behavior: 'pass' | 'fail' | 'unavailable';
  disclosure: 'preserved' | 'violated' | 'unavailable';
  matching: 'valid' | 'invalid' | 'unavailable';
  judgments: ArtifactRef[];            // bounded exact retained supporting evidence
  checkedAt: string;
}
```

Use existing domain authentication with only the pinned checker key; exact-field validation rejects extras and detached canonical copies prevent alias/getter substitution. The record's subject is an opportunity or a preregistered script case; its ID must match that concrete workload entry. `sourceDigest` commits the complete derived selection of input/result/event/version/request/output/feedback evidence and capture intervals, without the checker record itself (no hash cycle). IDs alone are insufficient. Require the record's output/feedback refs to equal those extracted from that source. Supporting judgment references must resolve through retained inventory and fit their assigned slots; no direct arbitrary filename or network reads.

The checker cannot declare missing runtime work acquired: recorder derivation independently verifies all required assignment consumption, terminated execution, output and feedback inventory. A positive acquisition label inconsistent with those facts is failed admission. A qualified checker may judge a complete task behaviorally wrong. It may also return unavailable. Preserve all three dimensions, including inconvenient ablation successes. `matching` is evidence for final reviewer validity, not a replacement for `DevelopmentReview.controls[].outcome`.

For this bounded implementation the recorder **imports and authenticates receipts; it does not execute a checker**. Any later physical checker/model/tool execution needs an explicit accounted role/path in the same original envelope before dispatch. A model checker cannot be an unaccounted callback. A locally supplied deterministic fixture receipt is synthetic evidence only, even when a fixture trust key accepts it. External authorization, competence qualification, private held-out workload and actual checker execution/accounting remain explicit **Aeon 1 implementation and acceptance work**, not an Aeon 2 deferral. Root must separately claim the finite checker execution/bridge integration task before real semantic acquisition; otherwise that acquisition remains unavailable.

## Small helper and recorder APIs

These are proposed signatures for root adoption, not descriptions of currently callable methods. `CaptureBracket` contains only retained refs and a role. Recorder supplies configuration, path/journal identity, assignment packet, bounds and reader methods from its accepted plan/state; callers cannot override them.

```ts
interface CaptureBracket { roleId: string; before: ArtifactRef; after: ArtifactRef }
interface AssignmentSelector extends CaptureBracket { assignmentId: string }
type Admission =
  | { status: 'recorded'; proof: ArtifactRef; observationId: string | null }
  | { status: 'failed' | 'unavailable'; code: string };
interface OpportunitySelector extends AssignmentSelector {
  opportunityId: string;
  related: AssignmentSelector[]; // exact mapped learning/interference/feedback brackets
}
interface ScriptCaseSelector {
  assignment: AssignmentSelector; feedback: AssignmentSelector;
}
interface CheckInput { sourceDigest: string; evidence: Uint8Array }

// Methods on the actual DevelopmentAcquisitionRecorder:
inspectAssignment(input: AssignmentSelector): DevelopmentAssignmentSource;
inspectLearning(input: AssignmentSelector & { opportunityId: string }): CheckInput;
inspectOpportunity(input: OpportunitySelector): CheckInput;
inspectControlCase(input: { controlId: string; case: ScriptCaseSelector }): CheckInput;
recordCycle(input: CaptureBracket & { cycleId: string; selectionId: string }): Admission;
recordExperience(input: AssignmentSelector & { interferenceId: string }): Admission;
recordLearning(input: AssignmentSelector & { opportunityId: string;
  checker: ArtifactRef }): Admission;
recordOpportunity(input: OpportunitySelector & { checker: ArtifactRef }): Admission;
recordControl(input: { controlId: string;
  scriptCases: (ScriptCaseSelector & { checker: ArtifactRef })[] }): Admission;
```

`inspectAssignment` returns detached unsigned metadata, with the same current-use final check as projection. It accepts no purported result/run/provenance. It is not separately persisted into a 127th assignment-proof stream. Each recording method recomputes the relevant assignment through the actual paged projector and embeds its bounded proof in the method's existing typed proof slot. `recordControl` gathers admitted ablation source proofs/receipts from owner state; ablations require an empty `scriptCases` list. Scripts require the exact preregistered complete case list and authenticated checker references. Its selectors supply only capture/input identities, never asserted executions, mode seal, valid/completed flags or arbitrary checker bytes.

The three check-input methods return fresh detached bounded canonical bytes and their digest for an authorized external checker. They use the same derivation as recording, excluding checker receipts, and confer no attestation. They perform final current-use checks before release; no private key/reader/Store is exposed. `recordOpportunity` operates for candidate and both ablation roles, storing all 36 task-output/feedback/checker bundles and an owner index. Only the candidate emits the opportunity observation; ablation admissions return `observationId:null` and supply DC2. Its `related` selectors must be the exact workload-mapped delivery set with matching role and honest individual brackets, not a caller-selected favorable subset. These facts also retain ablation learning/interference exposures without consuming the candidate's 3 learning/9 experience slots. Script case derivation uses the same receipt binding rule inside DC2 and its existing script/control slots.

Pure helper functions in new `development-source-admission.ts` validate the policy/workload/receipt and construct unsigned canonical `CycleProof`, `ExperienceProof`, `LearningProof`, `OpportunityProof`. They accept detached facts and bounded source readers provided by the recorder, never the observer key. They may be tested with arbitrary fixtures precisely because their return values confer no authority. New `development-control-proof.ts` derives the unsigned control proof from the same facts/readers plus exact accepted control mode and physical accounting transitions. Helpers must not take live Store objects, fetch external artifacts, mutate source or call runtime methods. Bounded reader callbacks are data access, not certification callbacks.

Each unsigned proof has exact common fields `{version:1, kind, planDigest, policyDigest, roleId, subjectId, captures, interval, source, checks}`. `captures` are exact manifest references; `source` contains the relevant assignment/cycle projector facts and additional concrete journal refs/event positions described below. `checks` is a list of retained authenticated receipt refs or an empty list for mechanical evidence. Role configuration is retained in source. `interval` is the lower/upper bracket of the actual represented event, never a checker/admission completion interval. Kind-specific output/feedback/episode/mode/execution fields are validated by the corresponding helper, without a generic extensible claim bag. The task author freezes the exact TypeScript discriminated union and serializer before source edits; it must contain only these sourced facts and preserve the existing observer representation.

Recorder-private commit procedure:

1. Detach selectors; require acquiring phase, known role/subject, exact current original grant/window, accepted policy identity and all-role current-use authority. Reject source/owner transactions incompatible with existing guard ownership. Use the actual already attached application/store/bridge associations; retain no new structural service object from a caller.
2. Open `before`/`after` from the recorder capture index. Select `current` as the latest retained capture for that role, and require prefix continuity to it. Actual current source withdrawal/custodian checks still run even if no newer capture exists. Use `openAcquiredCapture` and the paged projector, retaining exact intermediate refs; do not revive full-snapshot hydration or scan an operational Store for semantic content.
3. Reconstruct/validate all facts, independently resolve every referenced retained byte, validate applicable checker receipts and temporal rules, and compute exact bounded raw/owner/observation sizes before durable mutation. External receipt availability cannot skip source rechecks.
4. Derive the proof kind/ordinal from the preregistered canonical mapping, retain exact proof bytes, then append its observation and admission index entry in one recorder-owner transaction. Store observation identity, proof digest, interval and subject uniqueness there. If raw retention succeeds but commit fails, preserve the raw/pending/terminal state using existing failure machinery; never silently reissue a different proof, regain slots or claim cross-database atomicity.
5. Recheck all-role current use immediately before append and before releasing any proof/observation/result. No await or checker execution occurs while the existing source/custodian fences are held. If a caller performs an asynchronous external check between calls, rerun derivation and require identical sourceDigest on return. Withdrawal in any role denies release, even for a cached proof from another role. Final B publication repeats existing historical/current-use checks. A denial retains the established terminal attempt-use disposition, not usable cached semantic output.

Choose deterministic observation IDs `source:<kind>:<roleId>:<subjectId>` within the witness's 256-character ID limit; validate encoded length before claim/admission. Replay of an already recorded identical selector/proof returns the detached existing admission only after current-use checks. Changed bytes, checker ref or subject binding under that identity fail; no duplicate observation is emitted. Malformed/fabricated evidence yields a retained bounded failed finding; absent qualification/source, unsupported semantics or insufficient capacity yields unavailable. Existing terminal capacity/current-use errors retain their established behavior. Admission failure never emits a positive replacement observation.

Private `observe` gains only an optional bounded `proof: ArtifactRef` field in its **raw** wrapper and an internal call-site parameter; all old request/start/end callers remain unchanged. Existing signed data and outer configuration rules stay intact. If a proof is required, its existence, inventory membership and exact digest are checked before signing. Final raw/B artifact inventory retains the proof and referenced bytes for independent replay; nested refs are not assumed to be automatically checked by the witness. Explicit inventory/source validation is the recorder's responsibility.

For learning, opportunity and control, a checker `checkedAt` must be a valid timestamp within the behavioral acquisition window, no earlier than the complete source evidence supplied to it and no later than recorder host time. ### Honest time, including transfer

Let each sourced event interval be `[L,U]`, derived from two existing capture clocks around **new event sequences**. Both clocks must be same kind/boot/process, nondecreasing in wall and monotonic time, and satisfy the recorder's existing drift check. For live evidence require externally accepted qualification of actual host clocks/capture bracketing; current `requires-host-qualification` metadata is not that qualification. Synthetic clocks remain valid for fixtures only. Preserve current rejection of unexplained process/boot changes: this design implements no restart sensor or cross-process clock reconciliation.

For cycles in preregistered order require `L1 >= actualStart + W` and `Li - U(i-1) >= W`. Require distinct actual selections/runs and a current/end cut at least as late as every `U`; the existing start/end gate still requires three W. Use `observedAt = ISO(U)` from the retained bracket only after these stronger interval predicates pass. Then the unchanged witness's endpoint differences cannot create a false separation. Overlapping intervals, one broad capture containing three cycles, or three later reads of an old selection cannot pass. The source may be real yet temporal qualification unavailable; retain that distinction.

For each transfer require `Ltransfer - Ulearning >= W`, and for every required experience `Lexperience > Ulearning` and `Uexperience < Ltransfer`. Experience order among themselves need not be invented; episode distinctness is separate. Use their retained upper endpoints in the signed records. Never use actor-controlled `provenance.recordedAt` to establish these inequalities. A learning/check receipt collected later cannot shift Ulearning. These conservative predicates may reject uncertain timing even when a wall clock timestamp would mechanically pass; improve sampling within the fixed reserved captures or leave unavailable.

The current source proves neither host-owned spontaneous origin nor the protocol's autonomous-cycle interpretation. Preserve the raw origin and explicit `autonomy-unavailable` finding until a separately qualified source sensor/evidence resolves it. Never turn `unknown` into spontaneous or let a reviewer infer it solely from absence of an input row. No boundary observation is implemented here: restart, context reduction, later retrieval, spontaneous initiative, contradiction and applicability require their own actual sensors/judgments. In particular no caller token count, fabricated context overflow or copied cycle ID satisfies the boundary contract.

### DC2 source derivation

Keep the DC0 fields as the recognizable output, but derive them internally and add common policy/source/check bindings above. `modeSeal` must resolve to actual `host.development-control/mode` revision 1 and the matching `mode-sealed` event. Verify initial/final seal, accepted role configuration and registered control kind; intermediate history must preserve the binding. The initial capture must precede behavioral ingress. `captures` must name those actual retained cuts, not arbitrary supplied lists.

For both ablations gather all twelve mapped opportunities and matching learning/interference/feedback exposures. Validate matching workload bytes/schedule, actual original envelopes, model/effort/context profiles and accepted closure. Use captured effective payloads/tool receipts and actual request identities to support enforcement evidence. An accepted DC1 closure and mode label alone do not establish that a particular workload was isolated. Independent qualification must cover allowed operational mediators and actual workspace/external side channels. Unavailable or leaking mediation stays unavailable/invalid, including when a canary is absent. Source-only DC2 can establish the captured enforcement facts; it cannot award general semantic isolation.

For scripts resolve each actual `development_control_emit` effect, physical reservation/dispatch/settlement, output receipt and result observation. Validate exact stable effect ID, mode seal/input identity, input artifact, algorithm/source digest, run and finite nondecreasing receipt monotonic interval. Recompute the existing exact praise/agree/oppose output from the actual input using the pinned DC1 algorithm; do not accept a shell completion flag without the effect. Reject any provider-model request in that scripted role's complete captured/bridge inventory. Include feedback emissions and replay provenance. Zero tokens/cost are taken from actual accounted local effects; the admission API accepts no usage values. Preserve unknown settlements and do not replay emissions to make the proof complete.

Embed bounded signed script-case checker records in the corresponding five control-proof slots; there are no script-only `checker` slots in the 36-slot allocation. Their input references must first be retained in explicitly preallocated adaptation slots (nine for the concrete three-case/three-script workload), so budget both original receipts and embedded copies. Learning-check input receipts likewise use three declared adaptation slots before embedding. The policy's adaptation mapping must therefore extend its four named entries with exact role/subject-to-ordinal arrays for these twelve checks; every ordinal is unique and preclaimed. With four policy artifacts this uses sixteen of 54 optional slots before any judgment support or other adaptations, leaving at most 38. They must apply the same qualified rubric/extraction policy as relevant candidate judgments and demonstrate informative negative controls. Three invariant script outputs alone establish algorithm execution, not that the judgment rubric rejects unsupported learning.

Aggregate control acquisition `completed` only when every required execution and required checker observation was acquired, even if behavior fails. Known unfinished/crashed acquisition is `failed`; unresolved/missing acquisition is `unavailable` (unavailable dominates uncertainty, while known failures stay in detail). All covered cases remain in the denominator. `completed` never means the ablation performed well or the control is valid. Final independent reviewers retain `valid | invalid | unavailable` authority under the existing review schema.

## Capacity and artifact placement

The adopted complete profile already has 202 mandatory proof objects and up to 54 optional objects. This proposal adds no mandatory kinds and cannot treat unused reviewer/boundary capacity as interchangeable observation room.

| Existing kind/count | Source-admission contents |
|---|---|
| `task-output` 36 | Candidate and two ablations × twelve: bounded exact extraction plus assignment/run/output provenance. Aggregate the mapped source refs; do not duplicate entire source pages. |
| `feedback` 36 | Exact attributable feedback bytes/provenance for those same executions, bound to registered feedback ingress. |
| `checker` 36 | Signed opportunity checks including acquisition, behavior, disclosure and matching, with exact evidence commitments. |
| `script-receipt` 18 | All actual script task/feedback receipts with physical bindings. |
| `cycle` 3 / `learning` 3 / `experience` 9 | Recorder-derived candidate proofs. Learning includes its bounded initial-learning receipt. |
| `control` 5 | Source-derived aggregates referencing ablation proofs; inline bounded script checks where applicable. |
| `boundary` 6 / `reviewer-output` 2 / `review-judgment` 48 | Remain reserved for their existing owners/obligations; this design does not implement or consume them for missing evidence. |
| `adaptation` at most 54 | Explicit policy/workload/qualification/clock artifacts and any separately reserved checker support. No hidden per-assignment expansion. |

For the concrete allocation `q = 65,536` bytes, protect `202*q = 13,238,272` of `16,777,216` proof bytes, leaving at most `3,538,944` bytes and 54 slots jointly for optional artifacts.
