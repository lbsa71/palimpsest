## Frozen API and wire

`collectDevelopmentBehavior(..., reader, now = Date.now(), retainedArtifacts: readonly ArtifactRef[] = [])` adds recorder-supplied retained bytes to all mandatory reachable B references. B's existing `artifactIndex` remains its only inventory. Entries have exact `{artifact: {uri: 'sha256:<digest>', sha256: '<digest>'}, bytes: <nonnegative safe integer>}` shape, strictly ascending unique digest order and exact read lengths. Reconstructing B uses its authenticated index as the explicit reference input and checks equality with the complete reachable-plus-explicit inventory.

`DevelopmentAccountingTail.artifactIndex` is mandatory with that same canonical shape. It contains exactly all additional T bytes, excluding digests already in B, including reachable transition/settlement/review/execution/reason artifacts and recorder-supplied retained drafts and metadata. New `collectDevelopmentAccountingTail(registrationDigest, behavior, transitions, reviews, retainedArtifacts, reader, limits)` returns an unsigned tail for the existing observer signature. It accepts signed review bindings, reads B bytes to seed shared digest deduplication, and scans transitions/reviews plus extras. No index artifact, self hash or store is introduced.

Every unique B index entry consumes one record. Every unique additional T index entry consumes one record. The B record total is observations + original requests + B requests + B transitions + B index entries. The joined total adds T transitions + review bindings + additional T index entries. Both must remain within the original `maxRecords` (at most 512). Repeated references and aliases count once by digest; additional index records do not silently raise the limit. Artifact bytes remain under the original `maxArtifactBytes` (at most 1,000,000), and canonical envelope/index overhead plus deduplicated B/T bytes share the original `maxEvidenceBytes` (at most 8,000,000). The tail collector checks its own tail overhead; final preparation checks complete envelope overhead.

`DevelopmentReviewExecution.evidenceReads` entries require exact `{requestId, artifact, localToolCallId, localRunId, stepId}`. These metadata fields identify the actual retained canonical ToolCall `{id, runId, stepId, name, arguments}` with exact arguments `{artifact}`; fixture-only top-level artifact payloads are rejected. Physical request and reservation IDs equal `development-request:${identity([registrationDigest, roleId, 'tool:' + localToolCallId])}`. Prompt manifest equals `'tool:' + localToolCallId`. The mapped run equals `development-run:${identity([registrationDigest, roleId, localRunId])}` and must equal the final review model's run. This deliberately supports isolated reviewer child runs, not reads at an operational root. Payload IDs/run/step must equal the access metadata, name and physical model must be `evidence_read`, provider must be `effect-receiver`, purpose must be `reasoning`, role/root/lineage must remain registered, payload bytes must be canonical and bind the physical request digest, and exact B artifact bytes must equal the succeeded authenticated receipt. The read's succeeded transition must strictly precede the final model dispatch in authenticated transition order and cannot have a later timestamp.
