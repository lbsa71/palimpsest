## Observed defects in the selected comparison configuration

Codex 0.162.1 actually spawned two children. Their requests contain `agent_message` with `id`, `author`, `recipient` and content blocks of `input_text` and `encrypted_content`. The original observer correctly refused this unsupported shape before provider transport. A validator that accepts only ordinary messages prevents the selected native harness from performing the intended workload. Exact refused artifacts are retained in the original trial; use those bytes as the positive acquisition fixture, with meaningful negative mutations.

Claude 2.1.296 exposed Bash and Read under the declared Agent/Bash/Read/Write selection. Passing a tool name did not create that capability. Current [first-party bare-mode documentation](https://code.claude.com/docs/en/headless#start-faster-with-bare-mode), consulted 2026-10-11, describes reduced tools and skipped subagent discovery, and supports explicit `--agents`. The [subagent documentation](https://code.claude.com/docs/en/sub-agents) documents CLI definitions and built-in agents. These sources explain a likely configuration cause; only a captured request from the pinned binary can establish the actual surface. Documentation for the current product is not proof of behavior in the pinned version.

## Implementation and evidence boundaries

Use the existing concrete workers, runner, observer and native profiles. No new agent framework, generalized proxy, credential discovery, arbitrary header forwarding, dependencies, compatibility layer or production service changes are required.

For Codex, accept only the exact acquired item/content forms. Require valid bounded identities and fields, preserve every original byte and attribution, and reject unknown/media/hosted-server additions. Native author/recipient text is evidence of what the client sent, not authenticated host authority. Do not decrypt opaque blocks or assert their meaning. Preserve the original full-context reservation and refusal/unknown behavior. Any new format qualified only through synthetic replies must remain unavailable to paid transport until separately qualified; use a narrowly pinned profile/transport guard rather than allowing all unknown request types. Existing qualified plain coding behavior must keep its original semantics.

For Claude, compare the smallest explicit invocation changes that can expose actual native delegation. Prefer retained built-in native instructions when an isolated invocation can expose them. If explicit CLI agent definitions are necessary, retain their complete source and identify them as supplied configuration, not the default native agent. Capture and audit effective parent/child tools, instructions, model roles, effort, thinking and headers. A non-bare invocation may not read real user/project configuration, credentials, plugins, hooks or services: prove its blank isolated home/workspace/configuration boundary before running it. Keep standard/global pricing, exact protocol guards and current synthetic-only limit. Unknown emitted headers or capabilities are a new observed refusal, never an invitation to wildcard acceptance.

The physical fixture must identify actual child requests from their emitted native message structure, actual command tool results by call identity, and actual parent receipt of both child results. Task text containing an expected answer cannot satisfy an observation check. Retain both child-created files and bind observed overlap to two concurrent original-ledger requests. Parent receipt establishes transport mechanics, not competent judgment. Reuse the original concurrency fixture's pinned binaries and declared 8-request/concurrency-4/60-second/full-context envelopes for each **new** synthetic attempt; never reopen, replenish or raise a failed attempt's grant. Declare any acquisition-only attempt and replies before its dispatch. Maximum three initial native attempts per product in this unit, with fixed source and retained first failures; further work requires an explicit defect disposition and newly bounded task.

Pure checks must cover exact accepted and refused shapes, wrong pinned binary/profile, paid-route refusal for newly synthetic-only features, mutated options and unavailable tool surfaces. Actual checks require root's serialized physical window after source freeze and declared plans. No network provider, account inspection, external messaging, installation or publication. Use `gpt-6.1-sol` / high for implementation and a fresh `gpt-6-astra` / high review with a separate finite goal.
