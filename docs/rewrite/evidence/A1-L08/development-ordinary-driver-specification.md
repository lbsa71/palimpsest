## Concrete behavior and source constraints

`AutarkApplication` opens its own OperationalStore, calls its trusted `developmentAccounting` factory before creating the runtime, then installs ordinary communications and initiative scheduling. Its constructor admits/reconciles local work but does not intentionally start provider work. `CommunicationsCore.receive` schedules its notification in a microtask. `app.tick()` launches work and returns before that work necessarily completes; completion can launch another ordinary tick. A driver must preserve those facts rather than describe one awaited tick as one completed reasoning cycle.

The accounting bridge requires the candidate's original ledger and local ledger to share the **same Store object**, not merely a filename. Preparatory grant registration can use an earlier handle, but that handle must close before constructing the application. The candidate factory builds the original ResourceLedger over the Store supplied by the actual application constructor; it verifies the existing grant and role allocations without allocating a replacement grant. All other roles share that exact original ledger through their own local bridges. Recorder source `21aa234` requires these actual associations at assignment admission.

## OD1 API and acceptance freeze

The author freezes concrete TypeScript signatures before implementation. The intended surface is `DevelopmentAcquisitionDriver.prepare`, `ingestRegisteredAssignment`, `observeOrdinaryStep`, `freezeBehavior`, and `closeApplications`. No method selects, edits, completes or invents a goal. The driver owns the applications it constructs; it does not accept a structural `Pick` as proof that a factory returned an actual application.

- `prepare` receives the exact accepted signed plan/trust/raw and recorder stores, trusted per-role application options/factories, and original default ceiling. Validate and detach accepted plain descriptors before awaits; retain actual service instances and callback identity without exposing private copies through callback `this` or arguments. Construct the candidate first, on the already registered original state. Bind its actual original ledger inside the application's accounting factory. Construct each other behavioral role on its accepted isolated state/workspace. Validate exact configuration, role, journal, Store/runtime/communications and resource association. Factories cannot replace the recorder hooks or supply another grant. Reviewer processes remain the model-review adapter's responsibility.
- Until the recorder has been claimed and every accounting hook is bound, draft reservation and response callbacks refuse. Prove construction makes zero physical requests. Unexpected construction-time work must fail, not receive a temporary bypass. No server, Slack socket or application polling interval starts merely because the driver is prepared. Local construction failure closes already-created applications and retains its explicit error; it cannot clear claims, original charges, journal history or state to retry transparently.
- Claim the recorder exactly once after all required objects exist. Preserve its preregistration, clocks, source/capacity/retention checks and one-use semantics. A preparatory ledger handle with the same path is not an acceptable original ledger. Existing grant start, allocations, requests and unresolved charges must be unchanged. Do not create allocations with a new start time to repair a fixture or a real attempt.
- Assignment delivery is only the recorder's registered role-local `deliverAssignment` path. No direct runtime admission, changed message body, candidate-selected assignment or checker output enters this path. Candidate/control assignments can share an ID because the role is part of its identity. Current cancellation/deadline checks still run at admission.
- `observeOrdinaryStep` captures bounded source state, calls only the application's ordinary tick, and captures again. Return capture references and the actual phase/result; an awaited tick does not assert quiescence, completion, autonomy or one cycle. Automatic work between samples remains visible in the global journal. Sampling cannot spend protected final/response capacity, hide rejected work or stretch the behavioral deadline. It may explicitly refuse when the existing fixed capture budget cannot cover another pair.
- `freezeBehavior` forwards all actual candidate/control handles and bridges through the existing recorder gate. Missing controls, open/unknown requests, unsupported boundaries and unavailable journal history remain explicit. Constructing an ordinary app for a control role is **not** proof that the required ablation exists. No wrapper-level override can turn a negative B into accepted evidence.
- `closeApplications` is bounded by the actual application shutdown semantics, preserves late reserved responses and original uncertain charges, and closes controls before the candidate's original Store. It must not erase immutable evidence or cancel an original grant merely to make a clean closure assertion. Record shutdown errors and preserve failure disposition.

Use actual local application/SQLite/runtime/communications/accounting objects. Mock worker/provider transport where necessary and label that boundary explicitly. Small causal checks cover original-object identity, construction-time dispatch denial, wrong role/configuration, foreign factory objects, mutable descriptors, partial construction cleanup, ordinary assignment ingress, asynchronous tick behavior, bounded sampling, late response retention, consumed claims and close ordering. Check genuine before/after source and request records; do not write tests that only assert the wrapper called a method. No paid inference, native acquisition, host mounts, production service or private account access is part of this task.

## OD2 source facts that need an exact proof contract

Scheduler events currently contain an ordered selection and sequence, **not a timestamp**. The driver cannot capture an old selection later and stamp it with a new wall time to satisfy W. A qualified source projection must bracket new event sequences with retained before/after host-clock captures. Distinct cycle intervals must establish the required separation from their bounds; three delayed reads of an old event cannot establish three autonomous cycles. Actual initiative execution and physical request records must bind the selected goal/run. Self-labelled goal origin alone does not prove spontaneous origin: use actual admitted/steering input ancestry and host-owned origin records, preserving unknown or human-origin cases.

Input provenance must bind the exact registered packet entry to `communications.inputs`, actual admitted/steering events, run and retained result sources. The ordinary communications loop may reuse a run for a revision or follow-up; do not assume one assignment equals one new run. Learning, interference, contradiction, transfer success and rule applicability require independent task/feedback interpretation as well as these mechanical bindings. These judgments cannot be inferred from a successful HTTP response, a model's statement, a tool count or a source row's existence.

The observer must retain a reproducible proof with the exact capture refs, global event positions and relevant document version identities. JR1 withdrawn payloads and JR2 attempt-use withdrawal prevent later use; cached projections are not an exception. Missing source, intervention, unsupported boundaries and failed opportunities remain evidence. No generic signing callback that accepts arbitrary `DevelopmentObservation` data is authorized by this specification.

The hard capture limits may prove too small for a real multi-role application. Record an observed capacity failure and specify a separately reviewed bounded incremental capture if needed. Do not truncate history, raise a claimed attempt's bounds or present a small synthetic composition as proof that the full elapsed workload fits.
