## Frozen behavior contract

The first supported process profile is **one same-boot restart of the whole acquisition-host child**, containing the recorder and all behavioral role applications. The parent survives and owns only lifecycle supervision and bounded independent process receipts. This is an actual restart of the candidate application's OS process. Controls share the intervention timing but retain isolated stores/workspaces and their original role allocations. Preregister that intervention; it is not spontaneous behavior. This profile does not claim host reboot, parent crash recovery, installed service readiness or independent control processes.

The first context profile is the configured pinned **Mistral** model, text/tool traffic already supported by the existing serializer, one measured reduction and subsequent ordinary continuation/retrieval. All stages have fixed byte, record, request, CPU/wall and original-grant limits. Unsupported input forms, no suitable reducible prefix, missing exact tokenizer, insufficient evidence space or insufficient grant produce unavailable/infeasible evidence. Other engineering work can finish while token qualification remains open. No silent provider substitution or retrospective limit change is allowed.

The unchanged witness boundary fields remain the output: restart derives nonempty `openWorkIds`; context reduction derives `contextInputTokens > manifest.contextWindowTokens`. Their `artifact` references a complete typed proof, with before/after acquired capture refs. Those fields are projections of verified retained facts, never API inputs carrying operator assertions. The existing required numeric field for restart can be zero with an explicit not-applicable measurement in its proof; zero cannot stand in for missing context-boundary measurement. Retrieval is also a separately required boundary: reduction alone cannot satisfy it or a developmental transfer judgment.

## Minimal interfaces and ownership

The following names and semantics are the proposed contract to freeze before authoring. `ArtifactRef`, actual capture readers, `ShellCheckpoint`, existing role IDs and signed-plan identities are reused. Bounds and exact wire keys belong in the new plan profile, not an extensible free-form event schema.

```ts
// L09 lifecycle adapter; no model-callable surface.
type ProcessKey = { bootId: string; pid: number; startTicks: string; pidNamespace: string };
type HostAnchor = { wallMs: number; monotonicNs: string; process: ProcessKey };
type RestartPermit = {
  version: 1; attemptDigest: string; registrationDigest: string;
  restartId: string; ordinal: 1; predecessor: ProcessKey;
  beforeCapture: ArtifactRef; recorderStateDigest: string;
  originalInventoryDigest: string; reservedLifecycleBytes: number;
};
// A byte-ref index, not a caller-supplied assertion of successful restart.
type RestartProofRefs = {
  permit: ArtifactRef; parentLaunch: ArtifactRef; predecessorExit: ArtifactRef;
  drain: ArtifactRef; successorLaunch: ArtifactRef; successorAttach: ArtifactRef;
};

// Recorder-owner methods, joined only after JR2/CP2.
// prepareRestart captures actual apps/source and durably reserves all remaining slots.
prepareRestart(restartId: string): RestartPermit;
// Reopen validates the parent proof and changes only the process/clock segment.
reopenAfterRestart(options: AcquisitionRecorderOptions, proof: RestartProofRefs): DevelopmentAcquisitionRecorder;
// Loads registered inventoried refs; no generic callback accepting ObservationData.
admitBoundaryProof(ref: ArtifactRef): void;

// L02 shell hook, implemented by the trusted broker through existing worker RPC.
// Host derives effective bytes from the bound transcript/checkpoint/source chain.
type ContextCut = { runId: string; revision: number; checkpoint: ShellCheckpoint };
type ContextDecision = {
  cutDigest: string; prePayload: ArtifactRef; measurement: ArtifactRef;
  action: 'continue' | 'compact' | 'unavailable';
  prefixEnd: number | null; reason: string | null;
};
prepareContext(cut: ContextCut): Promise<ContextDecision>;

// Host-only, immutable accepted profile; never a function sent through worker config.
interface QualifiedContextCounter {
  readonly qualificationDigest: string;
  readonly provider: 'mistral'; readonly model: string;
  count(payload: Uint8Array, signal: AbortSignal): Promise<
    { kind: 'exact'; inputTokens: number; tokenizationDigest: string } |
    { kind: 'unavailable'; reason: string }
  >;
}
```

`ServiceProcessOptions` gains only a sealed development-start descriptor and a bounded lifecycle sink; the existing verified `service-child` selects a **fixed compiled helper** for that descriptor, not an arbitrary module path/function supplied by the candidate. The helper composes accepted OD1 and recorder objects, with no independent scheduling logic. Its control IPC allows prepare/sample/registered assignment/restart preparation/stop; it never accepts arbitrary source edits, SQL, observations, grants or signatures. Exact descriptor, helper/driver code, plan, source and dependency closure are bound before launch. Missing this injection API is a current composition gap, not implied by `ServiceProcess.start()`.

Each child constructs OD1 candidate first. Its application accounting factory constructs the original ledger over the Store passed by that actual application; all control bridges refer to that ledger. On restart new objects bind the **same durable original identities**, again sharing one actual Store within the new process. The parent never owns an application source handle or a spendable original ledger. Readiness requires all source/bridge/recorder associations and current-use checks, not simply IPC connectivity. Construction dispatch remains denied; ordinary ticks begin only after readiness. Because application construction performs recovery, recovery accounting writes and request-scoped late evidence must be permitted through reserved recovery paths while **new dispatch** remains denied. They must not require a newly claimed recorder or bypass custody.

The recorder owns a durable one-use `restartPending` record, separate from both the irreversible behavioral freeze and raw-write `pending` marker. The accounting owner extends existing reservation and `assertEntry` gates to consult it under the original Store transaction: deny fresh reservation/dispatch while it exists, but permit complete source capture and already-reserved response/settlement. After proof import and all-role reattachment, the recorder marks that ordinal consumed and removes only its temporary dispatch fence. A root cancellation, deadline, custody withdrawal or frozen behavioral phase still denies dispatch. This narrow shared-file change belongs to the accounting owner through root, not to the process or shell author.

Signers/trust stay in the previously accepted host closure, outside candidate workspaces and confined workers. A self-generated key, host flag or two process IDs cannot qualify an observer. The parent process receipt issuer and tokenizer qualification principal/closure must be explicitly accepted by the plan/trust owner. The recorder authenticates them and rederives boundary fields; the unsigned OD2 observer continues to own only mechanical source facts.

## Process sequence, clocks and original state

1. Before claim, validate the single-restart profile, all-role capture capacity, fixed parent spool allowance, exact original grant and current custodian. Reserve the terminal, final, pending-response and restart metadata independently. Parent startup uses existing frozen candidate/authority checks. Observe spawn directly in the parent; read bounded raw boot ID, child and parent `/proc/.../stat` and PID namespace twice, bracketing wall and `hrtime.bigint()` anchors. Compare start ticks, parent PID and namespaces across reads. A PID is not an identity. Retain raw observations, not just their decoded values.
2. Reach real open work through registered ingress and ordinary ticks. `prepareRestart` closes **new-dispatch admission temporarily**, without cancelling the grant, role allocations, runs or effects and without calling irreversible `freezeBehavior`. Capture every role at a complete CP2 cut. The candidate must have nonterminal work linked to registered ingress/selection, durable checkpoint/input/observations and original requests. Record the actual unresolved request set, including uncertain originals. A no-open-work sample fails this boundary. An in-flight response racing the cut remains in the journal/accounting tail; do not assert the before snapshot is the state at death.
3. Persist the one-use permit and pending parent-spool reservation, then acknowledge it to the parent. This is an intentional restart marker, distinct from an interrupted raw-write intent. The parent retains stop request/observed exit/close status and the previous identity. Graceful or forced stop is preregistered. Forced death may leave unknown provider outcomes; exit is not settlement. Never retry a consumed claim or wipe pending evidence to arrange a cleaner attempt.
4. Run existing cleanup and independently establish descendant drain. Observe process-group stop **and** existing worker namespace/cgroup cleanup receipts; verify kernel cgroup `populated=0` where that confinement profile applies, and release/reacquire the execution lease. A sampled process tree or missing leader alone cannot establish drain against detached descendants. If current lifecycle infrastructure cannot expose the accepted drain proof, add its narrow hook under L09 or report unavailable; no successor launch is credited before drain. Bound cleanup by its registered deadline; cleanup may finish after the behavioral deadline but cannot admit new work or extend elapsed qualification.
5. Persist `exit <= drain-complete < next-spawn < attach-ready` in the surviving parent's monotonic segment. Different start identities are required; reused PID with different start ticks is valid only with the complete chain. No second child/Store authority overlaps. All parent facts are retained in a fixed private no-follow, owner-only spool until the successor imports them through the recorder's reserved raw path. The spool is not a second source journal or resource ledger; it has a fixed finite record set, sequence, byte bounds and attempt/permit linkage. Interrupted/incomplete spool publication remains unavailable. Its physical duplicate storage also needs a capacity allowance; content deduplication is not a reservation assumption.
6. Launch the same frozen closure, plan, original state/workspace and controls. `reopenAfterRestart` verifies immutable prior inventory, the consumed permit, actual new `/proc` identity, parent receipt issuer and original grants before adopting the new clock segment. It permits this one planned process transition only. It cannot clear interrupted capture/freeze/raw-write failure, resurrect a withdrawn attempt, change boot/configuration/authority without a separately registered transition, or reopen a terminal failure as acquiring. It imports lifecycle raw bytes exactly once and attaches fresh actual Store objects before source use. Crash during transition import preserves conservative inventory and becomes unavailable; it does not grant another restart.
7. Capture after constructor recovery and before ordinary dispatch; compare exact journal graph, run/input/checkpoint/observation/effect identity, original allocation parents/issued-at/deadline/cancellation, request immutable identities and cumulative charges. Legitimate recovery/settlement suffix events may differ; missing history or deleted unknown requests may not. Existing unknown usage stays unknown and its conservative charge remains held absent an actual trusted settlement. Resume through the existing application queue/tick and capture subsequent actual results. Uncertain effects block reconciliation-before-retry; repeated model work is a new original-accounted request, never settlement of the previous one. Preserve a blocked result rather than claiming completed continuity.

Process-relative `performance.now()` values are comparable **only within their process segment**. The parent monotonic anchors bridge the intentional restart; child request/response handshakes provide bounded mappings to each segment. Do not subtract old-child from new-child times or reset the first acquisition wall anchor. Keep wall-versus-monotonic consistency tolerance no looser than the existing 1000 ms check, with separately bounded handshake uncertainty. Unexplained gaps, regression, changed boot, vanished parent, excessive uncertainty or suspend not covered by the selected clock qualification make elapsed development unavailable. Three W windows/cycle spacing still require conservative lower bounds across complete observed intervals; downtime does not become an autonomous cycle. Initial qualification is same-boot only.

## Pre-reduction token and continuation sequence

The measurement target is the exact serialized **would-be reasoning request before any reduction at this turn**, after all admitted host context, instructions, tools, steering and completed tool observations are included. It is not the raw checkpoint's byte count or an earlier request. Input token count includes the qualified provider's full message/tool framing and special tokens. Output allowance is recorded separately.

1. In source-owned Pi `prepareRequest`, before changing `transcript`, save a checkpoint covering the complete current cut, including first-call appended inputs. Invoke the narrow `prepareContext` RPC. The host binds that checkpoint to the actual invocation/run/revision and reconstructs the effective payload using the existing provider serializer. Reuse/extract the existing pure continuation filtering and payload projection; do not implement a second model loop.
2. A checkpoint digest alone is insufficient because a worker can supply checkpoint content. The broker boundary helper checks the ordered transcript derivation from host `ShellInput` (including actual application memory/agenda frame), prior accepted checkpoint/reduction, host-retained provider response projections and actual bridge tool observations, with exact call/step IDs. Initial append, failed-turn filtering and each accepted reduction must account for every message once. Unmatched assistant content, invented tool results, omitted pending inputs, duplicate/reordered replies or unsupported response shapes make the proof unavailable. Source proof includes the relevant immutable journal versions, request/response refs and checkpoint edges. It does not accept worker-generated large text as proof of real acquired context. Existing broker prompt-shape checks alone do not provide this derivation.
3. Reserve the preimage, measurement, possible summary/reduced/post-continuation artifacts and metadata **before** retaining them or invoking a counter. Resolve payload bytes under current JR2 custody. Count in the accepted host counter with fixed input bytes, output count and CPU/wall bounds; no network tokenization or provider request occurs here. The resulting receipt binds exact bytes, model, serializer, tokenizer asset/runtime/config hashes, original context window, output allowance and counter qualification digest. Safe integers only; unsupported/failed counters return unavailable, never a byte estimate dressed as tokens.
4. The proposed frozen token policy reduces when `inputTokens + maxOutputTokens > C`, where `C` is the actual qualified configured context window. A developmental overflow is credited only when **pre-reduction `inputTokens > C`**. Early safe reduction below C is valid runtime behavior but not evidence of the stronger boundary. Equality to C fails that boundary. A single newly received legitimate tool result can cross C; no oversized reasoning request is sent merely to obtain an error. The profile replaces the message-count trigger for these sealed attempts; it cannot silently change a claimed configuration. Existing threshold behavior remains separately evidenced.
5. Reuse the existing compaction instruction, sequential summary call and checkpoint update. Keep the first implementation finite: at most one summary per boundary. Select a nonempty oldest contiguous prefix ending between complete assistant/tool exchanges, preserving at least the configured retained suffix. Host and worker agree on the exact prefix digest/cut. Token-count the **actual summary payload**, including its canonical JSON escaping and compaction instructions, before dispatch; it must fit `summaryInputTokens + summaryMaxOutputTokens <= C`. Choose the largest safe eligible prefix under the fixed scan/count limit. If none fits, stop unavailable without dropping input. Do not introduce recursive summarization, ad hoc truncation or a new context engine. The existing prefix may itself be too large, so the normal message-count prefix cannot be assumed safe.
6. Summary capture/reserve/dispatched/transport/response/settlement uses the existing broker and original-grant bridge with purpose `compaction`, original run and owned instruction/tool manifests. A local token measurement is evidence/host elapsed work, not a fictitious physical model request or a provider usage settlement. Every actual summary/reasoning/tool call retains its real request and charge, including failed and uncertain calls. Counter results never overwrite billing usage or unknown reservations.
7. Only a valid actual summary response permits transcript replacement. Persist the mapping from exact pre-cut and prefix to response/summary and reduced checkpoint; retain the full original source. Count the exact reduced reasoning payload again. Require `reducedInputTokens + maxOutputTokens <= C`, and enforce digest equality when that payload reaches ordinary `capturePrompt`/reserve/fetch. A summary that expands context or cannot fit stops before further dispatch. Changed steering/source between prepare and dispatch invalidates the prepared cut; a new bounded measurement must be reserved or the attempt stops. A context decision is not a reusable dispatch permit.
8. Observe ordinary continuation from the reduced checkpoint, plus a later ordinary `memory_retrieve` or application host-context retrieval with its actual source records and audience/provenance. For the first profile, prefer explicit `memory_retrieve` because it already has an accounted tool observation and exact result; no new retrieval API is needed. The registered held-out task requires information independently verified as absent from the post-reduction request, then retrieved from an allowed durable source and used in a later independently checked outcome. Bind retrieval to the subsequent actual request that consumed its result and the actual result-producing invocation; an old `lastResult`, summary mention, workspace answer file or operator injection is insufficient. A failed opportunity is retained; counts do not establish learning or transfer.

The counter qualification is an external **finite dependency**, not an invented package selection. Inspection establishes no accepted exact tokenizer/model binding in this source closure. DB2-Q must identify the configured pinned Mistral model's actual tokenizer assets, chat/tool serialization rules and serving-profile relationship from authoritative provider evidence; freeze exact downloadable assets, license, local editable adapter, dependency/runtime/build closure and their hashes. Validate bounded independent cases covering Unicode, JSON escaping, multi-turn tools/arguments, system framing and empty content, including near-context cases. Compare to independently obtained provider input-usage receipts for the same exact unmodified requests where authorized; an observed match alone is not proof for untested formats or model aliases. Required acceptance states precisely what inputs/model revision the counter covers and excludes. If an exact relationship remains unavailable, record that gap and leave live overflow unqualified. No arbitrary tokenizer, nominally related vocabulary, text-only encoding, confidence interval or after-reduction provider usage may satisfy `kind: 'exact'`. No dependency installation, download, provider call or network research is authorized by DB0.

## Capacity, cancellation and custody

Use CP2's complete pages and existing manifest caps: at most 512 records, 1,000,000 bytes per artifact and 8,388,608 evidence bytes, or the plan's smaller limits. The broker's 2,000,000-byte payload cap is **not** the evidence allowance. A required indivisible payload exceeding the admitted artifact bound is infeasible for this profile; do not chunk it under a new unreviewed format or silently increase limits.

Before claim, extend the recorder owner's existing worst-case equation with `restartRaw + contextPreimage + summaryPayload + summaryResponse + reducedPayload + retrievalProof + continuationPayload + boundaryMetadata`. Source pages, all copies/references, signatures, owner state, spool import intents, B/T inventory associations and escaped serialized metadata count. Reuse counts only after exact retained-byte verification; assume no deduplication in admission arithmetic. Physical summary/reasoning responses also reserve their usual full late-response allowance. Bound number of tokenization calls/prefix candidates independently of physical requests and include local CPU/wall time within the existing grant deadline. Freeze a concrete feasible allocation before any new experiment; no numeric whole-development feasibility is claimed by this design.

Reserve restart slots and context proof slots separately from optional sampling. Mandatory final/terminal records and pending physical responses stay protected. Failed counting, aborted compaction, incomplete import and source refusal retain their exact bounded failure and already acquired bytes. A counter error must not prevent cleanup. Root cancellation/deadline/withdrawal fences new measurement use, compaction, provider dispatch, observation signing and B/reviewer admission; it does not erase a prior receipt or deny a late reserved response/settlement. Counter cancellation must terminate bounded work; any dependency that cannot meet that condition fails qualification.

Raw preimages and checkpoints may contain private or later-forgotten material. Acquire only under the accepted JR2 custodian scope, preserve source version links, and check current historical-version availability/custodian disposition before projection, counting, dispatch, proof signing, freeze and reviewer use. Operational forgetting withdraws use of copied originals, not silently deletes authoritative attempt evidence. Existing accepted external-copy retention/destruction rules govern stored originals and the parent spool. Cached tokens/proofs cannot bypass withdrawal. Source is read-only during capture, and recorder/accounting writes occur outside CP2's read fence.

## Positive and causal negative acceptance

1. **Restart continuity:** real-store offline composition preserves registered nonterminal run/checkpoint/input and an original dispatched/uncertain charge across simulated lifecycle events. The physical follow-up must repeat through actual distinct OS child lifetimes, with retained raw clocks, boot/PID/start/namespace, exit/drain/new-launch ordering and real ordinary later behavior. In-process reopen, fabricated parent receipts, no open work, reused lifetime, mismatched closure, missing drain and overlapping children reject. A provider/effect unknown remains held, not a success or implicit retry.
2. **Restart admission:** ordinary reopen still rejects an unexplained process change. Exactly one authentic reserved permit admits exactly one process segment with unchanged grant/start/deadline/role allocations. Replay, second restart, new boot, dead parent, old spool, raw-write/freeze interruption, removed request, changed cancellation or refreshed allowance reject. Exercise constructor recovery before reattachment and interrupted proof import without admitting any request.
3. **Clock causality:** regress wall/monotonic independently, use child clocks as if comparable, omit the interval at death, replay an old sample, increase handshake uncertainty or substitute a PID after the first stat read. None yields elapsed/cycle credit. Only conservative supported brackets qualify the relevant duration; zero request count does not prove elapsed behavior.
4. **Context source causality:** an actual ordinary cut with independent synthetic exact counter can drive one summary through the real host bridge and then a reduced request/retrieval result. Mutate only preimage content, tools, instruction, checkpoint, admitted input, provider response, observation step, source version or selected prefix; reject the forged lineage even when every digest is internally self-consistent. This check must expose the present distinction between host-captured payload and independently proved source.
5. **Token causality:** equal-to-C, below-C/message-count-triggered S09, byte estimate, post-reduction `prompt_tokens`, unqualified/wrong-model tokenizer, malformed count, counter timeout or worker-supplied count cannot earn overflow. Qualified synthetic input above C with summary and reduced requests within C passes mechanics, retaining permanent synthetic labelling. Physical qualification additionally requires DB2-Q and actual acquired preimage; fixture arithmetic is not that evidence.
6. **Compaction and retrieval:** an oversized summary prefix, split tool exchange, expanded/failed summary, no retained original, altered reduced payload or cancellation between measurement and fetch stops before the next dispatch. Positive continuation consumes the actual summary checkpoint and later allowed retrieval. Forged memory, inaccessible audience, withdrawn source, reread of an old result, answer already present in the reduced prompt or operator-injected answer cannot satisfy the held-out retrieval-use predicate. A checker/reviewer still judges actual outcome quality independently.
7. **Capacity and uncertainty:** oversubscribe each raw/record/owner/spool/counter limit separately and crash at every reserve/write/import/ack transition.
