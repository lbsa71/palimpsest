## Decision and concrete corrections

Reuse the recorder, its pending/raw/inventory protocol, source-owned Pi, accepted paged projector/extractor, existing signatures and exact bounded reviewer `original` reads. Implement one private recorder composition scope and narrowly refactor its existing reader/retainer kernels. No generic signer callback, public write-capable current-use fence, second evidence pool, new reviewer query protocol, duplicated control-output algorithm or complete snapshot reconstruction is needed.

The earlier design's “38 remaining” optional objects omitted **36 full opportunity proofs**. `deriveDevelopmentControlProof` rederives each of twelve ablation opportunity proofs and reads its exact encoded retained original; the candidate's twelve full proofs must also be retained for independent review. These are additional to 36 task-output, 36 feedback and 36 checker obligations. Actual b1 extraction creates canonical input/output hashes without retaining their preimages. DC2's fixture Map supplies extra preimages without recorder accounting; that convenience is not a feasible retention scheme. DC2 also lists all related assignment input/output commitments although it does not independently read every such commitment.

There are three different reference uses:

| Use | Authority and byte source |
|---|---|
| Retained reference | Exact immutable entry in the recorder inventory, named proof slot or captured original mapping; reads authenticate length/hash and current use. |
| Derived assignment commitment | `DevelopmentAssignmentProof.input/output`, and DC2 `executions[].inputRefs/outputRefs`, name canonical extraction from exact captured source. Their `sha256:` spelling does **not** establish inventory membership. Only the typed derivation described below resolves them. |
| Captured operational reference | For example script effect receipt/input `aeon:artifact:` values. Resolve through the particular accepted capture's original mapping, preserving original URI and hash; never use a naked hash to invent source membership. |

The existing b1/DC2 wire can keep these values; this composition freezes their **field-specific** meaning. Do not run a recursive “all ArtifactRefs must be separately retained” scan over these proofs. Conversely, do not expand generic `readArtifact`, reviewer `original` membership or checker judgment support to accept arbitrary derived-looking refs. Identical bytes may actually be present in both categories, but deduplication is never budget authority.

## Exact placement and protected reserves

Let `R` be candidate plus the two ablations, filtered in registration order; `O` the twelve manifest opportunities; `S` the three scripted controls in manifest order. Validated workload script order must be mapped to that control order explicitly. For `(R[r], O[o])`, `n = 12*r + o` (`0..35`). Use b1's existing `developmentProofSlot` for mandatory task-output/feedback/checker identity; assert equality to this formula. Do not assume the candidate is index zero unless registration says so.

| Slot identity | Exact bytes/meaning |
|---|---|
| `task-output:n` | Canonical b1 extraction of the opportunity task's `{status, observations}`. Standalone bytes, not a proof wrapper or pointer. |
| `feedback:n` | Canonical b1 `{input: attributed feedback InboundInput}`. Standalone bytes; not the feedback task's output. |
| `checker:n` | Exact signed opportunity checker record. Full proof embeds the same signed record and references this original. |
| `adaptation:16+n` | Exact `encodeDevelopmentSourceProof` full opportunity proof, including all related assignment source facts. No source pages or extracted byte copies are added. |
| `cycle:0..2` | Candidate cycle proofs in manifest cycle order. |
| `learning:0..2` | Candidate learning proofs in manifest transfer-opportunity order. |
| `experience:0..8` | Candidate interference proofs in first-occurrence order of the manifest's flattened interference IDs, exactly b1's current mapping; preserve legitimate sharing. |
| `control:0..4` | Final control proof in manifest control order; no duplicated extracted preimages. DC2's measured 64,063-byte fixture is close to q=65,536 and does not establish worst-case fit. |
| `script-receipt:6*s+2*k+e` | Exact actual DC1 effect receipt bytes: scripted control `s`, workload case `k=0..2`, `e=0` task / `e=1` feedback. All eighteen obligations exist even when the same bytes already occupy captured-original/physical-response inventory. |
| Existing boundary/reviewer slots | Six boundary, two reviewer-output and forty-eight review-judgment obligations remain exclusively assigned as before. |

For script-receipt, authenticate the effect, original dispatch/settlement and captured operational mapping using DC2; copy those exact bytes into the logical named proof slot. Existing `writeRaw` may reuse a content-addressed raw entry. Still create all eighteen immutable proof identity records, reserve eighteen q byte obligations before claim and charge each logical proof's bytes in the proof ledger. Do not remove an original-pool obligation, predict aliasing, or substitute canonical assignment output bytes for the actual effect receipt. The original reader association stays available even if the physical bytes deduplicate.

The semantic composition reserves these adaptation identities before claim:

- `0`: canonical policy; `1`: public workload; `2`: approved public checker certificate; `3`: public clock certificate if enabled. A missing synthetic clock certificate leaves slot 3 unused and reserved; it does not shift any identity.
- `4+t`, `t=0..2`: candidate learning checker receipts in manifest transfer order.
- `7+3*s+k`: nine script checker receipts in the same script/control and case order as above.
- `16..51`: the thirty-six full opportunity proofs.
- `52..53`: at most two explicitly preaccepted public support objects. Their exact allowed purpose, maximum bytes and, when known preclaim, hashes are frozen in the composition descriptor. Default is no support. They are not automatically two spare objects for arbitrary callers.

The existing policy's `adaptationOrdinals` must match these positions; b2 rejects an otherwise b1-valid arbitrary arrangement for this composition. Mechanical-only policy uses 0 and optionally 3; it has no semantic authority or future upgrade. All unused identities remain unavailable to generic callers unless the accepted descriptor explicitly leaves them unassigned. No support references may point at private checker answers/certificates. b1's general upper bound of 38 judgment refs remains a helper ceiling, **not** a promise that b2 allocated 38. Supply its `judgmentSlots` only from the at-most-two actually retained, admitted support objects; disallow cycles through receipts/proofs or reuse of future reviewer judgments.

Full q allocation arithmetic is:

```text
mandatory kinds: 36+36+36+18+3+3+9+6+5+2+48 = 202
202*65,536 = 13,238,272
16,777,216 - 13,238,272 = 3,538,944 = 54*65,536
16 policy/receipt positions + 36 full proofs = 52 optional positions
52*65,536 = 3,407,872; remaining = 131,072 bytes and 2 positions
```

Every enabled optional slot has a declared bound `b[j] <= min(q, policy.bounds.maxProofBytes)`; receipts also obey `maxCheckerBytes`. Policy itself and public workload/certificates obey the same singleton bound. Smaller plans use their signed q/pool, not these numeric maxima. Mechanical-only plans reserve only their explicitly enabled objects and their metadata, with no semantic defaults.

Current `retainProtocolArtifact` protects only unfilled mandatory slots. Extend its private reservation calculation to protect **unfilled enabled optional slots as well**, including all future full proofs and checker receipts. Before any logical proof write, let `U` be existing logical charges, `x` the incoming bounded charge, `M` the other unfilled mandatory identities, and `J` the other unfilled reserved optional identities. Require `U+x+|M|*q+sum(b[j], j in J) <= pool.maxBytes`, and existing plus incoming plus `|M|+|J|` logical identities within `maxArtifacts`. Reserve independent of raw deduplication. A write to an unassigned optional slot must preserve this same future reserve. Same identity/same bytes is idempotent; changed bytes refuse. Public generic retention cannot occupy a composition-owned identity; receipt imports go through the typed retained-reference path below.

These figures prove slot/byte **allocation feasibility** at the named ceilings. They do not prove all source proofs, source pages, outputs, control proofs, owner metadata or reviewer reads fit. A q overflow remains unavailable under the unchanged plan. Separately retaining canonical learning/script/interference preimages is infeasible: even three distinct learning outputs already exceed the two remaining optional positions in a full profile, before learning inputs or eighteen script assignments. No mandatory slot can be relabeled to hide that gap.

## Authenticated extraction with available checker and reviewer bytes

Create a private per-invocation `SourceAdmissionContext.readArtifact` adapter, never accept it from a caller. It serves (a) actual retained refs using the existing bounded raw reader and (b) a finite typed registry of derived assignment commitments for **this method's authenticated selectors**. Registry entries are `{roleId, assignmentId, before, after, field, expectedHash}`; `field` is `input | output`. They contain no caller-provided bytes, paths, proof objects or callbacks.

Before populating an entry, recompute `deriveDevelopmentAssignment` and `extractDevelopmentAssignmentArtifacts` through actual recorder-owned readers. On each derived read, resolve the same pinned selector against currently fenced retained captures, invoke the existing extractor again, require the expected hash and the requested/accepted extraction length bound, then return a fresh copy. Do not use a previous call's byte Map. Reject an unknown commitment, changed selector, ambiguous differing recipe, absent output or hash mismatch. An identical commitment across source recipes is allowed only after each participating recipe independently derives the same bytes; source attribution still comes from its own proof. Checker's `output/feedback` reads in `verifyDevelopmentSourceCheck` and script `caseInput` remain real authenticated reads.

For an opportunity, retain the main output and mapped feedback input in the two mandatory slots. Related learning/interference/feedback assignment inputs and outputs remain source-derived; the full opportunity proof contains their exact source proofs and brackets. Candidate learning uses the same derived resolver for its input and output, with its receipt retained at `4+t`. Script task outputs, script feedback inputs and both executions' other canonical commitments also use the resolver, while actual operational receipts occupy `script-receipt` slots. No canonical preimage is added to the control proof. During aggregate DC2, construct its registry one opportunity/case at a time or lazily from the bounded selector index; do not keep all 126 assignments' extracted bytes resident.

The host-facing check methods return a detached wrapper:

```ts
interface PreparedSourceCheck {
  check: DevelopmentCheckInput; // unchanged evidence and sourceDigest, no receipt included
  outputBytes: Uint8Array;
  feedbackBytes: Uint8Array;
}
```

Both byte fields are the exact derived preimages of `check.output/feedback`; supply them only after final current-use validation. Hashing the existing `check.evidence` remains unchanged, avoiding a checker-record/hash cycle. At most evidence `p`, output `a`, feedback `a` plus their explicit detached copies are resident at this boundary (`p <= q`, `a <= min(q, operational bound)` for this composition). Actual byte checks precede copying into the returned wrapper. A caller may retain those bytes independently but cannot return them as proof authority. No reader/Store/key escapes. This is preparation, not checker execution; any physical checker path still requires separately accepted accounting before dispatch.

Independent reviewers already have byte access without a new selector. Freeze includes every retained full proof, capture manifest, page and original in immutable B's actual inventory. A reviewer uses `case`/observations to locate candidate proofs, or the control proof's `source.opportunities` for ablations; then `original` on those **retained** refs. For an assignment commitment:

1. Read its full proof and its `captures` manifest refs. Validate the exact plan/policy/role/assignment binding and source recipe. The embedded `source.assignment.input` reconstructs input canonical bytes directly.
2. For output, follow `result.origin.execution` and the required observation JournalRefs in `source.assignment.proof.versions`. Read bounded document pages from the named after-cut manifest; locate exact journal version IDs, authenticate ref/document hashes and revisions, and reconstruct the producer's `lastResult.status/observations` in original order. This is exactly b1's `assignmentOutput`, including observation-version equality and run binding; any nested operational content uses that capture's original mapping.
3. Canonicalize `{status, observations}` and compare to the derived output hash. A missing/mismatched version is unavailable, not permission to ask generic `original` for the derived hash. Opportunity task/feedback standalone originals are a direct convenience but must agree with the same recipe.

The control proof's script execution list names task and feedback assignment IDs, exact effect/observation JournalRefs and retained captures, so the same reconstruction is possible even without retained standalone script assignment proofs. Re-derive their assignment association from the public packet and captured ingress/result history using the existing projector. No claim is made that a language-model reviewer has done this merely because bytes are available. Inadequate session read/context budget leaves the semantic review unavailable. Private answers never enter the generic index.

Each existing `original` fragment reauthenticates and debits the **whole original length plus receipt length**, even on cache hits. For an artifact of length `L` requiring `f` actual 2,048-byte-bounded receipts, debit is `f*L + sum(receipt lengths)` and tool reads are `f`; sum over manifest/proof/page/original reads, without free reconstruction or dedup credits. Existing P2 maxToolReads/maxTotalReadBytes/payload/checkpoint bounds remain authoritative. A finite small composition test must actually assemble a learning and script preimage through this read route and verify hashes; a prose recipe alone is not joined acceptance. A future convenience extractor tool would require a separate protocol, reservation and final-rederivation adoption; this design does not introduce it.

## Host inputs, methods and durable identities

Add an optional host-only `sourceAdmission` to claim/reopen options and to the internal preclaim verification calculation; the exact host data is passed as a separate argument, not inserted retroactively into the signed plan. It contains the existing `policy/trust` plus this small descriptor:

```ts
interface SourceComposition {
  version: 1;
  layout: 'source-admission-fixed-54-v1';
  maxExtractedBytes: number; // positive, <= min(q, operational singleton)
  support: { ordinal: 52 | 53; purpose: string; maxBytes: number;
             expected: ArtifactRef | null }[];
}
// host-only: { policy, trust, composition, acceptedCompositionDigest }
```

Purpose is a bounded externally accepted identifier, not executable routing. Compute `sourceAdmissionDigest = identity({policy, acceptedPolicyDigest, checker identity/principal/group/keyDigest, acceptedQualificationDigest, acceptedClockQualificationDigest, composition, acceptedCompositionDigest})`. Copy the native checker key as b1 already does; store only its digest in durable metadata. `acceptedCompositionDigest` must equal `identity(composition)` under prior host authority; constructor guesses are forbidden. Descriptor has no policy/plan backreference: packet/workload → role config/plan → policy → host admission digest. The acquisition closure hashes code, not eventual policy bytes. No cycle is introduced.

Pin the admission digest, enabled slot reservations and exact composition in owner state. Retain policy in slot 0; composition is durable owner metadata, disclosed in each new raw observation wrapper by its digest, with its code-defined layout and bounds available through the retained policy/accepted closure. Do not add an unbudgeted second policy artifact. If reviewer access to exact optional support descriptor is required, put its bounded public description in the policy's qualification/public workload before their independent acceptance; do not silently append fields to the accepted b1 policy wire. Reopen requires exact admission digest, support layout, native key digest, policy bytes, review admission digest, plan/closure and store/custodian identities; present-versus-absent cannot change. Revalidate immutable slots, indexes and proof refs. Existing source handles must be reattached before any source use.

Keep raw receipt intake separate: `importSourceCheck({kind:'opportunity'|'learning'|'script', roleId, subjectId, artifact})` takes an existing bounded raw-custodian reference, reads and authenticates it against the pinned checker/plan/policy/registered subject, then retains exact bytes in the assigned proof slot. Generic `readArtifact` never gains access to the entire custodian. Every inspection/semantic admission thereafter requires all behavioral initial captures. Do not force claim-time policy retention through the all-initial-captures gate or weaken that gate for later work.

Unknown disclosure cannot become a boolean. Retry of a committed key checks current use and returns the same stored result; changed selectors/checker/proof refuse. No duplicate signing.

## Private derive, retain, commit and release

The repaired **public** `withCurrentUse` and reviewer callback path fence owner, original ledger, custodian and sources read-only. Calling `retainProtocolArtifact` or `observe` inside them is correctly rejected. Do not weaken that fence or temporarily flip a public Store guard to permit writes.

Factor only the necessary private kernels: capture decoding/index/resolution and proof retention without recursively entering public current-use. A private invocation token held in a closure records active phase and accepted owner revision/digest; it is neither returned nor accepted by any public method. This is a scope token, not an authorization supplied by callers. Private helper callbacks are recorder-created functions. Reader methods require that exact active scope and expire on exit; public methods still acquire their original read-only fences.

The private composition executes synchronously in this order:

1. Reject an active owner transaction, pending raw write, reentrant admission, async/thenable arguments or unauthorized phase **before** source work. Detach data without invoking getters/proxies. Claim/reopen and descriptor checks already established authority. Acquire all behavioral historical-version fences in stable registration order, deduplicating Store objects (candidate Store is also original ledger); fence any remaining original Store and custodian read-only. Require depth-zero entry for recorder writes. Verify every role's path, journal prefix/version union and current custodian/attempt disposition as today.
2. Under an additional **owner read-only fence**, derive through private scoped readers, validate b1/DC2 checks and time, encode all proposed proof/raw-wrapper bytes, check exact slot/index/metadata/observation bounds and expected owner state. Raw reads occur under this owner fence too. The extracted commitment resolver cannot call public methods recursively. Release only the owner read fence; keep all source/original/custodian fences held.
3. Commit an owner `admissionPending` descriptor in its own durable transaction **before the first raw write**. This bounded record contains admission key/selector digest and planned slot/hash/byte identities, not bytes. Use existing `writeRaw`: commit raw `pending`, write immutable bytes, commit inventory and clear raw pending; then commit the logical proof identity. Protect owner with `withDevelopmentReadOnly` while calling the external raw-store read/write methods, leaving it writable only inside the recorder's own small `mutate` calls. Thus a hostile raw callback cannot modify owner state; no callback runs during the write-enabled region. Recheck exact owner revision/expected progress before each step. Persist each transaction independently; an outer owner transaction would erase the pending marker on a later failure and is forbidden.
4. Once all proofs and raw observation wrapper are durably inventoried, derive signed observation data from the validated proof only, using existing private signer. In one owner mutation append the observation (if eligible), append the admission index and clear `admissionPending`. The wrapper is `{source, planDigest, id, observedAt, data, proof, sourceAdmissionDigest}`; no full proof inline. IDs remain `source:<kind>:<roleId>:<subjectId>`, times come from accepted source interval endpoints (or the exact control stopping-point rule below), outer configuration remains the candidate configuration. No assignment observation is invented. Completed ablations have no opportunity observation.
5. With owner read-only again, verify committed proof/raw/index correspondence, current authority and the still-held source conditions. Return a detached reference/result only after the source/custodian scopes successfully exit. No internal token/reader escapes. Preserve callback-versus-source error discrimination so a bounded metadata error is not mislabeled historical corruption.

A process crash at any retention step preserves committed raw bytes and pending state. Reopen encountering raw `pending` **or** `admissionPending` refuses, matching the existing interrupted-raw-write contract; it never clears a pending marker to resume signing. The in-process catch attempts the existing terminal failure record after source fences unwind. This design introduces no permissive recovery constructor: late-response maintenance remains available only where the existing recorder lifecycle authorizes it, and an interrupted attempt that cannot reopen remains explicitly unavailable. An orphan raw write is recorded by existing failure semantics, not silently refunded. If a nonfatal derivation returns unavailable before retention, do not mark a nonexistent proof as retained. If actual known failed/unavailable proof bytes exist, retain them and record the explicit disposition; they may legitimately have no observation. Errors after the pending descriptor are terminal for this attempt. Terminal withdrawal markers are persisted only after read fences unwind, retaining P3's conservative denied state if marker persistence itself fails.

Source lock acquisition and caller error paths must not swallow a pending failure. Same-handle mutators (`put/delete/appendEvent/putArtifact/withdraw/close`) remain barred during owner/source read phases. The only authority to write owner state is internal code between those phases. This is the existing trusted-host threat boundary; it is not protection against a host replacing implementation methods or directly manipulating raw SQLite internals.

This control-only aggregate rule does not redate cycles, learning, experiences or opportunities. If any required assignment bracket is only available after the stop, the control observation is unavailable; a later final cut cannot supply an earlier bracket. Uncertain outstanding requests prevent complete DC2 admission. Preserve each control's acquisition/behavior/validity distinctions and missing coverage in findings. Before publishing B, final-current-use checks still cover all prior retained source versions and exact final cuts, as existing `withFinalCuts` requires. A late physical response may be retained/settled through the existing narrow exception, but cannot rewrite B, complete a control after its finalizer, consume a checker slot or reopen semantic admission. Finalized failure/unavailable does not become valid control behavior.
