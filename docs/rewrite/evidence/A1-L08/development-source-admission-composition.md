## Observed publication boundary

P3-R1 repair deliberately makes public `withCurrentUse` and `withEvidenceRead` callbacks read-only across captured sources, original ledger, custodian and owner. Consequently, a signing implementation cannot insert owner proof/index/observation writes inside that public callback. Conversely, a post-read authority check by itself is insufficient if mutation or reentry can occur before publication. The finite design must establish a private synchronous recorder-owned derive/retain/commit/release sequence with exact source/custodian fences, owner transaction semantics, no caller mutation callback and failure handling after raw retention. No await or external checker execution may occur while fences are held. Raw-store and owner-store writes are not one atomic database transaction; pending/failure state must remain durable and truthful.

Preclaim/reopen must pin both policy identity and accepted trust identities, including checker key identity without retaining secret key bytes in public evidence. Absence cannot be upgraded after claim. Existing reviewer admission/reservations and protected final captures remain binding. Deterministic subject IDs, identical replay, changed-receipt refusal, terminal markers and authentic late request settlement must remain compatible with these boundaries.
