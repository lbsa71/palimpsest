# C1 contract gate — draft v1

Revision: `aeon1.c1.v1`. Status: **implemented and fixture-verified; consumer acceptance incomplete**. Source handoff is the commit introducing this document and its contracts. L01 owns changes until C1 acceptance; after acceptance every changed boundary requires affected consumer acknowledgements, adaptation tasks and an explicit revision increment. No legacy compatibility is implied.

Import from `packages/contracts/index.ts` using relative `.ts` imports. Package exports point at the same entrypoint. Runtime dependency: Node `node:crypto` only. Namespace dependency graph is common ← control ← execution, common ← development; the execution-to-control edge is type-only. No consumer package is imported.

## Executable interfaces

- `Run`, `transitionRun`, `Step`, `ToolCall`, `Observation`, `ShellCheckpoint`, `Cancellation`, `InboundInput`, `inputIdentity`, `Effect`, `transitionEffect`, `EffectReceiver`, `ShellPort`, `ShellBridge` and `DelegationTask` describe execution.
- `Experience`, `MemoryRecord`, `SelfState`, `Goal`, `Drive`, `Obligation`, `Disclosure` and revisioned store ports describe development. Scope containment and derivation validation preserve source attribution and prevent automatic audience widening.
- `Capability`, `PromptManifest`, `PhysicalRequest`, `CandidateManifest`, `EvaluationEvidence`, `MeasurementEnvelope`, `ReleaseProposal`, `RecoveryState` describe control and evidence. `validateCapturedPrompt` hashes exact provider payload bytes; `identity` hashes canonical JSON.
- `conformance/fixtures.ts` supplies deterministic synthetic records. Its independent-evaluator fixture is **not** a trusted evaluation receipt. Never ingest fixture evidence as product qualification.

## Required consumer semantics

L03 owns atomic revision checks, deduplication, durable reservation/dispatch/settlement and current authority. The pure effect reducer is not a lock. Every effect receiver rechecks the current authority immediately before dispatch; shell callbacks do not confer authority. An uncertain effect cannot redispatch. Reconciliation can inspect a previous generation's uncertain effect under the current receiver's authority, preserving its original identity. Confirmed nonapplication is terminal `failed`; any later retry creates a separately authorized intent. Cancellation makes a run terminal but cannot erase effects already sent. Resuming a checkpoint must not reexecute a cancelled run.

L02 supplies application-owned instruction artifacts and captures the **final serialized request** before dispatch. `ShellBridge.reserve` persists a physical attempt, `dispatched` durably fences it before network I/O, and `settle` records actual or unknown usage. Each retry/compaction/reviewer/child call has its own ID. Unknown tokens/cost are `null`, never invented zeroes. `persistCheckpoint` stores canonical JSON content with `artifact.sha256 = identity(content)` and returns a verified artifact; the shell and receiver keep `observationIds` consistent with the checkpoint content; `readCheckpoint` checks artifact integrity and scope. `capturePrompt` must persist and validate manifest/payload correlation. Implementations can safely overreserve for uncertain dispatch; they cannot assume no request occurred after a crash.

L04 enforces audience authentication at retrieval. `Disclosure` is an authorization **reference**, not a self-issued permit. Broader derived learning requires a separately authorized transformation and downstream privacy validation; `assertDerivationScope` only supports narrowing. Forgotten-memory policy must not delete independently owed obligations. L05 owns goal state; L07 owns intake/delivery and observes obligations through L05/L03 transactions.

L09 authenticates evidence provenance and trusted evaluators, freezes the required case set and protocol, verifies artifact bytes, and runs validation under prior accepted controls. `independent: true` alone proves nothing. `validateRelease` checks structure/binding; it is not sufficient admission. Candidate `controls` identifies proposed control artifacts; `priorAuthority.controlRevision` identifies the already accepted judging controls. Control upgrades are separately staged and cannot approve their own transaction. Recovery reads latest lived state and uncertain effects outside the candidate checkout; independent rescue must work without any model.
