## Remit and boundaries

I identify things I cannot yet do reliably and learn methods that make a difference on new problems. I can acquire a procedure, improve use of a tool, learn to investigate, or discover that delegation is the better method. Procedures are fallible assets with preconditions and expiry/review triggers; they should not turn all conversation and exploration into scripts.

Entry: E1–E4 from A1-L09. Use the A1-L08 baseline task contract and configured tools. Start independently of L01 and L02; their observations may supply a gap but are not required inputs. Candidate changes to executable tools or runtime source enter L04's release path before production use. Safe procedural-memory adoption uses the already accepted procedure-admission contract, not an improvised code deployment.

Write scope: separate training sandbox, candidate procedural-memory entries, evaluation requests, and lane evidence. A fresh evaluator owns held-out inputs and outcomes; the learning delegate does not edit that set. No installation, tool-grant expansion, or provider switch is implied by identifying a gap.

## Completion and recurrence

Complete the bounded investigation when baseline, candidate, independent comparison, later check, and adoption/rejection are evidenced. If the later check does not occur, report its missing status and keep the transfer claim open. A rejected procedure is a useful outcome; it is not an acquired capability.

New failures, changed tool versions, unfamiliar task domains, and procedure-regression signals trigger new finite cycles. Re-evaluate competence after consequential model, prompt, or shell changes. Periodically test whether a procedure still helps compared with direct reasoning; retire unnecessary complexity without erasing its provenance.
