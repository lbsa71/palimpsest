## Statistical method

For each family/product/task, average the three scores. A task is one independent sampling unit; repeats are never three independent tasks. Report variance across task means and average variance within each task. Acceptance uses task-wise candidate minus comparator means on exactly matched cases. Candidate means lie in [0,3]; paired differences lie in [-3,3]. Correlated performance within a task remains in that paired difference, so shared task difficulty does not inflate variance as though the systems ran unrelated tasks.

For independent bounded observations, the one-sided empirical Bernstein bound uses unbiased sample variance `s²`, count `n`, range width `R`, and error allocation `δ`:

```text
lower = max(range minimum,
            mean - sqrt(2*s²*log(2/δ)/n) - 7*R*log(2/δ)/(3*(n-1)))
```

This follows [Maurer and Pontil (2009), Theorem 4](https://www.cs.mcgill.ca/~colt2009/papers/012.pdf), applied to reflected/rescaled task observations for a lower bound. It requires independent task clusters and bounded scores. The implementation requires the host to affirm the corresponding sampling assumptions. It is conservative, especially at small `n`; it is not a bootstrap interval or an exact-coverage claim.

The family error budget is 0.01. Split it equally across the two comparator differences and candidate absolute quality bound so all three statements are simultaneous; the five-family union bound is at most 0.05. This avoids treating two separate baseline statements as one marginal interval. Every lower bound must strictly clear its margin or absolute floor. An uncleared bound is indeterminate, not proof of inferiority or parity. Any observed hard violation or observed cost over the frozen ceiling is criterion-unmet regardless of scores. Complete finite acceptance does not create an ongoing optional-stopping guarantee.

## Planning simulation and sensitivity

Candidate scores are not inputs to `calibrate`. For each comparator/family, resample whole comparator task means independently on the two sides of an equality-model difference. This gives a symmetric mean-zero planning distribution. It preserves three-repeat task clustering but **does not estimate the unknown candidate's joint distribution**. The host must justify this equality model and pilot representativeness before scoring.

Every explicit sensitivity scenario multiplies that difference by a factor at least one and includes a strictly positive, explicitly supplied symmetric mass at -3/+3 for pilot-unseen tail tasks. A scenario whose scaled support exceeds score bounds is unsupported and requires a new comparator-only model; it is not silently clipped. Five pilot tasks cannot establish the correct tail mass or candidate/comparator correlation. The host must defend the supplied scenarios; their positivity alone is no guarantee of conservatism for real candidate behavior.

Seeded simulations accumulate task observations for all `n=2..maxTasksPerFamily`, applying the same paired lower-bound method. Select the smallest `n` for each family for which **every comparator and sensitivity** reaches the 0.8 power target. Use a Hoeffding lower confidence bound for each simulated Bernoulli rejection rate, with a union allocation across every searched count, family, comparator and sensitivity. This controls Monte Carlo selection optimism conditional on the supplied planning model; it does not turn a small pilot into population truth. The Hoeffding inequality is given as Theorem 1 in the same primary paper. The report retains the selected (or final unsuccessful) power cells; full search is deterministic from frozen records/configuration/seed/source.

Selection targets power to exclude the noninferiority margin at equality. It does not promise that the candidate will clear an absolute floor, avoid hard failures, or satisfy a different data-generating model. Insufficient power at the finite maximum requires a new comparator-only calibration version, never candidate-outcome-driven expansion. Large counts can result from conservative bounded intervals. The module computes total executions and the host-supplied worst-case cost quote for all three products and three repeats; it reports grant infeasibility without lowering thresholds. Actual per-request/token/time enforcement belongs to the authenticated host, and system resource/grant digests must identify that enforcement.
