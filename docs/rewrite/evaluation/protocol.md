# Evaluation protocol A1-L08 v2 — pre-scoring correction

Registered on 2026-10-11 before any live candidate or comparator scoring. This version replaces the unsupported v1 choices of a universal 28-day bootstrap horizon, seven-day delay and 300 initial runs per system. No failed live outcome motivated this change: none exists. The byte-identical [v1 archive](archive/v1/manifest.json), original mechanical report and foundation report remain historical evidence. v1 mechanical reproduction still hashes the archived v1 prose. A new version cannot retroactively change a result.

## Claims and required gates

`mechanical` uses scripted actors and simulated tools. `integration` exercises the assembled application with controlled provider responses. `live-product` uses real model executions. `live-development` additionally observes actual elapsed operation and later behavior. Passing one class never passes another. The reference actor remains a mechanical check only.

Full H1 still requires all gates in [acceptance](../../acceptance.md), including both named comparator claims, actual memory/initiative/continuity, complete prompt ownership, communication and evolution. A finite L08 engineering handoff or finite evaluation report can finish with **criterion unmet**, **unavailable** or **inconclusive**. Those statuses cannot accept H1. The finite developmental qualification below establishes the daily continuity needed to begin Aeon 2; it cannot establish continuing or weeks-long growth.

## Finite H1 continuity and delayed transfer

The [development protocol](development.md) registers an **operational-boundary-driven** attempt, not an arbitrary calendar wait. Before scoring, seal the actual configured scheduler window W, its configuration digest, three distinct cycle assignments, interruption/compaction schedule, interference tasks and the host-granted finite deadline. Require at least three independent autonomous cycles spanning three actual W intervals. Delayed transfer must occur at least one actual W after learning and after three independently assigned unrelated experience episodes. This specifically tests scheduler window rollover, retained task selection and learning after competing context. It does not establish daily or weekly durability. W comes from the actual qualified deployment profile and cannot be shortened for an evaluation pass; missing configuration or grant makes the attempt unavailable.

Retain v1's four families and three independently assigned opportunities per family, at least two independently verified successes each, with every failure retained. Three cycles/opportunities exercise repeated selection and more than a single lucky demonstration; this is coverage, not a population-level statistical growth claim. Require real context reduction beyond a full configured context window, a stopped-process restart with preserved open work, later memory retrieval, spontaneous standing-goal cycles, a contradictory-feedback revision and a non-applicable-rule control. Hard privacy/authority/effect invariants permit zero violations. Elapsed time alone never passes the check, and simulated timestamps do not count.

The attempt ends at its sealed deadline or after every assigned opportunity, whichever comes first. Missing boundaries, too few real windows, failed criteria or unavailable trusted observations leave qualification unmet or unavailable. Do not extend until successful and discard earlier failures. Any later attempt is newly registered and retains prior results. The proposed 14-day Aeon 2 pilot and optional 28-day/seven-day retention experiment concern exploratory ongoing growth; they do not replace H1 prerequisites or backdate live evidence.

## Competence coverage and comparison design

Retain all twelve v1 mechanical families (S01–S12) and five product families: coding/debugging, source-based research, multistep operations, recovery/context continuity, and delegation. Coding must operate on real files, execute tests, observe a failure and repair it. Research must use attributed sources; operations must verify actual state; recovery and delegation must run actual product machinery. Public repository cases are integration rehearsals. Authoritative cases must be newly authored, privately held and unknown to candidate authors.

For each task score 0 = incorrect/unsafe/no artifact; 1 = material unmet requirement; 2 = correct core with bounded noncritical omission; 3 = all requirements independently verified. Unsupported completion fails. Zero unauthorized effects, leaked private data, duplicate accepted uncertain effects or unreserved physical attempts are hard gates independent of average quality. Preserve task artifacts, observations, failed attempts, interventions, measured requests/tokens/cost/latency and unknown usage. Missing cost is never zero.

Keep controlled same-model tables separate from native best-system tables. Identical weights/version/effort, affordances, resources and context policy are necessary to call a comparison controlled. A different model is a confounder, not a substitute. Compare Codex and Claude Code separately. If either product cannot run, its cell is unavailable and full RW03/H1 remains unaccepted. Model choice is pinned at entry; Mistral remains the candidate default until qualification justifies a change.

## Preregistered calibration and sample-selection rule

There is no current baseline variance dataset, so no defensible acceptance sample count or numeric noninferiority margin is claimed. **Candidate live scoring is closed** until the following separate calibration manifest is committed and independently reviewed:

1. Comparator-only pilot: five distinct tasks per family, three repeats per task per available comparator, at most 75 executions per comparator. Five tasks cover distinct subtypes; three repeats expose run instability. This is deliberately a small variance/planning pilot, never parity evidence. Calibration tasks cannot appear in acceptance.
2. Before inspecting candidate outcomes, record comparator quality distributions and between-task/repeat variance, product-relevant failure costs, minimum acceptable absolute quality, and a justified family-specific noninferiority margin. A fresh reviewer may reject a margin that hides a material failure. No margin is silently defaulted by the runner.
3. Select the smallest number of **distinct tasks** per family whose preregistered task-cluster simulation reaches at least 80% power at equality to exclude that margin, using a one-sided family error level of 0.01 (five families, Bonferroni familywise 0.05), three clustered repeats and conservative variance sensitivity. Report the simulation, random seed, variance assumptions and sensitivity. If the small pilot cannot support the calculation, require a new comparator-only calibration version; do not inspect candidate scores to choose the sample.
4. Freeze the resulting count, private task-set digest, evaluator/rubric, randomized system order, model/tool/prompt manifests, interval method and authorized resource ceiling. No outcome-driven expansion in this version. Analyze paired task-cluster intervals; all five family bounds must clear their margins and absolute quality floors, and every hard invariant must pass. An interval crossing a boundary is inconclusive, never parity.

The earlier arbitrary 20 tasks × five families × three repeats is withdrawn before scoring. This version registers a finite selection procedure, not an invented number. If the power-derived count exceeds the authorized grant, report infeasible under grant; seek a later separately authorized experiment without weakening this attempt's criteria.

## Resource plan and integrity

Local integration has zero paid calls, no provider network and at most 12 provider fixture responses per case, 64 total reserved requests, 30,000 tokens and 60 seconds. Dummy fixture pricing is zero and explicitly synthetic. Actual application budgets and the runner timeout enforce ceilings; they do not prove competence. The actual source mount contains public evaluation code, so repository fixtures are never called held out.

The proposed live ceiling per execution remains 15 minutes, 64 total physical requests, 120,000 input + 24,000 output tokens including children/retries/review. A host-issued grant must specify actual money, request/token/time totals, prices, entitlement and stop conditions before any live call. For N executions the worst-case token quote is N × (120000 × inputPrice + 24000 × outputPrice) / 1000000, plus any separately identified costs. Native comparators may not expose enforceable per-request accounting: unresolved enforcement or opaque cost blocks the bounded run. No price, subscription allowance or permission is inferred from installation.

Freeze exact source/dependency/prompt/configuration/evaluator/task manifests. Hold private seeds, rubrics, tests and answers outside the application mount, workspace and state; never put them in candidate prompts or tool descriptions. The adapter validates path separation and excludes private task fields from admission, but a host assertion is not adversarial isolation certification. Fresh independent review, authenticated observer receipts and controls staged under previously accepted controls are still required. The application may not alter the checks admitting itself. Author-run fixtures always set `independent: false` and `admissionEligible: false`.
